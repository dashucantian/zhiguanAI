# 协作机制三环设计 v1（2026-10-29）

出：W3 协调位 `fc2ce735`｜性质：机制文书（不立项、不改规约；只把已在跑的做法成文并补外环）

## 一、内环：问题→方案→任务的闭环（已实跑一圈）

六步，每步有判据：

| 步 | 谁 | 判据 |
|---|---|---|
| 发现 | 监督三查＋监管条文对照 | 每条结论带命令与复算值 |
| 落单 | 协调位 | 一行一任务：问题／方案／归位方／判据／时限 |
| 挂账 | 监管位 | MON 编号、到期条件 |
| 处置 | 协调位 | **能办的当轮办**，不等字 |
| 销号 | 发现方复核 | 凭据对上才销，自报不算 |
| 结论 | 法师 | 涉及放行／改判据的终裁 |

**高效运转的四条硬规矩**：①回件时限 **24h**（已入委任状止损条）；②数带尺名＋时刻，**过期即报**；③定性词必须标「非测量」，不与量化混列；④谁都不审自己经手的件。

## 二、中环：带动全项目分工协作

1. **拍子**：机械拍＋执行器每 2h 自动跑；人机拍三窗各司（协调处置／监督抽检／监管挂账）。
2. **每窗一页「在办结论」**：开工索引的「在办」节是模板——各窗各有一页，推动＝每轮看到自己在哪一格、欠什么。
3. **互相顶出**：任一环断了（逾期、漏挂、未回），相邻环报，不靠人记性。
4. **监督复监督**：判分交监督位复核；监督位报伤不点名＝半条伤（已立此规）。

## 三、外环：为个人复刻到社区、形成反馈闭环打基础

复刻三件随模板包走：**结构（四层）＋判据（闸门脚本）＋案例（预装判语与坑）**——一个人照着能长出自己的节点。

社区反馈闭环＝四个钩子：

| 钩子 | 形态 | 判据 |
|---|---|---|
| 入口 | 反馈单模板三格（做了什么／卡在哪／期望什么），挂模板包 README | 每单 ≤200 字 |
| 分级 | 直接采纳→案例库；需适配→待裁单挂账；驳回→回原因 | 三天内分级 |
| 回灌 | 社区坑→踩坑档案（标「社区」来源）；社区改进→判语 | 与内部件分库分区 |
| 统计 | 每月回灌 N 条、采纳 M 条，写进社区分发版 README | 数字带尺名 |

**边界**：含真人名／厂商件／学员资料的**永远不出**；反馈入口**不出网**（表单落盘，本窗代收）。
