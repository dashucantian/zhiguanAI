# 信箱协议 README（任务意识层 L1↔L4 唯一通道 · 2026-09-22 阶段 0 建立）

> 依据：《任务意识层统一衔接方案 v1》§四（法师 09-22 批准阶段 0+1）。本目录是本机各窗口与云端/常驻 agent 之间**唯一**的交接通道——L4 换实现（QwenPaw／豆包专属工作伙伴／未来任何 agent）**不改本协议、不加平行目录**。

## 目录结构

```
信箱\
  README.md            本协议（唯一真相，改动须走 D 编号裁定）
  维那SOP.md            维那人设文件（全项目唯一，L4 任何实现共用）
  卡任务映射表.csv       ZG编号 ↔ 飞书任务 guid 对照（本地留存，防双录漂移）
  inbox\               法师派单区：法师（或经飞书转投）写入，窗口读取认领
  outbox\              窗口回报区：窗口办理后写入，法师/维那读取汇总
  engine\              （可选）引擎侧产物：每日待审快照、超时告警草稿
```

## 消息格式（文件即消息，只追加不覆盖）

文件名＝`YYYYMMDD-ZGxxx.md`（inbox 与 outbox 用同名配对）。内容模板：

```markdown
# ZG-xxx <任务标题>
- 状态：派单 | 进行中 | 待验收 | 已验收 | 挂起(原因)
- 优先级：紧急 | 本周 | 随缘
- 卡点：一句话（元数据级，不贴正文）
- 期望：法师要看到什么算完成
- 链接：看板记录 URL ／ 交付物路径（本机路径写绝对）
- 时区时间：YYYY-MM-DD HH:mm (Asia/Shanghai)
- 署名：法师口述转投 | 窗口号-AI编号
```

## 三条铁律

1. **元数据级**：任何录音转写、学员个人信息、脑电原始数据、代码正文**不得写入本目录**——这里只许出现编号、标题、一句话卡点、状态、链接。
2. **一次事件一个发信方**：任务状态提醒只从飞书任务卡（L3）发；两个千问 cron 只管制度健康，不重复推任务消息（防打扰，方案 §二）。
3. **命名唯一**：同一条 ZG 重开用 `-r2` 后缀新文件，不改旧文件；全部文件仅追加。

## 消费约定

- 窗口开工：扫 `inbox\` 未认领文件 → 认领＝在文件末行追加 `> 认领：<Session> <时间>` → 办理 → 同写出box。
- 维那（L4，若启用）：只读本目录＋看板元数据，按《维那SOP.md》报事；无新项则静默。
- 制度侧清单仍以 L1《00_当前状态.md》"待法师裁定"节为准，与信箱互挂编号、不双录内容。
