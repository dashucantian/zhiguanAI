## 一、反例有效性确认（W3 全对）

1. **age>LOCK_STALE_S 可夺活锁**：属实——旧 `locked()` 的 `_try_stale_takeover`
   `(pid and not _pid_alive(pid)) or age > LOCK_STALE_S` 中，age 分支可移除仍
   活跃持有者的锁。**本窗脑锁（worker 首跑 numba 编译可持锁 >120s）与 npz
   认领件（同款 age 分支）均继承此缺口**——W3 指认的"不把缺口放大到新资源"
   成立，已一并修。
2. **finally 无 owner token 比对删新主锁**：属实——旧 finally 直接
   `os.remove(lp)`，接管后旧持有者的 finally 会删新持有者的锁，互斥失效。
3. **OpenProcess 失败折叠成"已死"**：属实——旧 `_pid_alive` 在 OpenProcess
   失败（拒绝访问 5／探测失败）时返回 False＝"已死"，与 ERROR_INVALID_PARAMETER
   (87)＝进程不存在 混同。

## 二、修订内容（registry_tx 单一实现＋认领件同款）

1. **`_pid_status(pid) -> "alive"/"dead"/"unknown"` 三态**（替换 `_pid_alive`）：
   Windows 走 `ctypes.WinDLL("kernel32", use_last_error=True)`，OpenProcess 失败
   按 GetLastError 判别——**87＝确证 dead；5/其它＝unknown**（不当事死）；
   GetExitCodeProcess 259＝alive。
2. **DEAD-only 接管**：`_try_stale_takeover` 仅当 `_pid_status=="dead"` 才移除
   锁件；**age 分支整体删除**（活持有者无论持有多久不可夺）。unknown 不接管
   ——锁泄漏由调用方 TimeoutError＋按坑 018 口径人工核持有者处置（W3 结论
   "无法判定存活时保留 unknown/超时拒绝，不自动当死"逐字采纳）。
3. **owner token 释放比对**：锁件内容增 `owner_token`（secrets.token_hex(8)）；
   finally 读回比对 token 相符才删（句柄先关再删，Windows WinError 32 实测
   修正）；不符＝锁已被接管，不删新主锁。
4. **npz 认领件同款**（congci_pipeline `_claim_acquire/_claim_release`）：
   DEAD-only 接管＋owner token 记账（`_CLAIM_TOKENS`）释放比对——循
   "同锁族复用面一并审修"。
