# 乙案探索方案：两个 APP 的数据/功能能多大程度嵌入实践驾驶舱

> 出稿：2026-09-30 ｜ 窗口：**W1 工程线**（`AI-005·DeepSeek(deepseek-flash)`，`W1-DEEPSEEKFLASH-20260930-A`）
> 缘起：法师令——"**我是想看看、试一试，按照乙方案，能够在多大程度上实现两个 App 的相关数据或功能嵌入到我们的实践驾驶舱。希望能给出一个比较可行的探索实践方案，可以做一个测试。**"
> 性质：**探索方案＋测试判据**（不含代码改动；不改厂商软件本体；不启动任何服务，除非法师点头）

## 〇、先把"能嵌什么"这句话拆开——嵌入有五层，别混着谈

| 层 | 嵌什么 | 依赖 | 现状 |
|---|---|---|---|
| **L1 数据嵌入** | 数值本身（原始波形／指标） | 我们的代码 | ✅ **已实现**（9600→波形；指标→旁证源卡） |
| **L2 网页嵌入** | 把厂商**网页界面**用 iframe 摆进驾驶舱 | 厂商有没有网页 ＋ 防不防嵌 | 🔬 **本轮可测** |
| **L3 交互嵌入** | 在 iframe 里能点、能切指标 | 浏览器是否拦交互 | 🔬 随 L2 一起测 |
| **L4 控制嵌入** | 驾驶舱发指令控制厂商程序（切指标／开始停止） | 厂商有没有**控制类**接口 | ⚠ 高风险，须先探 |
| **L5 启动嵌入** | 驾驶舱里"一键打开"那两个程序 | 我们拉进程 | ✅ 可做（甲案②，待裁） |

> **要点**：L1 不需要 iframe，**已经到手**；乙案真正要试的是 **L2/L3**，顺带探 **L4**。

## 一、L0 静态取证（**已完成，不用启动任何程序**）

### 1.1 1.2.0 录屏软件：**没有网页可嵌**

| 证据 | 内容 |
|---|---|
| 安装形态 | `C:\Program Files\Pulse\NeuraDock\`，**jpackage 打包的 Java/Compose 桌面程序**（74 个 jar） |
| 依赖清单 | `app\NeuraDock.cfg` 全文 86 行，classpath 里**只有 `ktor-client-*`／`ktor-network`，没有任何 `ktor-server`**，也没有 jetty／netty／undertow |
| 运行时实测 | 它上一次运行时，`netstat` 对它那个进程**只列出一个 `192.168.188.105:9600` 裸 TCP**，**没有任何 HTTP 端口** |

⇒ **它没有网页界面 ⇒ L2 对 1.2.0 无从谈起。**它的"功能嵌入"只能走 **L1 数据**（我们已经做了），或 **L5 启动**。

### 1.2 指标平台：**有网页，而且很可能不防嵌**

| 证据 | 内容 |
|---|---|
| 打包形态 | PyInstaller（`PyInstaller`／`pyi-`／`_MEIPASS` 命中） |
| **HTTP 服务层** | 命中 **`http.server`、`socketserver`**；**`flask`／`fastapi`／`uvicorn`／`starlette`／`werkzeug`／`jinja2`／`tornado`／`aiohttp` 全部零命中** |
| **界面呈现** | 命中 **`webbrowser`**（用系统浏览器开页面——与法师截图里那个浏览器标签完全对上）；`tkinter` 命中系 matplotlib 的 Tk 后端所致 |
| 算力栈 | `scipy`543／`matplotlib`317／`numpy`137／**`mne`7** ⇒ 平台内部真做信号处理 |
| **蓝牙** | **`bleak` 命中 42** ⇒ **平台自己就带蓝牙客户端能力**（见 §四 重大更正） |

⇒ **两条推论**（须以运行时为准，但方向清楚）：
1. **有网页**：平台用系统浏览器打开自己 `http.server` 提供的页面 ⇒ **L2 有对象可嵌**；
2. **很可能不防嵌**：Python **标准库 `http.server` 在默认情况下不发任何安全头**——即**不设 `X-Frame-Options`、不设 CSP**，浏览器不会拦 iframe。
   ⚠ 但这**只是"默认如此"**：他们完全可能在代码里手写了头。**代码是压缩的，静态搜不到，所以必须实测响应头**——这正是 L2 的第一条测试。

> **方法学自曝（重要）**：字符串扫描对**响应头字面量**是**不具决定性**的（PyInstaller 把 Python 代码 zlib 压缩，搜不到≠不存在）。
> 本次能用的是**未压缩的模块名清单**——所以结论方向是单向的：**"某模块零命中"可信（确实没打进包），"命中"须防短名巧合**（`sys`／`json`／`socket`／`eel`／`cgi` 这类短名一律标为弱证据）。

## 二、可测分层与判据（测试怎么跑、看到什么算过）

### 测试 A（L2 网页嵌入）— **决定性一问：响应头**

```powershell
# 平台起来后：先按进程名找它的监听端口（这就是甲案③的手法）
$pid = (Get-Process NeuraDock_Developer_Metrics).Id
netstat -ano | Select-String "LISTENING" | Select-String "\s$pid$"
# 再取响应头（只读 GET）
```

| 看到的 | 判定 | 乙案结论 |
|---|---|---|
| 无 `X-Frame-Options`、无 CSP `frame-ancestors` | **可嵌** | 乙案成立，可做 iframe 页 |
| `X-Frame-Options: SAMEORIGIN`／`DENY` | **不可嵌** | 乙案**死**（除非厂商放开——但罗工已说"不支持全平台嵌入"） |
| 有 CSP 但 `frame-ancestors` 允许 | 可嵌 | 同上成立 |
| 根本不是 HTML（比如只返回 JSON） | 无网页界面 | 乙案降级为 L1 数据嵌入 |

### 测试 B（L3 交互嵌入）— **能不能点**

iframe 跨源**不阻止**内部交互（除非厂商设了 `sandbox` 或 `X-Frame-Options`）。⇒ 做法：做一页最小测试页，把平台地址 iframe 进去，**人眼确认能否滚动、能否切指标页签**。

### 测试 C（L4 控制嵌入）— **有没有可编程的控制口**

只做**只读探测**：`OPTIONS` 看 `Allow` 头、试 `GET /api/v1/` 看有无索引、看 `/api/v1/status` 是否自报能力清单。
**不建议**在未获厂商确认前调用任何 `POST`——那是动他们程序的内部状态，属未公开接口，稳不稳没人担保。

### 测试 D（**最高优先，且与乙案无关但更要紧**）— 两个程序能否**同时**持有头环

见 §四。**这一条的结果会反过来决定整个整合方案的形态**，故列为第一优先。

## 四、⚠ 重大更正：我上一轮的一条结论**下重了**

上一轮存证 §8.2 我写了 **"两条路吊在同一个 exe 上"**（依据是"关掉 1.2.0 后平台 71 秒无样本"这一**相关性**）。
本轮静态取证发现 **平台自己打包了 `bleak`（命中 42）** ⇒ **平台本身具备直连蓝牙头环的能力**，与"它靠 1.2.0 转发"不相容。

⇒ 正确的表述应是（两种都还活着，谁都未被证实）：

| 假说 | 含义 | 怎么证 |
|---|---|---|
| **甲说·依赖转发** | 平台的数据来自 1.2.0（我上轮的判断） | 关掉 1.2.0、平台单独跑，看它还出不出数 |
| **乙说·各自直连** | 平台自己连头环；关 1.2.0 时平台断数**另有原因**（头环休眠／被抢／未佩戴） | 只开平台、不戴头环 vs 戴上头环，看样本是否恢复 |

**而且乙说若成立，会带出一个新风险**：两个程序**都要连同一个头环** ⇒ **不是"同一个 exe"，而是"两个程序抢一个头环"** ⇒ 可能**根本不能同时用**（原始流与指标二选一）。
**这个结果会直接改写整合方案**：若真互斥，则"两路同时接进驾驶舱"从根上不成立，只能**分时切换**或**等厂商把两者合并**。

> 因此 **测试 D 优先于测试 A/B/C**。相关性与因果要分开——这是判语 011「证据独立核校」的同类要求。

## 五、怎样算"探索到了边界"（交付判据）

跑完测试 A–D 后，给出一张**可嵌入度结论表**：

| 维度 | 结论（四选一） | 依据 |
|---|---|---|
| 1.2.0 原始流 | 不可嵌界面／可嵌数据／可嵌界面／可编程 | 实测 |
| 指标平台指标 | 同上 | 实测 |
| 指标平台界面 | 同上 | **测试 A 响应头** |
| 平台内交互 | 不可动／可动 | 测试 B |
| 程序化控制 | 无口／有口（列出口） | 测试 C |
| **两路可否同时** | **可同时／互斥** | **测试 D** |

**达到这张表填满 ⇒ 边界即探明**，再谈施工才不是拍脑袋。
