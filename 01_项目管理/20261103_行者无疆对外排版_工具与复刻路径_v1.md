## 〇、一句话结论（先给判断）

**排版不是"选哪个大模型"能解决的，是"定一个模板 + 批量转换"的活。**
AI 真正帮得上的是**内容适配**（改段长、拆表格、写导语），不是排版本体。
Token Plan／Harness 那套（联网搜索、图像生成、语音合成、知识库）**对排版无直接帮助**，但对"配图与核事实"有用。

## 二、公众号是另一种东西，不能拿 PDF 凑

公众号的硬限制（决定技术路线，不是审美问题）：

| 限制 | 后果 |
|---|---|
| **不支持外链**（除公众号文章/小程序） | 书稿里所有站外引用都得改成文字说明 |
| **不支持自定义 CSS 类** | 必须**逐元素内联样式**——纯 Markdown 贴进去会丢排版 |
| **图片必须传素材库** | 现有 HTML 用 base64 内联，**贴公众号会全丢**，得逐张上传 |
| **表格样式极弱** | 复杂表会挤成一团，通常要改成分栏/列表 |
| 代码块、脚注、目录锚点 | 基本不支持或很难看 |

**我实测了三篇的结构风险**（本机现查）：

| 篇 | 表格行 | 外链 | 脚注 | 标题数 | >200 字长段 |
|---|---|---|---|---|---|
| 正编第一章 | 8 | 0 | 0 | 3 | 1 |
| 正编第二章 | 10 | 0 | 0 | 9 | 0 |
| 别编01 | 16 | 0 | 0 | 9 | 1 |

⇒ **好消息**：外链与脚注都是 **0**，不用大改语义。
⇒ **要处理**：表格（8—16 行/篇）要转成"分栏或列表"；别编的表更长，转起来工作量在内容侧不在技术侧。

## 三、工具选型（按"简单可复刻"排序）

### 甲·首选：`doocs/md`（开源，可自部署，离线可用）

- 干什么：Markdown → **微信兼容 HTML**（内联样式、主题制），一键复制进公众号编辑器
- 为什么选它：①开源可审 ②**主题可固化**（9 篇必须一致，这点最关键）③可本地跑，不出网
- 代价：部署一次（Node/Docker），之后批量走同一主题
- 复刻难度：**中**（一次投入，长期省）

### 乙·最省事：`mdnice`（在线，零部署）

- 干什么：同上，浏览器里粘贴 Markdown → 选主题 → 复制
- 代价：零部署，但**每篇手工粘**，且数据过第三方
- 适合：**先试效果**（今天就能验第一篇）

### 丙·已有资产改造：把 `生成阅读版.py` 加一个"公众号模式"

- 干什么：复用现有转换器，输出改为**内联样式 + 素材清单**（图片列成待上传清单）
- 为什么值得：我们已有 TOC、图片处理、字体栈；加一个模板分支即可
- 代价：改脚本（约半天），但**归属清楚、可版本化**
- 风险：微信样式兼容要试错几轮

**我的建议顺序：乙（今天验效果）→ 定主题 → 甲或丙（固化批量）。**

## 四、AI 该用在哪（别用错地方）

| 环节 | 谁来干 | 为什么 |
|---|---|---|
| **排版本体**（CSS、间距、字体） | **工具＋模板** | LLM 每次生成的样式都不一样，9 篇必歪 |
| **内容适配**（长段拆短、表格改列表、加小标题、写导语） | **LLM 可以干**，且干得好 | 这是语言活；用现成的 DSH／Claude 桌面即可，不必新接模型 |
| **可读性审读**（哪里绕、哪里断层） | **Claude 桌面**（长文强项，已能直读仓库 `mnt/zhiguanAI`） | 它读 30 万字不费劲 |
| **术语与口径一致性** | **闸**（已有《01_发布审查清单》A1—A3）＋我 | 人机都可以核，闸更可靠 |
| **配图** | 图像生成 MCP（如千问 Harness 权益）**可选** | 概念图可以，但书稿现有 cover/part 图已够 |

**一句提醒**：**不要指望"接个大模型就能自动排版"**。模型输出的是文本，公众号要的是内联样式——中间那层转换必须由工具或模板做。

## 五、关于 Token Plan／Harness（照原文说，不夸大）

千问官方文档（`platform.qianwenai.com/docs/token-plan/best-practices/built-in-tools`，本轮现读）写明：

- Harness 权益覆盖**联网搜索、图像生成、语音合成、知识库**等自研工具，均为 MCP 商店的 One Key 服务，用平台 API Key 鉴权；
- 接入方式：`opencode mcp add EnhancedSearch --url … --header "Authorization=Bearer YOUR_API_KEY"`（OpenCode／Codex／Claude Code／Qwen Code 各有写法）；
- 订阅即享额度与折扣，不占 Credits。

**对我们的实际用处（诚实评估）**：

| 能力 | 对排版有用吗 | 对我们的真用处 |
|---|---|---|
| 联网搜索增强 | **无** | 核事实（书稿引用的外部信息是否仍准确）、查同类书怎么排 |
| 图像生成 | **有一点** | 概念配图；但现有 assets 已够，非必需 |
| 语音合成 | **无** | 若要做"听书版"，另说 |
| 知识库 | **间接** | 若把书稿＋审查清单做成知识库，可让 AI 按清单自查 |

⇒ **接它不是为了排版**；若要接，理由是"核事实＋按清单自查"，不是"出好看的版"。

## 六、可复刻的简单案例（三条，都很土但有效）

1. **一人一书一主题**：`mdnice` 选一个主题 → 三篇试排 → 定稿 → 之后每篇同主题（只需换内容）。**零成本，当天可验。**
2. **模板固化批量**：`doocs/md` 自部署 → 把主题 CSS 存成模板 → 9 篇批量转换 → 逐篇复制。**一次投入，长期一致。**
3. **PDF 与公众号双轨**：书稿继续走 `生成阅读版.py` 出 PDF（已有）；公众号走另一条转换线。**两条线共用同一 Markdown 源，不互改。**

| 步 | 做什么 | 花多久 | 要您字 |
|---|---|---|---|

**关键判断**：第 1、2 步**不需要接任何新模型**——用现成工具＋我们已有的书稿就够了。第 3 步是可选项，且与排版无关。
