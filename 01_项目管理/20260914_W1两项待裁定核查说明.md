## 二、IsoEngine off-by-one：说白它到底错在哪、改不改有什么后果

### 2.1 缺陷本体（已实测确认，非推测）

`closedloop_engine.py:107-108`：

```python
self._phase_carrier = float(ph_c[-1]) % TWO_PI     # ph_c[-1] 是第 n-1 个样本的相位
self._phase_mod     = float(ph_m[-1]) % TWO_PI
```

而 `ph_c = self._phase_carrier + TWO_PI * carrier * n / sr`，`n = arange(frames)` = `[0, 1, …, frames-1]`。

**故本块用了 `ph_c[0..frames-1]`，存下的却是 `ph_c[frames-1]`；下一块首样本又从 `ph_c[frames-1]` 开始 → 第 `frames-1` 个样本被播放两次。**

每块少推进一个样本的相位，累积效果＝**频率整体降低 `1/frames`**。

**前端 Worklet 是正确实现**（`vr_feedback.html:376-387`）：逐样本 `pc += stepC` 放在**取样之后**，末态 = `start + n*stepC`，正好是下一块首样本应有的相位，无重复。**故前后端算法确实不一致**，交接文档此点属实。

### 2.2 实测数据（本轮离线仿真 + 静音帧数探测，不采信转述数字）

#### 关键前提：本机真实帧数 = 1136，且**固定**

`sd.default.blocksize` 与创建流后 `stream.blocksize` 均为 `0`（`paFramesPerBufferUnspecified`，帧数由 PortAudio 决定）。故以 `volume=0.0` 全零输出启动真实音频流（**物理上不发声**）收集回调帧数：

```
2 秒内回调 77 次，帧数 min=1136 max=1136，唯一值=[1136]，无 underrun
```

**帧数固定是重要好消息**：降频是**恒定比例**，不会抖动。若帧数抖动，等效于给载波叠加极低频 FM 调制，那才是真麻烦。

#### 换算到本机的实际偏差

| 参数 | 标称 | 实际输出 | 偏差 |
|---|---|---|---|
| 载波 | 220 Hz | **219.8063 Hz** | −0.1937 Hz（−0.088%） |
| 节拍 | 10 Hz | **9.991197 Hz** | −0.0088 Hz（−0.088%） |

#### 降频量级随帧数变化（说明为何必须先测帧数）

| frames | 降频 | 220Hz→ | 10Hz 节拍→ |
|---|---|---|---|
| 32 | 3.125% | 213.09 Hz | 9.600 Hz |
| 256 | 0.391% | 219.09 Hz | 9.961 Hz |
| 512 | 0.195% | 219.64 Hz | 9.980 Hz |
| **1136（本机实测）** | **0.088%** | **219.806 Hz** | **9.9912 Hz** |

**本机落在最轻的一档**（帧数大 → 降频小）。若当初按交接文档「每块重复一个样本」的定性描述推测严重性，会高估约 3.5 倍（对比 frames=256 档）。

#### 是否有爆音／咔哒？——**没有**

| 判据 | 实测 | 含义 |
|---|---|---|
| 块边界一阶差分 / 块内 99.9 分位 | **0.978x ~ 0.998x**（frames 32~2048 全档） | ≈1 → 边界与块内**无差别**，无突跳 |
| `set_beat` 热更新切换点差分 / 稳态 | **0.000x**（切换点恰在过零处） | 相位累积机制生效，切频**无爆音** |

> ⚠️ **须防误读**：仿真中「与修复版偏差 RMS ≈ 140%」这个数字**不表示音质差**。它是两个**频率略有差异**的正弦波长时间播放后的相位失同步（219.81Hz vs 220.00Hz 拍频约 5 秒一轮），单独听任一个版本都正常。此数字只说明「两版不是同一个信号」，**不可当作失真指标**。

#### 缺陷的真实性质（一句话）

**不是噪声问题，是标称值问题**：声音听起来完全正常（无爆音、无失真、无抖动），但**实际频率比代码里写的、比实验方案里写的低 0.088%**。
