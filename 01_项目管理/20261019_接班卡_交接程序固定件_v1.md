# 接班卡 · 交接程序固定件 v1

出具：2026-10-19 23:17:41（本机 `Get-Date` 现取）｜地位：与《窗口交接一页单 v2》配套的**固定程序**。单管现状，卡管程序；卡不随每次换窗重写。

> 为什么要拆：一页单的行数上限会把硬规矩挤掉——坑 043 的原话是"一行上限把自己的硬规矩挤没了"。单越短越好，程序越稳越好，二者分开，各自才守得住。

## §一 改动纪律
1. 单每换一窗重填；卡不动。
2. 改卡＝版本号 +1 ＋§九变更记一行；不许口头改、不许在单里临时改判据。
3. 单与卡冲突时以卡为准，并回头改单。

## §二 接班首动作（顺序写死，不许跳）
1. 核根路径与 sha256（单⓪）→ 不一致＝红停。
2. 读单正本（仓库内那份，不是附件缓存、不是对话粘贴的）。
3. 读本卡。
4. 复述三点（§三.1）→ 四查（§三.2）→ 填单⑩ → 落回执 → 才开工。

## §三 复述与四查

**1. 三分钟复述（接班窗做，结论写进回执，回执落点见单⑩）**
- 我接的是……
- 现在第一件事是……
- 我不能碰的是……

**2. 四查（接班前四个只读检查，各留一行结论＝对上／不对上）**

- **查库**：`git -C <根> log -1 --oneline`／`git status --short`／`git rev-list --count @{u}..HEAD`，三样现取。
  - ⚠ 本窗实测（2026-10-19 23:18:38 本机 `Get-Date` 现取，DSH workspace-write，三次复现）：`log` 可跑；`status` 与 `rev-list @{u}` 报 `Program 'git.cmd' failed to run: Access is denied`。⇒ **记"未取＋原因"，不得据此判"无改动"**。这就是单②要写"git 到哪一步"而不是"能 git"的由来。
- **查盘**：单④点名的每个文件——在不在、mtime 与单记时刻是否一致、（必要时）hash。不一致写"不对上"，不擅自解释成"应该就是那个"。
- **查信**：`01_项目管理\信箱\` 按 mtime 扫最新三件。
  - `inbox\`＝法师派单区，命名 `YYYYMMDD-ZGxxx.md`，未认领＝末行无 `> 认领：<Session> <时间>`；
  - `outbox\`＝窗口回报区，与 inbox 同名配对；
  - `engine\`＝协作件，命名 `YYYYMMDD-<窗>-<会话号>-致<X>_<主题>_v1.md`；
  - 铁律（`信箱\README.md` 三条）：本目录只许编号·标题·一句话卡点·状态·链接，录音转写／学员个人信息／脑电原始数据／代码正文一律不入。
- **搜裁**：`01_项目管理\待裁单.md` 现读一遍，不用旧印象；证据面见 `待裁单_证据附页_20261013.md`。
  - `00_当前状态.md` 的"待法师裁定"节只是**互挂**，不是正源——坑 043 根因③：L1 是状态面，不是候裁面。

## §四 四个才算（交接验收，缺一即黄，缺两项及以上即红）
1. 单在盘上（路径＋sha256 对得上）
2. 复述对上
3. 四查输出对上
4. 回执落接班窗己档（落点见单⑩）

## §五 五条硬规矩（承 v1，编号不动）
1. 单在盘上才算交出，口头说了不算
2. 读数带时刻与尺名，不带就是印象
3. 没验的写"未验"，不写成"已验"
4. 代裁不越权，亲裁事项先落待裁单
5. 复述对不上，交出窗先改单再交

## §六 补则三条（v2 新增，与五条并列）
6. **程序不随单重发**：单每次重填，卡不动；要改判据就改卡、升版本，不许在单里临时改。
7. **读盘即出网**：本单内容进入对话（＝进入模型上下文）前，先读单②的许可；未许可只给脱敏摘要（路径＋编号＋灯号），不给判语正文与禁做面细节。
8. **交出窗不可达且无人代录**：不得由接班窗自认绿，最高黄。

## §七 兜底三档（载体不够时怎么落）

| 档 | 载体 | 怎么落 |
|---|---|---|
| 甲 | 能读能写仓库（同机 DSH） | 全流程照做，回执自己写 |
| 乙 | 能读不能写 | 单与回执由交出窗或法师**代录**至 `engine\`，复述与四查结论由代录人转贴；回执署名写"代录：X" |
| 丙 | 不能读盘（纯对话窗） | 单视为黄；只许脱敏摘要（去路径、去判语正文，留编号与灯号）；连编号都不许出＝红停 |

- **读不到单**（路径变／副本旧／sha 不符）：红停，不按记忆开工，向法师或交出窗取正本。
- **无 git**：④三项写"未取＋原因"，不得留空、不得写"应该没有改动"。

## §八 跨客户端对照（Qoder → DSH 六处不可迁移）

| 项 | Qoder 侧 | DSH 现状 | 替代件 |
|---|---|---|---|
| 会话号 | 可查可回，可写进单 | 窗口标识不可跨端引用 | 身份键改为 正本路径＋sha256＋时刻（单⓪①） |
| 信箱投递面·唤窗 | 有投递面与唤起手段 | 无调度、无投递面；"信箱"只是仓库目录 | 信箱＝目录＋mtime 扫描，人工或窗口自读；不承诺自动唤醒，只写"已落盘"不写"已投递" |
| 模型行 | 可填型号 | 不可验证 | 只写"自报，未第三方验"（单②） |
| 回执落己档 | 窗口有己档 | 新窗己档不存在 | 回执路径写死在单⑩，落 `engine\` |
| 放行 | 窗内批准 | 不迁移 | 新窗重新获批，②记已批范围 |
| 外设（真机／五感／MCP） | 视环境而定 | 未验 | 写"未验"，禁做面照旧 |
