## 不让一个“成功”覆盖所有产物

分别记录主数据保存、qc_done附属事件、快照、账本回填、从此脑处理五个组件。主npz已存不证明events写成，更不证明脑处理committed；每组件有attempt/job id、源指纹、状态发生时刻、完成时刻、原因和最近成功版本。证据缺失如实unknown，不用界面默认绿。来源文件指针限定授权可读域，不把完整私人路径/识别信息曝到面板。

scheduled表示已排定、无成功承诺；success必须已提交一致可校验产物；failure有明确异常/失败原因且不盖掉旧成功；skipped区分无适用任务、节奏未到、上轮在途、无效数据或用途未准，不能把return None全部记同一计数。duplicate为已commit同键的成功无新增，不与无效输入abstained混合。unknown表示证据不足/无法验证，不把“进程还活着”当success。术语可按已批准方案保持pending/committed/failed/abstained，但展示映射须组件和原因明确。

## 合成验收矩阵

| 场景 | 必须观察到 | 不允许的结论 |
|---|---|---|
| 首次后台排定但尚未写完 | scheduled，尚无成功检查点 | 把返回路径写为success |
| 旧成功后新写失败 | 新attempt failure＋原因，旧成功时刻/hash不动 | 最新失败覆盖旧成功或用排定时刻伪成功 |
| 间隔未到/无目录/上轮在途 | 独立reason，只有规定的未执行场景计skipped | 所有None都当失败/跳过 |
| 主数据成功、附属事件缺文件/写拒绝 | 主success，附属skipped或failure并列 | 已保存＝全部契约齐 |
| 入库数据已落、账本回填失败 | 数据产物指纹/位置＋回填failure＋对账恢复状态 | 泛化为整个数据保存失败或静默忽略 |
| 脑候选写成、record/trace或index失败 | pending/failed有恢复证据，持久已commit版本未冒进 | candidate存在就发brain_saved |
| 同源重复/改路径/新处理版本 | 重复同键无新增，合法新版本显式分支或拒绝理由 | already与弃权混淆、旧ID永远遮蔽新内容 |
| 锁忙/持有者不可探测 | 超时/unknown，原owner不被错误删除 | 无法探测＝死亡，超时＝可接管 |
| 缺许可/QC拒绝/已撤回 | 不入队并给受限可见reason，不曝个人原件 | 文件存在或无姓名＝用途已准 |
| voice开始/保存/排队/完成/失败/去重 | 说的状态对应确切组件/事件 | 打印/保存提示冒称学习已完成 |
| iframe旧trace/不同session/无文件 | 明确stale/mismatch/missing与版本 | 当前渲染＝当前任务最新成功 |
| 退出/断线/停止 | 资源释放与基线回退证据，任务取消/未取消区分 | stop按钮存在＝全部副作用已停止 |
