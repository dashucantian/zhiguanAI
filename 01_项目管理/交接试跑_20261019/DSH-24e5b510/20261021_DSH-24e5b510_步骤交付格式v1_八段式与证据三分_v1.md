# 步骤交付格式 v1（八段式＋证据三分）· T3

出具：2026-10-23 12:2x（本机 `Get-Date` 现取）｜窗：`DSH·24e5b510`
缘起：NeuraDock 那套方法里真正能立刻搬的只有两样——**每步八段交付**与**三类证据不许互相冒充**。我方已有"四查＋四个才算"（卡 v1.9 §三.2／§四），缺的正是这两样。本件把两侧并成一条可复现的交付线，**不改卡、不改模板**，只作操作层。
性质：格式件（非裁定）。挂靠：卡 v1.9 §三.2 旁；协调位认可后再议是否进卡。

## 一、十个字段（八段＋两栏）

1. **当前目标**：这一步要变成什么可核事实（一句话，动词开头）。
2. **窗口与目录**：工作目录绝对路径；影响的件路径。
3. **前置条件**：版本／环境／依赖／他窗是否在途（在途即停）。
4. **命令**：可原样复制的一条（多条则分步编号，不合并）。
5. **预期结果**：命令返回值＋应看到的行（写关键行，不写"应该正常"）。
6. **完成检查**：判据化——命中数／字节／hash／退码／行数（带尺名）。
7. **证据三分**（新增，核心）：
   - `doc`＝维护文档写的（卡、规约、设计稿，带 `file:line`）；
   - `report`＝人报的（法师口字、他窗自报、我自己上一轮的结论）；
   - `tool`＝工具实际核验的（命令输出、提交号、hash、退码）。
   三者必须分栏记，**`report` 不得升格为 `tool`**；`doc` 与 `tool` 冲突时，判"以执行式为准"（同判据 13 的口径）。
8. **失败后下一步**：按失败类型给分支（权限／管道／端口／许可／数据不足），每支一句处置，不写"重试"。
9. **需要贴回的结果**：给下一位的最小材料（命令原文＋输出关键行＋退码＋件路径），够别人复算即可，不贴长文。
10. **结论范围**：这份结果**能证明什么／不能证明什么**（一句"不证明……"必须写）。

## 二、停机条件（对齐"安装未通过不进入数据分析"）

- 前置未核 → 不出命令；
- 命令退码非 0 且原因未明 → 不进下一步；
- 完成检查里任一判据为"未取到"→ 记 `未验`，**不许写通过**；
- 三分证据里 `tool` 为空 → 该步结论最高只能写"report 级"，不得写"已核"。
