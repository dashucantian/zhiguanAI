### 2.3 本机算力实测：推翻前一日报告的技术假设

09-04 那份调研报告假设本地大模型需要"24GB 显存的 RTX 3090/4090"，并据此把 GPU 采购列为隐性成本。09-05 AI 助理实测本机配置，**该假设不成立**：

| 项目 | 实况 |
|------|------|
| 处理器 | AMD Ryzen AI MAX+ 395（Strix Halo，16 核 32 线程） |
| 机型 | ASUS ROG Flow Z13（GZ302EA） |
| 内存 | 约 64GB LPDDR5X 统一内存（CPU 与 GPU 共享同一内存池） |
| 显卡 | Radeon 8060S 核显（RDNA 3.5，40 CU），**无 NVIDIA 独显** |

由此得到一个比省钱更重要的发现：本机瓶颈是内存带宽（约 215–256 GB/s），而带宽受限机器上决定推理速度的是**每生成一个字真正参与计算的激活参数量**，而非总参数量。同平台实测：

| 模型 | 架构 | 量化 | 速度 |
|------|------|------|------|
| Qwen3.8-27B | Dense | Q4_K_M | 约 11.7 tok/s，开 MTP 推测解码后 21.2 tok/s |
| Qwen3.8-27B | Dense | UD-Q4_K_XL | 基线 11.8 tok/s，开 MTP 峰值 31.8 tok/s |
| Qwen3.8-27B | Dense | AMD 官方测试 | 最高 24.5 tok/s |
| Qwen3.6-35B-A3B | **MoE** | — | **基线 49.5 tok/s，开 MTP 后 69.4 tok/s** |

参数量更大的 MoE 反而快 2–6 倍。

### 2.4 架构判决：生成式模型不做实时渲染

VR 头显一帧预算 16.7ms（90Hz），脑电驱动的视觉变化延迟须控制在 20ms 内；视频生成是秒至分钟级、3D 生成是分钟级，两者相差 3–5 个数量级，无优化空间。据此确立**离线生成资产、在线参数化驱动**架构：离线用生成式 3D 模型产出禅修场景资产，在线由 Shader 把脑电频段功率映射为光照、粒子、水面波动、雾气浓度等参数。大模型故障时视觉反馈不受影响，系统可优雅降级。

### 2.5 A3／A4 实施：改走 WebXR 零安装路线

探查发现**本机未安装 Unity**（Unity Hub 与各编辑器路径均不存在）。若等 Unity 安装与学习，周期以周计，与"最快速度"直接冲突。故 A3 改走零安装 WebXR 路线：

- 新建 `vr_feedback.html` 单页（three.js r160，WebGLRenderer，`renderer.xr.enabled = true`）
- three.js 引擎**本地化**至 `vr_assets/`（three.module.js 1243KB、jsm/loaders/GLTFLoader.js 106KB、jsm/utils/BufferGeometryUtils.js 31KB），脱离 CDN，寺院断网亦可用
- `console_server.py` 新增 `/ws/vr` WebSocket 指标出口、`/vr` 页面路由、`/api/vr/status`、`/api/vr/models`、`/api/vr/model`、`/vr_assets/{path}` 静态路由
- 设计约定：VR 端只消费低频指标（频段能量／状态／体征），**不推原始波形**（体积大且渲染用不上）
- 监测与实验两条数据流均自动广播；`VRSession` 支持跨事件循环推送

首轮浏览器实测暴露两处着色器语法错误（ShaderMaterial 选项对象被重复闭合，多出一个 `}`），报 `Uncaught SyntaxError: missing ) after argument list`，canvas 数为 0。修复后实测通过：canvas 渲染成功，HUD 实时显示"状态 放松 Relaxed／Alpha 13.9 dB／Theta -11.5 dB／数据源 monitor"。

> **【订正 2026-09-08，法师授权】** 上述 HUD 数值出自**模拟数据源**（`MonitorSimulator`），不是真机脑电，原表述未标明数据源、易被误读为真机首验结果，特此订正：
>
> - 数值溯源（2026-09-07 B3 离线回放时查证）：`MonitorSimulator` 合成参数为 alpha 振幅 7 μV → 功率 24.50 μV² → **13.89 dB**，与 HUD 所示 Alpha 13.9 dB 差 0.01 dB；合成数据 theta 频段仅含 σ=1.5 白噪声 → **−11.20 dB**，与 HUD 所示 Theta −11.5 dB 吻合。故"状态 放松 Relaxed"亦为合成信号的产物，非真实禅修状态判定。
> - 该轮实测的**有效结论仅限渲染链路本身**：着色器语法修复后 canvas 渲染成功、HUD 数据联动、WebSocket 推送约 4 条/秒——这些与数据源是真机还是模拟无关，结论依然成立。
> - **真机首验是 09-06 01:07 那次**（见本文 §2.7：`local_20260906_011204.npz`，267.6 秒，丢包 0.17%，质检通过，入库 ZEN-20260906-P001-S12），两者不可混为一谈。
> - 真机数据的实际频段量级与模拟数据相差悬殊（B3 回放实测：Alpha mean 7.89 dB、Theta mean 13.01 dB，且 **theta > alpha**），故模拟数据的 HUD 读数不能作为映射参数的标定依据——此点直接催生了 §2.5 之后新增的 B3 离线回放工具（见看板 ZG-010）。

WebSocket 通道以脚本实测：模拟采集 6 秒内 VR 通道收到 20 条指标包（约 4 条/秒），字段完整。

### 2.6 四轮真机排障

法师在 Pico 4 Ultra 上实测，连续四轮才通：

**第一轮："Pico 上这个网址打不开啊，显示已离线。"**
诊断：09-05 21:35 启动的旧版服务进程（PID 42888）仍占用 8777 端口，且只监听 `127.0.0.1`；法师重启批处理时新服务绑定失败（控制台红字 ERROR 10048），Pico 连到的是无 VR 功能的旧进程。防火墙并非障碍——已存在放行 Python 3.12 的入站规则（含 Public 网络、全端口）。
处置：确认旧进程处于空闲、无进行中采集后终止；法师重试成功，新服务绑定 `0.0.0.0`，局域网访问 `/vr` 返回 200。

**第二轮："还是一样的，怎么回事？是通过 Wi-Fi 连接的吗？还是通过蓝牙？"**
答复：Pico 访问走 **Wi-Fi（同一局域网）**，蓝牙只用于 Muse 头环连电脑那一段。
诊断：扫描 192.168.188.x 全网段，存活设备仅路由器一台（192.168.188.1），**Pico 不在该网段**，其连接请求从未到达电脑。
处置：请法师在 Pico 内核对 Wi-Fi 名称（志节-205）与 IP 前缀。

**第三轮："已经打开了网页，看到了跟电脑上一样的场景，但是无法进入 VR。"**
诊断：WebXR 规范规定 `navigator.xr` 仅在**安全上下文**（HTTPS 或 localhost）暴露。Pico 走 `http://192.168.188.105:8777` 属纯 HTTP 局域网地址，浏览器直接隐藏 VR 能力。电脑上用 localhost 打开算安全上下文，故本机测不出来，一到头显就暴露。
处置：新增 `local_tls.py`（幂等生成自签证书至 `vr_assets/tls/`，有效期 825 天），`console_server.py` 改为**双端口**——8777 HTTP（电脑控制台照旧）＋ 8778 HTTPS（头显进 VR 必经），同一 app、`asyncio.gather` 并行 serve；`VRSession` 客户端与其所属事件循环绑定登记；页面 ws/wss 随 `location.protocol` 自适应。
验证：局域网 HTTPS 访问 `/vr` 返回 200，`/api/vr/status` 显示 clients=2（Pico 页面已自动重连）。**法师确认 Pico 4 Ultra 成功进入 immersive-vr 会话，第一重多模态闭环（视觉）端到端打通。**

**第四轮（AI 侧自查）：着色器语法与工具失效。**
两处 ShaderMaterial 选项对象重复闭合；修复过程中 Edit 工具多行与单行 `old_string` 匹配连续失败，最终用 Python 字节级检查（逐字符打印 hex）才看清真实字符序列，按行重写解决。

## 四、与项目主线的关系（战略层）

**对《止观AI三年总体战略方案》**：本次打通的是"多模态反馈训练系统"的第一重闭环（视觉），使战略中"VR 虚拟道场"从设想进入可运行状态。且走的是零成本路线——未采购任何新硬件、未购买显卡、未订阅任何服务。

**对既有统一架构（D17/D18/D19）**：严格遵守。所有新能力并入既有唯一入口 `console_server.py`，未建平行入口；脑电采集层（`BleDirectReceiver`／`MonitorSimulator`）完全未动，只在其上增加数据出口；运行环境延续 Python 3.12 约定；真机数据仍走既有质检闸门、隔离区与 Zen-EEG 入库机制。
