## 四、灵魂式探索的体现（法师核心要求）

复盘第三节是本文档的灵魂，回答"这个过程如何验证了它自己所主张的理论"：

| 机制 | 本次实证 |
|---|---|
| **假设轻持** | 判语 013：书是概念大厦，其第五篇**自我诊断了概念大厦的限度**（画像必有信息损失、分辨率≠效度），故只借结构不借真值；隐显稿 §2.4 明写**证伪条件** |
| **预测误差驱动** | **AI 原提案被法师修正 3 处**：①建构轴由 AI 提的"安定"（状态量）改为「入照运融出」（过程相）②佛法表述由"须勘定如法"改为"持自知"③贯通稿待决项由 AI 报的"5 项"经核实为实际 8 项 |
| **熏习回写** | 隐显稿 V0.1→V0.2 即第一次回写。稿内原话："这两处修正没有推翻假设，反而使假设更贴自身的结构。**本稿的版本史即慢环的第一圈**" |
| **多方印证** | M4 印证矩阵五相×五路；在线阈值↔离线复算双轨写 meta；增量效度自检 |
| **自知** | 判语 013 操作化：D₁~D₈、HPCS 可作人读复盘词汇表，不得预置为标注 schema。AI 09-09 曾提议"D₁~D₁₀ 直接当标注维度表"，**属越层，已撤回并记入判语 013 教训** |

**最深的一层同构**：项目自身的运作过程，就是灵魂假设的第一个实例——三份既有文档与法师指示是显性规则，项目现状（"出"字空心、H3 悬空、T 漂移无源）是隐性状态，贯通稿是二者相遇的生成，法师审定意见是预测误差，文档升版是熏习回写。贯通稿附记原文："**项目也在自己的日用环里。**"

**本次纳入的最大收益**：不是多了一个理论框架，而是项目第一次完整走了一遍"假设→验证→修订→沉淀"的闭环，并把这个闭环本身记录了下来。《递归的生命》第五篇自我诊断了概念大厦的限度；止观 AI 用判语 013 把这个限度变成了操作纪律。**一个理论最有价值的地方，是它说出自己在哪里失效。**

## 五、方法论提炼（可复用）

### 5.1 七环节

```
1. 理论识别与评估 → 定性来源、划定价值边界、设"不流两边"总闸、找理论的自我限度
2. 结构对齐       → 语义/结构/逻辑三层，每层落到具体载体
3. 架构重构       → grep 实测受影响文档、分层归位、制定清单、保留版本史
4. 任务立项       → 入板、阶段归位（核实资源需求）、回读核对编号、同步本地清单
5. 判语沉淀       → 可引用/可追溯/可加严；安全伦理类须先落界面与审查清单
6. 多轮裁定       → 合并审定、改述原话须本人认可、义理级只登记不引申、区分新裁定与回填
7. 复盘总结       → 事实底盘实测、踩坑同源归类、模式提炼、借鉴价值
```

### 5.2 三条硬约束

- **先方案后动手**：建新体系/批量文件前先给方案待确认
- **统一架构不造冗余**：并入既有模块，附加式改动不动既有字段
- **红线先立**：判语 009/012/013、ZG-052

### 5.3 灵魂式探索五条操作准则

1. 假设必须写出证伪条件（不可证伪不入体系）
2. 每次裁定都记为预测误差，原提案被修正处必须显式记录、不得静默覆盖
3. 版本史即慢环（版本头记录"依哪条裁定改了什么"）
4. 词汇层与真值层严格分离（预置为 schema 即越层）
5. 损失投影诚实（每个视图标注"它丢弃了什么"）

### 5.4 本次新提炼的四条启示（写入技能 case-study）

1. **找理论的自我限度陈述，优先于找它的结论**——一个理论最有价值的地方是它说出自己在哪里失效
2. **最深的对齐在伦理／主体性／权力结构层面**，不在技术层（自主性捕获→ZG-052）
3. **词汇归一应作为重构的第一批动作**——理论纳入最先暴露的问题往往不是"理解不了"，而是"同一件事各说各话"（反馈强度／刺激度／S_opt／认知负荷 → 生成强度）
4. **待决清单可能含早已裁定但漏回填的项**——请示前先 grep 核实，避免重复请示（五字诀定论即属此类）
