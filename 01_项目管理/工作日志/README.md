## 一、三层节奏（不硬性日更）

| 层级 | 频率 | 内容 | 说明 |
|------|------|------|------|
| ① 每日轻记 | 每天（可开可关） | 3–5 行：今天推进了什么、卡在哪 | 法师口述一句，AI 成稿，附在当周日志末尾或单独小文件 |
| ② 事件日志 | 有大事则记 | 会议、决策、合作、技术突破、重要来访 | 按四层结构完整记录，见下方模板 |
| ③ 周月综述 | 每周一例会前／每月末 | 串联本期事件、回看行动项、校准方向 | 对接既有周一例会与月度复盘机制 |

原则：**有大事必记，无事不硬写。** 空日子硬写只会伤掉记录习惯。

## 二、事件日志四层结构

1. **事实层**：何时、与谁、谈/做了什么（要素齐全）
2. **决策层**：当场达成的共识、拍板事项
3. **行动层**：行动项（事项／负责人／时限）＋待决事项
4. **战略层**：与《止观AI三年总体战略方案》及既有系统的关系

## 三、命名与编号

- 文件名：`止观AI工作日志-YYYYMMDD-主题.md`
- 编号：按时间顺序流水编号（001、002……），写在日志抬头
- 原始素材（录音文稿、聊天记录导出等）存 `工作日志\原始素材\`，日志正文注明来源

### 三bis、顶部摘要与索引同步（2026-09-14 法师裁定 F6）

1. **每篇新日志须在顶部加 ≤300 tokens 摘要**，格式：

```
> **摘要（≤300 tok）**：<一句话结论>｜关键裁定：<Dxx／判语NNN>｜关联：<KZ-0NN／坑NNN>｜产物：<文件路径>
```

2. **写完立即登记下方 §七 日志索引**（编号／日期／主题／文件名四列齐全），**不留到"以后补"**。

> 〔范围〕**只对 020 起的新日志生效**，001–019 存量**不回改**（避免大改动）。
> 〔缘由〕索引机制项目已有（§七，19 篇已逐篇登记），缺的是"摘要"与"随写随登记"两条纪律。日志积累到百篇而无摘要与索引，即成信息垃圾场（GPT 评审 §七 的意见，经核校后采纳其**纪律**部分、不新建 `session_index.md`——§七 已承担该职能）。
> 〔与 L1 的关系〕`00_当前状态.md`（L1 状态层）只引摘要、不引全文；历史细节留在本层日志。

## 四、存档与发布纪律

- **默认仅内部存档**；任何内容对外发布，须经法师逐篇审阅后方可公开（详见 `..\人格档案\99_隐私分级说明.md`）
- 涉及出家众、学员、未定合作条款的内容，发布前必须脱敏
- 重要引语须标注来源与日期
