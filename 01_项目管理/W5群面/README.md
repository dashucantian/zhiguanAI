法师 2026-11-10 21:5x 定窗别「W5｜群面」，定位＝外围外循环的通道窗；22:5x 确认机器人值守的就是这两个群；23:2x 授权协调位先发大群跑通、再开窗。

## 目录里有什么

| 文件 | 入不入库 | 是什么 |
|---|---|---|
| `群轮询台账.py` | **入库** | 增量拉两个群的新消息，追加进台账。只读不发 |
| `README.md` | **入库** | 本说明 |
| `群互动台账.jsonl` | **不入库**（`.gitignore` 已排） | 群内消息台账，一行一条 JSON |
| `轮询游标.json` | **不入库**（同上） | 每个群上次读到的时刻 |

**为什么数据不入库**：法师 2026-11-10 22:0x 字——群信息属**一二级保密内容**，只在**各自圈层内**流通，**跨群或跨圈层须过层级闸门**。git 推 GitHub 属圈层外，故台账与游标只留本机。

## 怎么跑

```bat
cd 01_项目管理\W5群面
python 群轮询台账.py --baseline   :: 首次建游标（不写台账）
python 群轮询台账.py              :: 增量拉一次
```

首次在新机器上跑，先 `--baseline`，否则会把历史消息一次性灌进台账。

## 台账字段

`ts` 抓取时刻／`chat` 群名／`chat_id`／`msg_time` 消息时刻／`message_id`／`sender`（open_id 或 app_id 前 12 位）／`sender_kind`／`msg_type`／`text`（正文前 500 字）／`level` 层级标（未判填 `1?`）／`replied` 是否已回。

## 两个已知坑（都踩过）

1. `lark-cli` 在 Windows 上是 **shell 脚本**，Python 子进程直接调会 `WinError 2`。本件用 `cmd /c <…>\lark-cli.cmd` 调；路径可用环境变量 `LARK_CLI` 覆盖。
2. `lark-cli event consume` **只支持 bot 身份**，且**同一应用全局只准一条长连接**——2026-11-10 22:4x 实测，那条连接当时被 DSH 的飞书集成占着（平台报 `online_instance_cnt=1`），所以本件先用**轮询**，长连接等 DSH 退位后再接。
