# 「给 8779 新线立闸」还是「旧闸不外推」：两个选项详细说

- 名词先对齐：**旧线**＝`vr_mandala.html`（8777 那套，曼荼罗场景，九道闸管它）；**新线**＝8779 场景控制台 `_scene_env.html`（方案A「莲池夜观」，10-31 起，带 bloom／暗角／颗粒＋三预设 A-静坐／A-观想／A-空境）。

## 一、两条路分别是什么

### 路线甲：给新线立闸

给 8779 也定一套**验收判据**，照旧闸的格式写进 `vr_gates/`，跑闸时新旧两线各跑各的。

要立的判据（从新线自己的交付记录里就能出，不是凭空造）：

| 判据 | 量什么 | 缘由 |
|---|---|---|
| 三预设资产齐 | `/api/presets` 返回 7 条，三条 A 系预设字段（scene／dist／breath／groundMode／fog／bloom）逐项可读回 | 10-30 已验过一次接口，把它固化成闸 |
| 颜色主调 | 地面环线统一金线 `#d4af5a`（延续曼荼罗取证的金叶主线） | 方案里的设计纪律，可截屏核 |
| 运动幅度 | 自旋 ≤0.06、公转 0、雾 ≤0.045 | 照 10-22「朦胧感」教训定的红线 |
| 颗粒上限 | grain ≤0.30 | 参数上限，防越调越脏 |
| 后处理不进 XR | XR 内 `bloom` 执行路径**不启用**（帧缓冲纪律） | 10-30 自证里写死的纪律 |

代价：写闸＋跑闸约 **半天到一天**；以后每次动新线，跑一遍。
好处：新线的改动从此**有账可查**——改坏了当场知道，不用靠「看着还行」。

### 路线乙：明说旧闸不外推

在 `vr_gates/README.md` 与总跑器里各加**一句声明**：「本目录九闸只验 `vr_mandala.html`（8777）及其衍生变体；**8779 控制台及方案A 系列不在覆盖内**，其质量由人工观察承担，直到另行立闸。」

代价：**半小时**。
好处：先把「没人看着」这件事**公开承认**，而不是假装九道闸护着一切。
坏处：新线继续裸奔——bloom 强度调爆炸了、预设改坏颜色，都要等您戴头显时才发现。

## 二、正题：这条新线现在是不是「裸奔」

是。具体裸在哪：

1. **效果件全在 `output/`**——而 `.gitignore:75` 把整棵 `output/` 忽略，闸也不在库外；
2. **参数没有回归锚**——旧线要点能核是因为每项有数字判据（黑底 ≥85%、金色 0.3~15%…）；新线的 bloom 0.50、暗角 0.25 这些**只有设置没有判据**，谁改了什么都无从对比；
3. **三预设是纯 JSON**，任何人手改一个数字，九道闸照常全绿。

## 三、我的建议：**分两步走，先乙后甲**

**第一步（现在就做·半小时）**：走路线乙——先把「九闸不覆盖 8779」**写成文档事实**，别让人误以为有闸保护。
理由：您还没决定给新线配多少验收强度，先别让账本替您撒谎。

**第二步（下一个 VR 轮次做·半天到一天）**：立新线最小闸（四条：资产齐／金线主调／运动与雾上限／后处理不进 XR），照旧闸格式入库。
理由：这四条几乎不花维护成本——脚本从页面 API 和 JSON 里读值即可，每次开机顺手跑，不用头显。

**什么叫「到时候再补」**：如果您想先看几个星期的效果再定标，那就在 README 里加一行「**新线立闸预计 11 月中启动**」，把心里的账写在面上——比「既没闸又没说」强。
