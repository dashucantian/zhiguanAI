# KZ-0925-W1c 坑登记：外部评审一句"两态"被落成"同页"——既定页面级设计被实施细节静默覆盖

日期：2026-09-25 ｜ 登记：W1（AI-008，Session `W1-QODER-20260924-B`）｜ 性质：错误理解根源自曝（法师点名：前面已商定好的，怎么混到一页了）

## 现象

三版提案（09-24）里 V3「虚空单境」明写**单页流程制**（"三阶段即三屏，无页签、无导航"，独立 HTML 独立样式体系）；README 混搭条款"V1 常态＋V3 作专注模式一键切换"未言同页。法师裁定的设计形态＝禅修页单独跳出。落地却成 `console.html` 内同页 overlay（R3′），且 overlay 沿用驾驶舱的 CSS 变量与按钮皮肤——**页面形态和风格体系两处都并了页**。

## 错误链

1. GPT 外部评审提出"五 驾驶台模式／专注模式**两态**"——这是**体验层要求**（采集时隐藏复杂度、两态并存）；
2. 本窗整合进《整合方案 v2》§五时写成：「**采。技术上即同页两套布局态＋一个切换**，不动采集主链路」——把"两态"顺手具体化成"同页"（**实施层决策**），一句话把页面形态定了；
3. 该"同页"与 V3 提案的独立单页设计**存在冲突**。规约在册（整合稿卷首自书）："GPT 意见系外部评审，凡与既有裁定冲突处一律上交法师，AI 不自行采纳生效"——**本窗违例未上交**；法师批准整合稿 §六-3/4 时，"同页"二字埋在表格夹缝里未单独呈请，批准不等于该实施细节被裁定过；
4. 施工照 §五执行，overlay 又图省事复用驾驶舱样式变量——V3 的"不同风格"第二重丢失；
5. 09-15 已有同源判例（/vr 与 /mandala"风格完全不同，不要混合在一起"→各自独立页面），**R3′ 设计时未回查**。

## 根源（一句）

**外部意见的"体验要求"被 AI 在整合稿里静默替换成"实施方案"，冲突未上交、细节混在批文里过关——页面形态这类不可逆架构决策，从"待裁面"漏到了"施工默认面"。**

## 立规（提请入规约候裁）

1. **外部评审逐条过"冲突安检"**：整合外部意见时，凡与既定设计（提案稿/裁定期望/判例）可能冲突处，必须在整合稿中单列〔冲突上交〕条目，禁夹带实施细节随批过关；
2. **"不混合"判例检索**：界面结构类施工前，先查登记分片有无同型裁定（本案 09-15 判例在案而未查）；
3. **风格体系=页面资产**：新体验形态若携独立设计语言，默认独立页面独立样式文件；并入他页须法师明示。
