# KZ-1007-W3e｜`收口检查.ps1` 第 4 门假阴性：GBK 解码吞换行，trailer 明明在却报缺

日期：2026-10-07。窗口：W3｜身份：AI-014（Qoder 桌面端）｜Session：`W3-QODER-20261007-F`。
编号先查后取：1007 号 KZ 已有 a/b/c/d ⇒ 本片取 `KZ-1007-W3e`。
性质：**验收闸门自身的缺陷**（循规约 §二.6 末句"该脚本自身输出亦须核验，教训 7.1"）。非本窗提交之过。

## 一、现象

跑 `收口检查.ps1` 对提交 `b8de51d`：

```
[OK] 最新提交含 trailer Session:
[OK] 最新提交含 trailer Window:
[告警] 最新提交缺 trailer Model: （§二.3 六件套）
结论：[收口未完] 1 项告警。      退出码 2
```

而 `git log -1 --format=%b b8de51d` 原文实测**明列**：

```
Author-Role: AI撰写/AI施工
Proposal-by: 宗国法师（…）
Approved-by: 宗国法师（10-07「开例外入库」＋择甲）
Model: Qoder-desktop          ← 确实在，且位于行首
Session: W3-QODER-20261007-F
Window: W3（制度与机动）
```

Python 直读原始字节判 `(?m)^Model: ` ⇒ **True**（UTF-8 与 GBK 两种解码都 True，因为 Python 不丢字节）。

## 二、根因（实测锁定，非推定）

在 PowerShell 里逐行定位含 `Model: ` 的那一行：

```
LINE#20  startsWithModel=False  len=122
```

**该行长 122 字符且不以 `Model: ` 开头** ⇒ trailer 与上一行**被并成一行**。机制：

1. `git log` 输出 UTF-8 字节；PowerShell 5.1 按 **控制台代码页（本机 GBK/936）** 解码子进程 stdout；
2. 全角字符的 UTF-8 编码共 3 字节，其**末字节常落在 GBK 前导字节区间**，于是解码器把它与**紧随的 `\n`（0x0A）**配成一对；
3. `0x0A` 不是合法 GBK  trail 字节 ⇒ 该换行被丢弃，两行合并；
4. 门 4 判据是 `(?m)^$k`（要求行首），合并后 `Model:` 不在行首 ⇒ **假阴性**。

**触发条件**：待查 trailer 的**前一行以中日韩字符收尾**。本次前一行以全角括号 `）` 结尾（EF BC 89，末字节 0x89 是 GBK 前导字节）。
**为何 Session／Window 照过**：它们的前一行分别以 ASCII `t`（`Qoder-desktop`）与 ASCII 结尾，不产生前导字节，换行未丢。

> **⚠ 上一段「触发条件」的归纳已被本轮实测证伪，原文照留、就此更正（10-07 17:5x，W3 自曝第二轮）**
>
> 1. **不是"前一行以中文收尾"这一条局部条件**。真正决定换行是否被吞的，是**整段输出到该处为止的字节配对对齐**（GBK 逐对消费，奇偶一错即连锁）。反证：本窗第二笔提交 `df6f6c9` 的 `Approved-by` 行**同样以全角 `）` 结尾**，结构与 `b8de51d` 一致，门 4 却三判全过。⇒ 结论只能收到"**随机咬**"这一层，具体哪一笔被咬不可预判——这恰恰比原判断更严重：连"中文结尾就要复核"这种规避法都不成立。
> 2. **取证方法有误，已在 PowerShell 内重做**。上一轮我用 Python `decode('gbk','replace')` 复现 .NET 的 936 解码，两笔都判"行首无 Model"，与 PS 实测**方向相反**——Python 遇非法 trail 字节只替换前导字节、把 `\n` 留下重新处理，.NET 则把这对字节一起吞掉。**换解码器≠换实现**，跨实现复现必须回到出问题的那一侧实测，否则会把结论订反。
> 3. **PS 内实测（`$tr = git log -1 --format='%b'` 逐行判，ASCII 探针，两笔各跑）**：
>
>    | 提交 | 含 `Model: ` 的那一行 | `StartsWith("Model: ")` | `(?m)^Model: ` | 门 4 结果 | 原始字节实际含行首 `Model: ` |
>    |---|---|---|---|---|---|
>    | `b8de51d` | 第 20 行，len=122（被并入前文） | False | 无匹配（MATCH_Simple=0） | **[告警] 缺 Model** | **True** |
>    | `df6f6c9` | 第 14 行，len=20（独立成行） | True | 命中（MATCH_Simple=1） | **[OK]** | True |
>
>    两笔原始字节都确有 `(?m)^Model: `（Python 直读判 True，这一项不受影响）。故 **`b8de51d` 的告警＝闸门假阴性**这一条主结论不变，只是**归因的表述**由"前一行中文收尾"更正为"字节配对的整段对齐、不可预判"。

## 三、影响面（不只本窗）
