## 十七、机械拍首日两处真 bug（10:35／11:35 两拍死掉）——已修，现全链跑通

**症状**：日志在 10:35、11:35 两拍**只有「拍开始」一行**，后面什么都没有；同时 `1020-10`（满线 10:13）与 `1020-11`（满线 11:20）到线未落。
**根因一（PATH）**：任务计划进程的 PATH 里**没有 git**。脚本用裸 `git` 调用 ⇒ 只有"已到线且未入库"的拍才会走到 git 那几行并当场抛错；09:31／09:35 两拍因为**零个到线件**、从未调用 git，才看起来正常。**修**：显式 `$Git='C:\Program Files\Git\bin\git.exe'`（9 处调用全换）。
**根因二（EAP）**：`$ErrorActionPreference='Stop'` 让 `git ls-files --error-unmatch` 的**正常「未跟踪」回报**被当成 `NativeCommandError` 终止整拍；换成 `ls-files -- <path>`（不写 stderr）后仍被 `git add` 的 LF/CRLF warning 触发。**修**：改 `Continue`，一切判断改由 `$LASTEXITCODE`／输出内容显式做。
**验证（11:44—11:45 现跑）**：一拍落 2 枚 —— `1020-10` → `f12c4cc`（过线 92 分）／`1020-11` → `7b51858`（过线 25 分），**已推、余数 0**，日志有「拍结束」。
**教训（同坑 066 一族）**：**定时任务里的脚本，不能假设它跑在你的会话环境里**（PATH／编码／EAP 三样都会变）；且"零活"与"跑通"在日志上长得一样——所以本件把「拍开始／拍结束」都写日志，缺口一眼可见。第一处 bug 是**它自己的日志形状**抓到的，不是我想到的。
