## 一、缺陷复述（施工前实测）

| 后果 | 证据 |
|---|---|
| **12/12** `device_info.json.collection_start_utc` 为**结束时刻** | S08 写 `2026-09-05T11:21:47Z`，而首样本真实时刻 `10:21:16Z` → **错标 60 分 31 秒** |
| **S05/S06 纪元轴整体后移一个会话时长** | `gap = meta.timestamp − ts[0]` ≈ 0，而 duration 为 316.4 s／705.0 s → 时间轴后移 **316.2 s／704.5 s** |
| **S02–S04 的 `ts[0]` 落在 1970-01-01** | 归档保留了相对秒（`ts[0]=0.0`），未加纪元锚点 |

**根因**：`muse_local_server.py` 的 `save_bin()` 用 `datetime.now()` 取 `timestamp` 与文件名 `local_YYYYMMDD_HHMMSS`，而这两处**发生在保存动作里** → 记录的是**存盘（结束）时刻**；字典 V1.2 §3.1 却把它定义为「采集**开始**的本地时刻」，`ingest_session.py` 又据此做纪元锚点与 `collection_start_utc`。

## 二、改法（B1–B4 逐条对应 Gate-B 要求）

| Gate-B 要求 | 实现 |
|---|---|
| **B1 明确区分 `started_at` / `ended_at`，不能一个字段承担两种语义** | `meta` 新增 `recording_started_at`＋`recording_started_at_epoch`／`recording_ended_at`＋`recording_ended_at_epoch`；`timestamp` **保留原值**但增 `timestamp_meaning: "ended_at"` 如实标注（不删不改既有字段） |
| **B2 `collection_start_utc` 必须对应第一条 EEG 样本** | `ingest_session.py` 改由 `start_epoch` 生成（`datetime.fromtimestamp(start_epoch, timezone.utc)`），不再用 `meta.timestamp` |
| **B3 时间源可说明** | 新增 `timestamp_source`（采集端：`measured`／`synthesized`）与 `collection_start_utc_source`（入库端三级：`meta_recording_started_at` 实测／`derived_from_first_sample` 反推／`fallback_meta_timestamp` 兜底；反推跨度过差时标 `(span_mismatch)`） |
| **B4 时间戳单调性必须被验证** | `ingest_session.py` 新增：`timestamps` 长度须等于 `meta.samples`、`np.diff <= 0` 即**非零退出**（字典 §3.1 明文要求严格单调，旧实现从不校验） |

**三级优先取「开始纪元」的取法（含对旧数据的处理）**：
```
① meta.recording_started_at_epoch 存在 → 用它（新采集，实测）
② 否则若 timestamps[0] > 1e9（真机实测时间戳）→ 用 timestamps[0] − duration 反推
③ 否则 → 回退 meta.timestamp（对 S02–S04 这类"相对时间戳"样本是**必需的**：
   其数组从 0 起，必须有一个把相对量抬到纪元的锚点）
```
> **说明**：③ 不是"没修"，而是对 V1.1 期相对时间戳样本的唯一合法锚点；其来源由
> `collection_start_utc_source: fallback_meta_timestamp` **如实例外标注**，不再冒充实测。

### 3.1 与旧实现的直接对照（**本包最有说服力的一行**）

> 同一会话，**旧实现**会把 `collection_start_utc` 写成 `meta.timestamp` 换算值
> **2026-09-20T21:28:35** —— 即**比真实开始时刻（21:27:55）晚 40 秒**。

**两组判然可分，且各自指向不同的根因**：

| 组 | 特征 | 会话 | 根因判读 |
|---|---|---|---|
| **甲组：比值≈1、gaps 极大、缺口小** | 比值 1.0012–1.0017，gaps 万级，缺口 <6 s | S05／S06／S07／S08／S10／S12／S13 | **真实设备级抖动**（BLE/TCP 到达间隔不均），总丢失很小 → **这才是"正常"的采集时间轴** |
| **乙组：比值显著>1、gaps 极少、缺口大** | S04 比值 **1.0248** 且 **gaps=0**；S09 1.0329；S11 1.0134 | S04／S09／S11 | **合成/线性回填时间轴**：`gaps=0` 说明间隔**完全均匀**（不是真实到达时刻），而比值>1 说明**回填用的采样率与 `meta.sfreq` 不一致** |

> **乙组的发现是本轮新证据**：
> - **S04 的缺口 92 s（比值 1.0248）** ——其 `timestamps` 是 `arange(n)/sfreq` 合成值
>   （`session_note` 自述 `linear_interpolation`，源 npz 无 `timestamps` 键），
>   比值 1.0248 提示回填所用速率与 256 不符（对应盘查 C-3 的同类口径问题）。
> - **S09／S11 是已登记的模拟合成数据**（`data_origin: simulator`），其 `gaps` 极少
>   （94／35）而比值 1.03／1.01，与"模拟器分批喂数"的机理一致。
>
> **结论**：`缺口` 与 `gaps` 两个量**合起来**才能区分"真实抖动"与"合成时间轴"——
> 这是 P1-1（时间戳真实化）应有的 `gap_stats` 字段的直接依据。

### 3.4 一处附带发现（修正后才可见）

| 量 | 值 |
|---|---|
| `samples`（= `len(ts)` = `eeg` 行数） | **9960** |
| 中位 `dt` | **3.906 ms** → 恰好 = 1/256（栅格本身正常） |
| **时间跨度 `ts[-1]−ts[0]`** | **40.0355 s** |
| **样本数 ÷ 采样率 = 9960/256** | **38.9062 s** |
| **缺口** | **1.129 s（跨度比样本数多 2.9%）** |
| **`dt > 1.5×` 期望值的间隔个数** | **73 个** |
| 最大单次间隔 | **40.4 ms**（≈ 期望 dt 的 10 倍） |
| `Σ dt` | 40.0355 s（= 跨度，自洽） |

**机理**：73 个缺陷间隔 × 约 15.5 ms 超出量 ≈ 1.13 s，与缺口吻合。挂钟节拍为
`time.sleep(0.25)`，模拟器每批喂 12 样本 → 每 0.25 s 有 0.25×(1−12/64)=0.203 s
的样本缺口，40 s 内约 160 批 × 0.0071 s ≈ 1.13 s。**即该缺口源于模拟器分批喂数
（墙钟节拍），而非头带丢包**——且 NeuraDock 路径因传入 `t_rel` 设备时间戳，可保持
250 Hz 均匀栅格（见 `add_eeg` 的 `t_rel` 分支）。

> **本项的意义不是"发现了一个新故障"，而是**：修正锚点前，**这 1.13 s 与 73 个缺陷
> 间隔完全不可见**——因为跨度被锚在结尾的写法吸收成"看起来合理的总时长"；现在它与
> `样本数÷采样率` 的恒等式**对不上**，于是显形。
> → **这正是"锚点正确"的直接红利：它让原本看不见的丢包/时钟问题变得可测。**

## 六、经验卡（依 EX-Gate，按 Gate 沉淀）

```
标题：一个字段不得承担两种时间语义
事件：采集端 meta.timestamp 与文件名 local_YYYYMMDD_HHMMSS 记录的是**存盘(结束)**
      时刻，而字典 V1.2 §3.1 把它定义为"采集开始时刻"，入库又据此做纪元锚点 →
      12/12 会话的 collection_start_utc 错标；S08 错 60 分 31 秒；S05/S06 的整条
      时间轴后移一个完整会话时长（316.2 s / 704.5 s）。
根因：**起录与结束共用一个字段**，且该字段的取值点（保存动作）与其声明的语义
      （采集开始）不一致——定义与实现相反。
为什么没发现：① 该字段"看起来完全正常"（有值、格式合法、单调）；② 没有任何测试
      校验"结束−开始 ≈ 样本数/采样率"这一恒等式；③ 错标方向恒定（总是偏晚），
      单看一条数据无法察觉，只有跨会话对照才暴露。
形成原则：**时间语义必须先于时间字段**；起录与结束各占一个字段，且字段的
      取值点必须与它声明的语义一致。
复用模板：新增任何时间字段，先回答三问——①它取值的**代码位置**是何时？
      ②它声明的**语义**是何时？③两者是否同一个时刻？任一不符即错。
关联·上游：Gate-B 证据包（本文件）｜v1 §三 A-7｜测试 verify_p0_9
关联·下游：AD-3 归档流程（device_info.collection_start_utc）／字典 V1.3／
      P1-1 时间戳真实化（t_rel ＋ gap 统计）
状态：已验证（待 Gate-B 裁定）
```

**第二张（同属 Gate-B，因 §3.2 而产生）**：
```
标题：锚点正确后，原本看不见的问题才会显形
事件：修正开始时刻锚点后，同一会话的"时间跨度 40.0355 s"与"样本数/采样率
      38.9062 s"相差 **1.129 s**、且逐样本间隔中有 **73 个**超过 1.5 倍期望值
      （最大 40.4 ms）才被看见——修正前该缺口被"锚在结尾"的写法吸收成
      "看起来合理的总时长"。
根因：错误的锚点不仅产生偏差，还会**吸收**其他异常——把丢包/间隙摊进总时长里，
      而总时长本身没有可校验的恒等式。
为什么没发现：旧口径下 duration 与样本数之间没有任何对账关系。
形成原则：**修正口径时，要预期"原来隐藏的问题会冒出来"**——这不是新故障，
      是旧故障第一次可见。
复用模板：任何"修正取值来源"的改动，改完要**重新扫一遍全量历史**看有没有
      新暴露的不一致，而不是只看新数据是否正常。
关联·上游：本包 §3.3／§3.4｜关联·下游：盘查 B-4（P1-1 时间戳真实化 ＋ gap_stats）
状态：**已验证**（12 归档会话全部重扫完成，见 §3.3；并据结果划出
      "真实抖动(甲组)"与"合成时间轴(乙组)"的分界判据）
```
