# 接班卡 · 交接程序固定件 v1.1

出具：2026-10-19 23:36:30（本机 `Get-Date` 现取）｜地位：与《窗口交接一页单 v2.1》配套的固定程序。单管现状，卡管程序。
本版据 2026-10-19 冷读试跑（见 `01_项目管理\交接试跑_20261019\20261019_试跑记录_冷读首轮_v1.md`）的十条实测缺口改定；v1 留存不改。

## §一 改动纪律
1. 单每换一窗重填；卡不动。
2. 改卡＝版本 +1 ＋§九变更记一行；不许口头改、不许在单里临时改判据。
3. 单与卡冲突以卡为准，并回头改单。**例外：回执落点以单⑩ 为准**（单是当次派令的一部分，卡给的是缺省值）。

## §二 接班首动作（顺序写死）
1. 核根路径与 sha256 锚（单⓪：同目录 `.sha256`；本单已入库则加 git blob）→ 不符＝红停。
2. 读单正本（仓库内那份，不是附件缓存、不是对话粘贴的）。
3. 读本卡。
4. 复述三点（§三.1）→ 四查（§三.2）→ 填单⑩ → 落回执 → 才开工。

## §三 复述与四查

**1. 三分钟复述（接班窗做，结论进回执，不铺进单⑩）**
- 我接的是……／现在第一件事是……／我不能碰的是……

**2. 四查（各留一行结论＝对上／不对上，附一句依据）**

- **查库**：`git -C <根> log -1 --format='%h %ci %s'`、`git status --short`、`git rev-list --count @{u}..HEAD`、`git diff --cached --stat`，四样现取。
  - ⚠ **输出捕获在本机不可靠**（实测 23:18—23:32）：`git status --short | Out-Null` 与 `> 文件` 报 `Program 'git.cmd' failed to run: Access is denied`；用 `@()` 赋值捕获返回空**且不报错**（假零风险，坑 047 同族）；**裸跑可拿全文**。⇒ 凡计数一律取直跑全文，不许信捕获值。
  - ⚠ **行数计数不许用 `Get-Content`**：本机按 GBK 解码，实测把 74 行算成 45 行。用 `[System.IO.File]::ReadAllText()` ＋正则数 `\n`。
- **查盘**：核对象＝单④"已落盘未入库"与⑥点名的件——在不在、mtime、行数/字节是否与单记一致。若单④未点名任何件＝本查记**不对上**，并在回执写不足（不许拿"没有对象"当通过）。另核一笔：目录件数与单⑨"出具后盘面变化"是否一致。
- **查信**：`01_项目管理\信箱\` 按 mtime 扫**最新三件**，基线就是这三件本身（不预设"应该有哪些"），判两样：命名合规、铁律合规。
  - 命名：`YYYYMMDD-<窗>-<会话号>-致<X>_<主题>_v1.md` 与 `复<X>` 同权并存（盘上回函一律用"复"）；
  - 铁律（`信箱\README.md`）：只许编号·标题·一句话卡点·状态·链接；录音转写／学员个人信息／脑电原始数据／代码正文不入；
  - **认领判据**：以 `outbox\` 是否有同名配对件为准——有配对＝已办，**不看**末行有无 `> 认领：`（实测反例：`inbox\20260928-ZG074.md` 无认领行却有配对回件）；
  - **现势**：`inbox\` 最新停在 2026-10-01 20:25:20，今日无新派单；派单与协作实际走 `engine\`。判"信"要看 engine，不是看 inbox 有没有东西。
- **搜裁**：`01_项目管理\待裁单.md` 现读（页头＋各节标题够用，不必全文）；报**两把尺**：页头"候字"条数与列项总数；`00_当前状态.md` 的"待法师裁定"节只互挂、不作正源（坑 043 根因③）。

## §四 四个才算 ＋ 两条硬尺
1. 单在盘上（`.sha256` 锚对得上，或第二锚 git blob 对得上）
2. 复述对上
3. 四查输出对上（查盘无核对象＝不对上）
4. 回执落点按单⑩ 执行；单⑩ 未填则落 `01_项目管理\信箱\engine\`，且**不得判绿**
5. **页尺**：成单 ≤70 行、⑩ ≤12 行；超尺记"填不下"，灯号黄，不阻断开工
6. **两版 hash**：原 `<正本>.sha256` 不动（锚发放版）；填⑩ 后另写 `<正本>.filled.sha256`；两值都进回执

## §五 五条硬规矩（承 v1/v2，编号不动）
1. 单在盘上才算交出，口头说了不算
2. 读数带时刻与尺名，不带就是印象
3. 没验的写"未验"，不写成"已验"
4. 代裁不越权，亲裁事项先落待裁单
5. 复述对不上，交出窗先改单再交

## §六 补则三条
6. **程序不随单重发**：单每次重填，卡不动；改判据就改卡、升版本。
7. **读盘即出网**：本单内容进入对话前先读单②的许可；未许可只给脱敏摘要（路径＋编号＋灯号）。
8. **补签**：交出窗还在跑时，签认走回执内一行（交班后补）；未补签＝灯号保持黄、不阻断开工；不得因"找不到人签"把单判绿。

## §七 兜底三档

| 档 | 载体 | 怎么落 |
|---|---|---|
| 甲 | 能读能写仓库 | 全流程照做，回执自己写 |
| 乙 | 能读不能写 | 单与回执由交出窗或法师**代录**至落点；复述与四查由代录人转贴；署名写"代录：X" |
| 丙 | 不能读盘（纯对话窗） | 单视为黄；只许脱敏摘要；连编号都不许出＝红停 |

- **读不到单**（路径变／副本旧／锚不符）：红停，不按记忆开工，取正本再动。
- **无 git**：三态写"未取＋原因"，不得留空、不得写"应该没有改动"。
- **单出具后盘面变化**：送出后由交出窗或接班窗在单⑨ 补一行（时点＋文件名）；条目不影响已记读数，但要在回执注明。

## §八 跨客户端对照（Qoder → DSH）

| 项 | Qoder 侧 | DSH 现势 | 替代件 |
|---|---|---|---|
| 会话号 | 可查可回 | 不可跨端引用 | 身份键＝正本路径＋锚＋时刻（单⓪①）；`DSH_SESSION_ID` 可现取，但只作记号不作凭证 |
| 信箱投递面·唤窗 | 有投递面与唤起 | 无调度、无投递面，"信箱"只是仓库目录 | 目录＋mtime 扫描；不承诺自动唤醒；只写"已落盘"不写"已投递" |
| 模型行 | 可填型号 | 不可验证 | 只写"自报，未第三方验" |
| 回执落己档 | 窗口有己档 | 新窗己档不存在 | 落点写死在单⑩ |
| 放行 | 窗内批准 | 不迁移 | 新窗重新获批，②记已批范围 |
| 命令输出捕获 | 可捕获、可计数 | 管道/重定向被拒，`@()` 赋值假零 | 一律裸跑看全文（§三.2） |
| 外设（真机／MCP） | 视环境 | 未验 | 写"未验"，禁做面照旧 |
