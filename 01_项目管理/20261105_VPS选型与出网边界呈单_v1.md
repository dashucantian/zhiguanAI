## 三、流量与出网成本

**事实**：模型 API 调用由 API 厂商计费，VPS 只承担出网带宽；官方确认 OpenClaw 通过 HTTPS 出网到模型提供商，明文 HTTP 端点被拒，且"utility tasks may send bounded task content to the selected model provider"。

**推断（非事实）**：脱敏后反馈文本体积小，4 小时一次、月约 180 次的文本请求，月出网估算 **< 1GB**，远低于最低套餐的 500GiB。⇒ **不构成流量包风险。**

**本地小模型**：OpenClaw 原生支持 Ollama（`baseUrl: "http://host:11434"`，官方注明**不要加 `/v1`，否则 tool calling 失效**）。Ollama 官方系统要求：**1B—3B 最低 4GB 内存（推荐 8GB）；7B—8B 最低 8GB（推荐 16GB）**。
⇒ **推论**：叠加 OpenClaw 自身开销，**2GB VPS 跑本地模型不可行；3B 级需 ≥4GB 且很紧；7B 级需 ≥8GB**，此时月价进入 $20—40 区间。
⇒ **对本项目的含义**：若坚持"本地模型处理"（法师裁断第 5 条），**那就不该上 VPS**——本机才是本地模型的正确位置；VPS 与"本地 AI"是互斥的两条路，不是一条路的两段。

## 四、不买 VPS 的四条替代路径

| 路径 | 成本 | 撑得住 4 小时间隔？ | 关键风险 |
|---|---|---|---|
| **Windows 本机 OpenClaw ＋ 任务计划** | $0 | 能 | **休眠（S3）下 Task Scheduler 服务被挂起、任务不触发**；须勾"唤醒计算机运行此任务"＋BIOS Wake on LAN＋电源计划允许唤醒定时器；关机错过可在恢复后补跑；合盖／离机即中断 |
| **GitHub Actions 定时** | 免费额度（private 仓库 **2000 分钟/月**，public 仓库免费） | 能（schedule 最短 5 分钟，高负载会延迟） | runner 无状态；workflow 必须在默认分支；4h×6 次/天＝180 次/月，按每次 ≤10 分钟估算约 1800 分钟，**是否够用属推断**；且反馈数据不能入库 |
| **Cloudflare Workers Cron** | 免费版每账号 5 个 Cron Trigger；付费 Workers $5/月起 | 能 | **单次 10ms CPU**，只够"触发 HTTP 请求"，跑不了 agent 主体 |
| **常开笔记本 docker compose** | $0 | 能 | 继承休眠／关机中断风险 |

**本项目的现实前提**：官方 Windows 文档明确**休眠／合盖／关机期间不触发**。⇒ "本机常开"必须落实为：禁止休眠 ＋ 开启唤醒定时器 ＋ 断电后开机自启，否则 24h 扫描存在缺口。

## 五、隐私与合规（三层，别只算第一层）

**第一层｜VPS 供应商本身**
- 自托管 VPS 是**我们控制的机器**，但供应商在法律与技术上仍是**受托方／潜在接触方**。
- Hetzner 隐私政策称"数据留在欧盟、不交给第三方"，**但滥用举报可保存至多 10 年**。
- DigitalOcean 隐私政策收集"使用数据／系统级指标"并与第三方厂商共享，**未公开子处理者与地点**。
- Vultr 曾因服务条款中"用户内容可自由支配"引发争议并撤回（CEO 声明不使用用户内容）——**条款与实际日志留存是两回事**。
- ⇒ 结论：按"**可能可见元数据／流量**"评估，不是按"绝对私密"评估。

**第二层｜模型提供商（这条更关键）**
即使在自有 VPS 上，**用 API 模型时反馈文本仍会离开本机到模型提供商**。这是独立于 VPS 供应商的一条出境链路，**VPS 买了也不能消掉它**。
⇒ 消掉这一层只有两个办法：本地模型（那就回本机，见 §三）、或只把**聚合级结果**送出去（法师裁断第 6 条若照定位裁决单 §五 候裁点③ 的严版执行，第二层本来就不过原文）。

**第三层｜本机闸门**
脱敏必须发生在**离开本机之前**。VPS 落盘内容、SSH／网关令牌、日志留存期限由我们自定，可自控。

## 六、三案呈裁（本窗建议甲案）

| | 甲案 | 乙案 | 丙案 |
|---|---|---|---|
| 做法 | **先跑通本机链路**（Windows 任务计划＋本机 OpenClaw，$0），VPS 备而不买 | 买最低配 VPS（Hetzner 2GB／€5.99 或 Vultr 2GB／$10）跑 24h，脱敏后聚合结果上云 | 先用 GitHub Actions 免费额度做 4h 定时触发（$0），数据全在 Actions 里跑 |
| 成本 | $0 | $6—10/月 | $0（受 2000 分钟/月配额约束） |
| 与"本地 AI 处理"（裁断⑤）是否相容 | ✅ 完全相容 | ⚠ 相容，但**原样件绝不能上 VPS** | ⚠ 相容，但反馈数据要进 GitHub 云环境 |
| 与"一级不出网"是否相容 | ✅ | ⚠ 仅脱敏后聚合级可上 | ⚠ 同左，且 runner 在境外更不可控 |
| 常开可靠性 | ⚠ 须禁休眠＋开唤醒＋断电自启 | ✅ | ✅（GitHub 自己跑） |
| 主要代价 | 须实测一次真触发（哨线历史常迟到） | 引入第三方物理机与一条出境链路 | 配额可能不够；反馈数据上云面更大 |
| **本窗建议** | **✅ 甲案**（先做，且不花钱） | 备选 | 不建议 |

**甲案为什么排第一**：法师裁断第 5 条是"用本地 AI 以及做脱敏"。**脱敏与推理都在本机，扫描也在本机最省事**；而本机链路历史上不按期触发（哨线连续 3/4 迟到），这是**可以先测、测不过再花钱**的问题——先花 $6 买 VPS 并不能自动解决"本机扫描不按期"这个更根本的问题（那其实是要改本机的定时配置）。

**乙案什么时候才该走**：① 本机链路实测不可靠且修不动；② 需要机器 24h 常开不占本机睡眠期；③ 需要多渠道接入。
**买之前必答**：定位裁决单 §五 候裁点③（VPS 能否接触原文——本窗建议：只能接触脱敏后的聚合级结果）。
