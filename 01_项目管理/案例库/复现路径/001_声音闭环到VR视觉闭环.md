# 复现路径 001：从声音闭环到 VR 视觉闭环

> **目标读者**：已有声音神经反馈闭环（Muse 头环 + Python 后端），希望扩展到 VR 视觉反馈的项目
> **前置条件**：
> - 已有稳定运行的声音闭环系统（脑电采集 + 实时分析 + 音频反馈）
> - 具备 Python 后端开发能力
> - 有 Pico 4 Ultra 或类似 VR 头显
> - 本机有 Unity 开发环境（或愿意安装）
>
> **预计耗时**：2-3 周（含调试）
> **难度**：中等（主要难点在 WebXR 安全上下文和蓝牙稳定性）

---

## 阶段一：架构决策（1-2 天）

### 1.1 确定视觉渲染方案

**决策点**：Unity 原生 vs WebXR

| 方案 | 优势 | 劣势 | 适用场景 |
|------|------|------|----------|
| Unity 原生 | 性能最优，生态成熟 | 需要安装 Unity，学习成本高 | 长期产品化 |
| WebXR | 零安装，跨平台，开发快 | 性能略低，浏览器兼容性限制 | 快速验证、原型开发 |

**本项目选择**：WebXR（理由：本机未装 Unity，优先快速验证）

**关键判据**：
- 如果已有 Unity 经验且计划长期迭代 → Unity
- 如果需要快速验证或团队有 Web 开发背景 → WebXR

### 1.2 确定数据传输架构

**决策点**：直连 vs WebSocket 桥接

| 方案 | 优势 | 劣势 |
|------|------|------|
| 直连（VR 直接连蓝牙） | 延迟最低 | Pico 蓝牙栈不稳定，易断连 |
| WebSocket 桥接（PC 中转） | 稳定，可复用现有后端 | 增加一跳延迟（<50ms，可接受） |

**本项目选择**：WebSocket 桥接（理由：蓝牙稳定性是已知痛点，见坑 003）

**架构**：
```
Muse 头环 → PC 蓝牙 → Python 后端 → WebSocket → VR 浏览器
```

## 阶段二：后端改造（3-5 天）

### 2.1 添加 WebSocket 服务

**目标**：在现有 HTTP API 基础上，增加 WebSocket 端点，实时推送脑电指标

**关键代码**（参考 `console_server.py`）：
```python
from fastapi import WebSocket

@app.websocket("/ws/vr")
async def vr_ws(websocket: WebSocket):
    await websocket.accept()
    try:
        while True:
            # 从现有数据流获取最新指标
            metrics = get_latest_metrics()
            await websocket.send_json(metrics)
            await asyncio.sleep(0.25)  # 4Hz 推送
    except WebSocketDisconnect:
        pass
```

**注意事项**：
- 推送频率 4Hz 足够（VR 视觉反馈不需要 256Hz 原始波形）
- 包含字段：timestamp, alpha, beta, theta, delta, attention, meditation
- 异常处理：客户端断开时优雅退出

### 2.2 添加 HTTPS 支持（关键！）

**为什么必须 HTTPS**：WebXR 规范要求安全上下文（Secure Context），只有 HTTPS 或 localhost 才能访问 `navigator.xr`。局域网 HTTP 地址（如 `http://192.168.x.x`）会被浏览器拒绝。

**解决方案**：自签名证书

**步骤**：
1. 生成证书（参考 `local_tls.py`）：
   ```python
   from cryptography import x509
   from cryptography.x509.oid import NameOID
   from cryptography.hazmat.primitives import hashes, serialization
   from cryptography.hazmat.primitives.asymmetric import rsa
   import datetime

   key = rsa.generate_private_key(public_exponent=65537, key_size=2048)
   subject = issuer = x509.Name([
       x509.NameAttribute(NameOID.COMMON_NAME, u"localhost"),
   ])
   cert = x509.CertificateBuilder().subject_name(
       subject
   ).issuer_name(
       issuer
   ).public_key(
       key.public_key()
   ).serial_number(
       x509.random_serial_number()
   ).not_valid_before(
       datetime.datetime.utcnow()
   ).not_valid_after(
       datetime.datetime.utcnow() + datetime.timedelta(days=365)
   ).sign(key, hashes.SHA256())

   with open("cert.pem", "wb") as f:
       f.write(cert.public_bytes(serialization.Encoding.PEM))
   with open("key.pem", "wb") as f:
       f.write(key.private_bytes(
           serialization.Encoding.PEM,
           serialization.PrivateFormat.TraditionalOpenSSL,
           serialization.NoEncryption()
       ))
   ```

2. 配置 FastAPI 使用 HTTPS：
   ```python
   import uvicorn
   uvicorn.run(
       app,
       host="0.0.0.0",
       port=8778,
       ssl_keyfile="key.pem",
       ssl_certfile="cert.pem"
   )
   ```

3. Pico 浏览器首次访问时，手动信任证书（点击"高级" → "继续访问"）

**踩坑预警**：
- 证书有效期建议 1 年，过期需重新生成
- 不要用 `localhost` 作为 IP 地址，用实际局域网 IP（如 `192.168.1.105`）
- 如果报"证书不受信任"，这是正常的，手动信任即可

## 阶段三：VR 前端开发（5-7 天）

### 3.1 搭建 WebXR 基础框架

**技术栈**：
- Three.js（3D 渲染）
- WebXR API（VR 模式）
- WebSocket（数据接收）

**最小可运行示例**（参考 `vr_feedback.html`）：
```html
<!DOCTYPE html>
<html>
<head>
    <meta charset="utf-8">
    <title>VR 神经反馈</title>
    <script src="https://cdn.jsdelivr.net/npm/three@0.160.0/build/three.min.js"></script>
</head>
<body>
    <script>
        // 初始化 Three.js
        const scene = new THREE.Scene();
        const camera = new THREE.PerspectiveCamera(75, window.innerWidth / window.innerHeight, 0.1, 1000);
        const renderer = new THREE.WebGLRenderer({ antialias: true });
        renderer.setSize(window.innerWidth, window.innerHeight);
        renderer.xr.enabled = true;
        document.body.appendChild(renderer.domElement);

        // 添加场景内容
        const geometry = new THREE.BoxGeometry();
        const material = new THREE.MeshStandardMaterial({ color: 0x00ff00 });
        const cube = new THREE.Mesh(geometry, material);
        scene.add(cube);

        const light = new THREE.PointLight(0xffffff, 1, 100);
        light.position.set(10, 10, 10);
        scene.add(light);

        // WebSocket 连接
        const ws = new WebSocket('wss://192.168.1.105:8778/ws/vr');
        ws.onmessage = (event) => {
            const data = JSON.parse(event.data);
            // 根据脑电数据更新场景
            cube.scale.setScalar(1 + data.attention * 0.5);
        };

        // 渲染循环
        renderer.setAnimationLoop(() => {
            cube.rotation.x += 0.01;
            cube.rotation.y += 0.01;
            renderer.render(scene, camera);
        });

        // 进入 VR 模式
        navigator.xr.requestSession('immersive-vr').then((session) => {
            renderer.xr.setSession(session);
        });
    </script>
</body>
</html>
```

### 3.2 设计视觉反馈映射

**关键决策**：哪些脑电指标映射到什么视觉元素？

**参考方案**（本项目实际采用）：
| 脑电指标 | 视觉元素 | 映射逻辑 |
|----------|----------|----------|
| attention | 心息之珠亮度 | `brightness = 0.3 + attention * 0.7` |
| meditation | 水面涟漪扩散速度 | `speed = meditation * 2` |
| alpha | 雾气浓度 | `fogDensity = 0.1 - alpha * 0.05` |
| theta | 粒子系统密度 | `particleCount = theta * 100` |

**设计原则**：
1. **正反馈优先**：专注度提升 → 视觉变亮/变清晰（鼓励用户保持专注）
2. **避免过度刺激**：变化要平滑，不要突变（用插值或缓动函数）
3. **多通道并行**：同时映射多个指标，但每个通道独立，避免相互干扰

### 3.3 优化性能

**目标**：90Hz 稳定帧率（Pico 4 Ultra 要求）

**优化手段**：
1. **降低推送频率**：后端 4Hz 推送，前端用插值平滑到 90Hz
2. **减少 Draw Call**：合并几何体，使用 InstancedMesh
3. **LOD（Level of Detail）**：远处物体用低模
4. **纹理压缩**：使用 KTX2 格式

**监控工具**：
- Pico 浏览器内置性能面板（FPS、内存、GPU 占用）
- Chrome DevTools Remote Debugging（通过 USB 连接）

## 阶段四：联调与测试（3-5 天）

### 4.1 局域网连通性测试

**检查清单**：
- [ ] PC 和 Pico 在同一 Wi-Fi（同一网段，如 192.168.1.x）
- [ ] PC 防火墙放行 8778 端口（HTTPS）
- [ ] Pico 浏览器能访问 `https://192.168.1.105:8778/vr`
- [ ] 手动信任自签名证书

**常见问题**：
1. **Pico 显示"已离线"**：检查端口是否被旧进程占用（见坑 002）
2. **无法进入 VR 模式**：检查是否用 HTTPS（见坑 001）
3. **WebSocket 连接失败**：检查 wss:// 协议（不是 ws://）

### 4.2 蓝牙稳定性测试

**测试方法**：
1. 启动闭环实验，连续运行 30 分钟
2. 监控数据流是否有静默断连（>18 秒无数据）
3. 记录断连次数和恢复时间

**预期结果**：
- 理想：0 次断连
- 可接受：1-2 次断连，每次恢复时间 <5 秒
- 不可接受：频繁断连（>5 次/30 分钟）

**如果频繁断连**：
1. 检查头环电量（<20% 时信号弱）
2. 检查 PC 蓝牙驱动版本（更新到最新）
3. 考虑改用 BLED112 专用蓝牙适配器（本项目采用）

### 4.3 用户体验测试

**测试维度**：
1. **视觉舒适度**：是否有眩晕感？（如果有，降低运动速度或减少粒子）
2. **反馈直观性**：用户能否理解视觉变化与自身状态的关联？
3. **沉浸感**：是否能帮助用户进入放松/专注状态？

**测试方法**：
- 让 3-5 名志愿者各体验 15 分钟
- 收集主观评分（1-10 分）和定性反馈
- 根据反馈调整视觉参数
