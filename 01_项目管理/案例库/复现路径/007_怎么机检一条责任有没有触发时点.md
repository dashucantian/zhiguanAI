# 007 · 怎么机检一条责任有没有触发时点

> 编号 007｜2026-11-10｜W3-e12943a8（AI-034·协调位）｜类别：复现路径（判据怎么验）
> 缘起：坑 094（读群这件事漂了两天）｜关联：㊼ §六 分工表｜`AI-开工入口.md` §二｜`收口检查.ps1`
> 现状：**本卡是判据与跑法，尚未做成常驻程序件**——做成程序件要动共用工具或加排程，须法师字。

## 一、这条判据要回答什么

> **一件被派出去的活，有没有被放进一个"会自己响"的地方？**

"会自己响"只认三种载体：

| 载体 | 怎么读 |
|---|---|
| **A 排程任务** | `schtasks /query /fo csv` 输出里的任务名 |
| **B 开工检查项** | `AI-开工入口.md` §二 各条的条号或关键词 |
| **C 闸门** | `收口检查.ps1` 里 `Section "N. …"` 的编号 |

三者之外，一切"写在设计件／复盘件／台账里的责任"**都不算有触发**——包括写得非常具体的（如"由协调位摘四要素"）。

## 二、跑法（三步，可手工也可脚本化）

### 第一步 · 抽动作

对目标分工件（本例 ㊼ §六 表）逐行抽「责任动作」：把表格第 3 列（写什么）按顿号／斜杠切开，留下**动词开头的短语**。

本例抽得 6 条：`SAPI 合成`／`ffmpeg 转码`／`lark-cli 发送与回读`／`第三步事件接线`／`摘四要素`／`回写主表既有栏`／`落回执件`（共 7 条，`落回执件` 与 `回写` 同源可合并）。

### 第二步 · 逐条找载体

对每条动作，在三处载体里找**同一个动作名或其同义词**：

| 动作 | A 排程 | B 开工检查项 | C 闸门 | 判 |
|---|---|---|---|---|
| SAPI 合成 | 无 | 无 | 无 | **无触发**（但属一次性建设，非周期动作，可豁免） |
| ffmpeg 转码 | 无 | 无 | 无 | 同上，可豁免 |
| **lark-cli 发送与回读** | 无 | 无 | 无 | **无触发**（周期动作，不可豁免）← 坑 094 就出在这里 |
| 第三步事件接线 | 无 | 无 | 无 | 未开工项，标记"未开始"而非"无触发" |
| **摘四要素** | 无 | 无 | 无 | **无触发**（周期动作，不可豁免） |
| 回写主表／落回执件 | 无 | 无 | 无 | **无触发**（周期动作，不可豁免） |

### 第三步 · 出两张名单

- **有触发**：动作 → 载体 → 载体名（例如"回写 L1 → B → 开工入口 §二.6①"）
- **无触发**：动作 → 为什么算周期动作 → 建议挂哪里

**只看"无触发"那张。** 有触发的那张不用管。

## 三、判据与证伪

**判据**：一个分工件跑完，输出"无触发"名单；名单为空＝该件所有周期责任都有落点。
**证伪（这条判据是哑的，如果）**：把一份**已知某动作确实每周都在发生并留痕**的分工件丢进去，它仍报"无触发" ⇒ 判据误报，须收窄动作词表或扩同义词表。

**已知会误报的两类**（先记下，免得后人当成新发现）：
1. **一次性建设动作**（SAPI 合成、转码、接线）本就不该有周期触发——须先判"周期/一次性"，否则名单会被噪声灌满。
2. **同义不同词**（"摘四要素" vs "整理回执" vs "摘成四要素"）——词表窄了必漏。

## 四、这次的手工实跑结果（2026-11-10 21:0x，尺＝三处载体现读）

- 对 ㊼ §六 跑一遍：**周期动作 4 条，无触发 4 条**（发送与回读／摘四要素／回写主表／落回执件）。
- 对 `AI-开工入口.md` §二 跑一遍：**25 条强制动作，全部有载体**（它们本来就是检查项本身）。
- 对 27 道闸门跑一遍：**全部有载体**（它们本来就是闸门）。
⇒ **没落点的只出现在"设计件里写的分工"，不出现在"开工入口与闸门"里**——所以这个检查只需对**设计件／分工表**跑，不必全库跑。

## 五、边界

- 本卡只给判据与跑法，**未做成程序件**；要不要做成常驻检查（挂在收口检查或开工脚本里）候法师字——它要么改共用程序件，要么加一条排程，两条都须字。
- 判据对"周期/一次性"的区分目前靠人判，**尚未机检**；这是本卡最大的未验处。
