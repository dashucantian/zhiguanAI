# 复现路径 002：把第二种脑电设备接入既有采集架构（多设备硬件层）

> **目标读者**：已有一套"单一设备 + 单一入口"的脑电采集系统（如本项目的 Muse + Web 控制台），现在拿到第二种设备（任何带 TCP 数据服务的脑电工作站），想把它接进**同一个后端、同一个实验流程、同一个前端**，而不是另起炉灶写一套平行系统。
> **前置条件**：
> - 现有系统有一条清晰的脑电数据通路：设备 → 接收器 → 环形缓冲 → 分析/保存/前端广播
> - 新设备能对外提供数据流（TCP / 串口 / LSL 任一均可，本卡以 TCP 为例）
> - 具备 Python 与一点点前端（HTML/JS）能力
>
> **预计耗时**：2–3 天（协议明确时）；若厂商协议要靠逆向，另加 1–2 天
> **难度**：中等。真正的难点不在"收数据"，而在**把单设备假设从系统里逐层剥离**，以及**用可复现的自测替代真机**。

---

## 第 0 步：先守住架构原则（半天，最重要）

**本项目遵守的约束**：新设备一律并入既有单一硬件层与唯一入口，不开平行采集脚本、不加第二个控制台。这条原则来自项目自身的"统一架构不造冗余"纪律。

它决定了后面所有技术选择：接收器必须与既有接收器**同接口**、缓冲必须**参数化**而不是复制一份七通道版、前端必须**按数据渲染**而不是按设备写死。

**动手前先做一件事：找全"单设备假设"的藏身点。** 在代码库里 grep 通道名和采样率常量，本项目扫出四类：

```
grep -n "TP9\|CHANNELS\|SFREQ" **/*.py **/*.html
```

| 藏身点 | 表现 | 处理 |
|--------|------|------|
| 缓冲层常量 | `CHANNELS = ["TP9",...]`、`SFREQ = 256` | 改为构造参数（缺省值=原值） |
| 会话/实验层 | 波形循环 `for ch in CHANNELS`、样本数 `len(eeg[CHANNELS[0]])` | 改读 `buffer.channels / buffer.n_ch` |
| 前端 | 图例、画布行数、通道读数写死 4 通道 | 改为按帧数据的键动态渲染 |
| 保存层 | npz/报告的通道列表 | 由缓冲携带，禁止二次推断 |

**判据**：改造完成后，跑一次旧设备（Muse）的完整模拟，产出与改造前逐字节一致——这证明"缺省行为不变"，是后续一切的地基。

---

## 第 1 步：协议侦察（半天）

**优先级：官方开发者仓库 > 官方说明书 > 自己逆向。** 本项目的顺序反过来了（先读的说明书），结果说明书漏了两个关键握手细节，是后来克隆官方 mock 服务器源码才发现的。教训：**厂商给 AI 助手写的集成仓库（SKILL/插件/mock 代码）往往比人类说明书更接近事实**，因为代码不会漏写步骤。

侦察要拿到的六项信息（缺一项就别开始写代码）：

1. **连接与握手**：端口、是否要先发指令。本案实测：TCP 连上 9600 后**必须发送 `"start"`**，否则一个字节都不推；说明书全文无此句。
2. **行格式与字段数**：本案为按行 CSV；USB 模式 10 列（1 样本）、蓝牙模式 42 列（5 组 × 8 字段），**必须按字段数自动识别**，禁止硬编码切列。
3. **通道顺序**：要拿到代码级文档依据。本案定版 `CP5, CP6, PO3, PO4, O1, Oz, O2`，250 Hz，单位 µV（与厂商群聊答复、官方配置档案交叉一致）。
4. **时间戳语义**：单位（ms）、起点（设备开机/会话开始）、重连后是否归零——直接决定第 4 步的时基方案。
5. **分包行为**：一行 CSV 可能被 TCP 拆成多次发送（官方 mock 故意如此演示）→ 接收端**必须攒到换行符再解析**。
6. **无设备时能否出流**：本案答案是不能——"打开数据服务"按钮绑定设备连接状态，且无模拟模式。这意味着真机到货前，**验证只能靠自己造的 mock**。

> 逆向兜底（本案实际用到）：软件无文档时，解包其程序（Electron/Java 均可解），对界面组件类做字符串扫描，找到按钮使能条件绑定的状态字段。一天内可完成，合法合规范围内仅用于互操作。

## 第 2 步：定义接口契约（1 小时）

新设备接收器实现与既有接收器**相同的鸭子接口**，上层完全不感知设备差异：

```python
class TcpReceiver:
    running: bool              # 工作线程开关
    last_error: str            # 最近一次错误文本
    packet_count: int          # 已解析样本组数
    on_status: callable        # 状态回调（连接/断线/error/end 事件）
    def start(self): ...       # 非阻塞，内部起线程
    def stop(self): ...        # 置停 + 尽力优雅关闭（触发断连保存）
    def is_connected(self) -> bool: ...
```

**纪律**：失败路径必须发 error+end 事件（与既有硬件层同一约定），否则前端会停在"假在线"。

## 第 3 步：缓冲层参数化（半天）

最小改动模式——**全局常量原样保留，缓冲实例携带自己的布局**：

```python
class DataBuffer:
    def __init__(self, channels=None, sfreq=None, device="muse"):
        self.channels = channels or CHANNELS      # 缺省=旧行为
        self.sfreq = sfreq or SFREQ
        self.device = device
        self.n_ch = len(self.channels)
        self.eeg_all = {ch: deque(maxlen=SECONDS * self.sfreq)
                        for ch in self.channels}

    def add_eeg(self, sample_times, eeg, aux):
        chs = range(len(self.channels))           # 不再 range(4)
        ...
```

下游所有函数（波形窗口、频段功率、存盘、报告）里的通道数和采样率一律改用实例属性。**改动全部是"读实例"替换"读全局"，无逻辑变化**——这让代码审查极其便宜。

存盘元数据加一个 `device` 字段，数据从此自带血统（本项目入库登记与回放筛选直接受益）。

## 第 4 步：写接收器（1 天，五个工程点）

**① 握手**：连接成功后立刻 `send(b"start")`，再进入收流循环。

**② 行缓冲**：socket `recv` 的返回边界与行边界无关，用 `buf += chunk; split(b"\n")` 处理，残段留到下次。

**③ 列数自适应**：按字段数分派（10 列=单样本 / 42 列=5 组），未知列数记错跳过——**宁缺勿错**，错列会静默污染数据。

**④ 时基（本卡最硬的一条经验）**：
- **不要**用"收到即当下"。TCP 积压会成批到达，若都打本地时间戳，采样率瞬间虚标数倍，下游滤波与频段分析全部失真——**这个 bug 正是自测时 mock 成批推送暴露的**。
- **要**用设备时间戳，加两道防御：单调不回退（回退即丢弃或重定基线）、跳变超阈值（如 >2s，常因重连归零）则重新锚定。
- 缓冲的 `add_eeg` 接受外部时间轴，本地墙钟仅用于显示与新鲜度判断。

**⑤ 看门狗与断连**：超过 N 秒无数据判离线并触发保存；断线自动重连（指数退避，上限 10s）；重连成功后重发 `"start"`。信号调理（去直流+1–40Hz 带通）与既有设备路径同构，保证两条硬件线的频段数据可横向比较。

---

## 第 5 步：接通会话与前端（半天）

- 会话/实验构造处按 `adapter` 参数选择接收器与缓冲：`neuradock` → `DataBuffer(channels=ND_CHANNELS, sfreq=250, device="neuradock")` + `TcpReceiver`；其余分支不动。
- 前端设备下拉框加一项，payload 加 TCP 地址字段（默认 `127.0.0.1:9600`）。
- **波形渲染改为 `Object.keys(wave)` 驱动**，图例、行数、通道读数全部随帧数据自适应——这一步做完，任何第三种设备的前端工作就只剩"加一个下拉选项"。

---

## 第 6 步：不等硬件的端到端自测（半天，本卡的价值所在）

厂商软件没有模拟模式？**自己造一个数据源**——直接采用官方 mock 服务器（本项目用其 codex 插件仓库里的 Node 脚本），它按真协议推流（含故意拆包）。

两级测试（本项目均为可重复运行的脚本，退出码 0/1，可直接进 CI）：

**单元级**：mock 推流 → TcpReceiver → 缓冲。验证点：
- 握手发生、行数计数正确；
- 七通道全部到位，npz 形状 `(N, 7)`；
- **物理正确性**：mock 在 Oz 通道掺 10 Hz 正弦 → 频段分析中 alpha 应在 Oz 上出主峰（本案实测 10.03 Hz）；
- **时基正确性**：实测采样率应≈250 而不是成批到达的虚高值；
- 42 列蓝牙行与 10 列 USB 行混合都能解析。

**集成级**：从真实会话入口（监测 start）走完整链路 → tick 事件波形含 7 通道 → 停止存盘 → 读回 npz 核对形状、`device` 字段、通道名。**并回归旧设备模拟路径**，确认改造无涟漪。

自测产生的模拟数据文件当场删除，不入库——这条要写进脚本，人总会忘。

## 已知失败模式速查

| 症状 | 根因 | 处置 |
|------|------|------|
| 连上了但一个字节都没有 | 没发 `"start"` 握手 | 见第 1 步第 1 项 |
| 数据断断续续、半行报错 | 没做行缓冲 | 见第 4 步② |
| 采样率虚标、滤波输出怪 | 收包即打本地时间戳 | 见第 4 步④ |
| 频段功率全 0 | 缓冲还在读 4 通道全局常量 | 回第 0 步清单逐处排查 |
| 前端只显示 4 条波形 | 图例/行数写死 | 第 5 步动态化 |
| "数据服务"按钮灰着点不动 | 厂商软件按钮绑定设备连接，无模拟模式 | 正常现象，等真机或用 mock 自测 |
| 重连后时间轴跳变 | 设备时间戳随重连归零 | 第 4 步④跳变防御 |

## English Summary

**Reproduction Guide 002: Plugging a Second EEG Device into an Existing Single-Device Architecture**

How to integrate a new hardware stream (here: a 7-channel EEG workstation exposing a TCP data service) into an existing acquisition stack — same backend, same experiment pipeline, same web console — without spawning a parallel system. Target: 2–3 days once the wire protocol is known.

**Core discipline:** every new receiver implements the *same duck-typed interface* as the existing one (start/stop/running/last_error/status-callback); the ring buffer is parameterized (`channels`, `sfreq`, `device`) with defaults byte-identical to legacy behavior; the frontend renders channels **from the data keys**, not from device-specific constants. Grep for channel-name and sample-rate constants first — they mark every hidden single-device assumption.

**Protocol reconnaissance:** prefer vendor developer repos (mock servers, integration plugins, config profiles) over manuals — code cannot skip a step, docs can. We learned the hard way: the connection requires sending `"start"` before a single byte flows, and one CSV line may be split across TCP writes. Channel order, rate and units must come from code-level documentation, cross-checked with vendor chat.

**The hardest engineering point is time-base:** never stamp-on-arrival (TCP backlog inflates apparent sample rate and silently corrupts downstream filtering); use device timestamps with monotonicity and jump guards. Auto-detect row layouts by field count (10-col USB vs 42-col Bluetooth); watchdog + exponential-backoff reconnect + reconnect re-handshake.

**Test without hardware:** vendor software gated its data service behind a physical device connection with no simulation mode — so we drove the whole pipeline against the vendor's official mock server. Two green self-tests (unit + full console-session integration, exit-code CI-able) validated handshake, 7-channel ingest, a planted 10 Hz alpha probe peaking on Oz, correct 250 Hz effective rate, npz shape and `device` metadata — plus a legacy Muse regression proving zero ripple. Simulation artifacts self-delete.
