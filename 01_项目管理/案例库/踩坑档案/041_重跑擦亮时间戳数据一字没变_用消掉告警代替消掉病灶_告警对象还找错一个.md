## 现象

值守片说：`任务关系图/视图甘特流程图.html`＋`任务关系图.html`＋`_records_fresh.json` 三件停在 10-04 04:05—04:07，等 212.1 小时，**状态＝无人接**；同目录两把生成器在盘，**"重跑即修复"**。

本窗照做，而且做得算规矩（先备份、跑后逐行比对）：

```
备份 → _analysis_tmp/视图重跑前备份_1013/（跑前 sha16 5ef77597e5ca3e5d／8e9085eb3f16407f）
python 生成关系图.py     → RC=0，「已生成…任务数 72」
python 生成甘特流程图.py → RC=0，「已生成…任务数 72」
与备份逐行比对          → 增 0 行／删 0 行        ← 关键在这
mtime                   → 10-04 → 10-13 01:34:53  ← 只有这个变了
```

**告警消失了，但没有任何东西被修复。** 三件的内容与跑前**完全相同**。

## 根因（两层，都不在"视图"上）

**第一层：视图根本不是病灶。** 两把生成器实际读的输入是 `_records_raw.json`，实测 mtime＝**10-12 18:58:25（等 6.6 小时）**——**并不旧**，图谱线昨日晚间重拉过。真正发生的是「**拉了，没人往下游跑一步**」。

**第二层：跑出来一字不变，是因为源数据本身就是定格。** 源表（飞书 Base）`更新时间` 最新一条＝**09-30 01:21**，10-01 之后 **0 条**（10-12 本窗已实测过一次）。⇒ **重跑只是把账面时间戳擦亮，修不了"没人写源表"这件事**——而后者才是这条悬案从头到尾的真身（与 P3／排期表那条同源：那是法师面的事，**不是任何窗能"接单"干掉的活**）。

**附带查出：告警连对象都找错了一个。** `_records_fresh.json` 被并列进"三件"，但
- `grep -rl "_records_fresh" --include=*.py` ＝ **0 个脚本读它**（只有 10-04／10-07／10-11 三份**文书**提到过）；
- `git check-ignore -v` ＝ 命中 **`.gitignore:236:_*.json`**，压根不进 git；
- 它与同目录 `_records_raw.json.bak_1004` **84940 B、sha256 前 16 位相同＝逐字节相同**——就是同一份数据的一份备份。
⇒ **它是 10-04 那轮的一次性中间产物，追它没有任何下游后果**；把它和真产物并列，等于让下一轮继续追一件追到也白追的东西。

## 对策（三条，已在本轮落成动作或提请）

1. **凡"重跑类"处置，判据必须是"跑前跑后逐行比对"，不是"跑成功了"**。RC=0 只证明生成器没崩；**内容零变化＝这条告警没有可修对象**，此时该报的是"病灶不在这里"，不是"已修复"。⚠**把 mtime 变化当成果＝自我表扬式收口**。
2. **陈旧类告警拆成两问，两问都过才自消**：①派生物 mtime 是否晚于其**实际输入**（不是晚于日历）；②那个输入本身新鲜吗。现势＝①已平（01:34:53 ＞ 18:58:25）、②按期（6.6 小时）⇒ **该条应自消，不该日日列**；真要列的是「源表自 09-30 起无人写」，换个类别去列（人面，不是窗面）。
3. **告警对象白名单一条**：**只有"被脚本读的输入"或"被 git 跟踪的产物"才算断链对象**。gitignored 的一次性产物／备份文件移出悬案面——否则 212 小时这个数字明年还在。

## 可复用边界

- 适用：一切**"过期／陈旧／无人接"类告警的收口**——缓存、派生视图、快照、看板、定时产物、CI 报告。也适用于**值守面构造检索清单**（本例的"三件"就是检索面没区分产物与备份）。
- 不适用：真需要重算的东西（输入变了但产物没跟上）——那时"重跑＋比对"会显示**有**行变化，属正常修复。
- ⚠**这条不是"要谨慎"**。它的硬内核是一句可核查的话：**你这次重跑，跑前后逐行比对差了几行？** 答"没比对过"＝你不知道修没修；答"0 行"＝你擦亮的是账面，得接着往上层找病灶。
