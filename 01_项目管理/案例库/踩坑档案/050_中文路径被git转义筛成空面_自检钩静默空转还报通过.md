# 050｜判据面被"合法地"筛成空：git 把中文路径转义加引号，`endswith('.md')` 全落空

**日期**：2026-10-14　**窗口**：W3 协调 `542dc2cd`　**级别**：KZ（工具自证不彻底会长期空转）

## 事实

本窗给「证据台账」装 pre-commit 钩，思路是：暂存区里筛 `.md`／`.txt` → 逐条查裸数有没有绑证。
钩子装好后在临时仓里跑，**一次输出都没有**，而且提交照常通过——看着像"这批件没问题"。

真因两条，都是"筛子"而不是"内容"：

1. `git diff --cached --name-only` 对**非 ASCII 路径缺省转义并加引号**：
   `测试6.md` 输出成 `"\346\265\213\350\257\2256.md"`。于是
   `grep -E '\.(md|txt)$'` 与 `ln.endswith((".md",".txt"))` **同时为假**——行尾是引号不是扩展名。
   本仓文书几乎全是中文名 ⇒ 这道筛子对本仓**恒为空面**。
2. 钩子里那句写成 `… --staged 2>/dev/null`，把 python 的 `FileNotFoundError` traceback 吞了
   （临时仓里没有 `收口检查.ps1`）。零输出 + 零告警 = 静默空操作。

两条叠加后，"自检通过"的实际含义是"自检什么都没看到"。

## 危害

这型坑的可怕处在于**它不报错、也不报错第二次**：钩子内建"永不拦"（四窗共用一个 index，
拦一次就是挡三个窗），所以它无论如何都 exit 0——把"放行"和"没跑"混成了同一个信号。
项目里同族的已经踩过三次：门4 用 GBK 解 git 的 UTF-8 输出吞掉换行（误报缺 trailer）、
门14 拿 mtime 当生效时点（改规约即缩小检查面）、坑 044 甲（抓不到当不存在）。

## 对策（已落地）

1. **读 git 的机器口一律 `-z` ＋ `-c core.quotepath=off`**，按 NUL 切；
   `ev_check.py:targets()` 与 `.git/hooks/pre-commit` 两处同改，并在行内留字说明为什么不能省。
2. **空输出必须自证为"没跑"而不是"通过"**：钩子改为捕获 stdout＋stderr，
   零输出即打印 `⚠自检零输出 ⇒ 这一轮没有证据自检，别当通过`。
3. **被检面为零也要出声**：`ev_check` 零命中时打印
   `检索面内 0 份文书（取法＝… ；空面≠通过，只是本轮无对象）`。
4. 加一条**双向自证**习惯：新写任何"筛子型"判据，先用**一个已知应该被筛出来的中文名样本**跑一遍，
   筛不出来＝判据坏，不是样本干净。本轮临时仓实测两面对照：
   闸门源在场 → 报 `丙 裸数×2／甲 假引用×1` 且提交仍通过；闸门源缺席 → 报 `不作通过结论` 且提交仍通过。

## 一句话口令

> **筛子跑空前，先喂它一个"一定该被抓到"的名字。** 抓不到，修筛子，别交差。
