## 一、现象

两封跨窗函的**第 3 行「收件」行**里，引用的那封函名被写错**一个分隔符**：

| 封 | 第 3 行引用的是 | 错在哪 |
|---|---|---|
| 回执件（`…_回执_两处口径差照收_C3-13保持未动_⑱四条已复扫_v1.md`） | `…-复Qoder窗c73afab0-⑰改毕回件独立复点成立与两处口径差_…` | `c73afab0` 与 `⑰` 之间写成**连字符** |
| 订正件（`…_订正_⑰回件取件时刻标签与四值止时_三篇末次同字节重跑_v1.md`） | 同上（同型同错） | 同上 |

正确写法是**下划线**：`…-复Qoder窗c73afab0_⑰改毕回件独立复点成立与两处口径差_…`。

⚠关键：**窗号本身两处都对**，错只在「窗号 ↔ 标题」之间那个分隔符。

## 二、根因

1. **文件名是手写进正文的**（不是从盘上生成后再复制），手指打错一个字符，肉眼在中文长串里看不出来。
2. **当时没有"落笔后按盘上落名逐字回比"这一步**。事后补的互引扫描才查出：一封 OK、一封 MISSING。

## 三、为什么常规检查抓不到（三层盲区，逐层说明）

| 检查方式 | 为什么抓不到 |
|---|---|
| **比"窗口 id"** | 比对的是「文件名里的窗号 ↔ 抬头里的窗号」，而此处**两个 id 都对**，错在 id 与标题之间的符号 ⇒ 比 id 永远比不出来 |
| **子串检索** | `*复Qoder窗c73afab0*` 对两种形态**都命中**（连字符版、下划线版都含这个前缀）⇒ 子串尺看不见 |
| **肉眼读函／glob 读目录** | 中文长文件名里 `-` 与 `_` 视觉近似，且 glob 只判"存在与否"、不判"逐字是否相等" |

⇒ **唯一有效的判据＝按盘上落名逐字全等比对**（第 3 行反引号里的整串 ↔ 目录里实际存在的文件名，做一个集合差）。

两封函 05:3x 落笔、05:32:58／05:33:23 即修，**修前版本从未单独存过盘**（不是另存副本再改名，而是就地 Edit／替换）。⇒ 任何**只针对盘上件**的检索（本窗当时那一整套 grep＋结构化比对＋规则面）**必然抓不到**。这不是检索不够努力，是"经历过的错误"在盘上本就不留痕。

## 六、解法

- **甲（首选）**：函件落笔后跑一次**互引回比**——取每封第 3 行反引号内的文件名，与目录实际文件名做**逐字全等**差集，报 `OK`／`MISSING`。作者自备脚本即可（写作者窗已落 `_analysis_tmp\_probe_crossref.py`）。
- **乙（判据侧）**：任何"在不在清单里／引对没引对"的判断，**必须整行全等或精确路径**，禁用子串（与坑 083、与 ㊲ 待立法同一根）。
- **丙（取证侧）**：同轮自造即修的缺陷，**盘上无痕**——要立卡就得指向**会话日志**（工具调用参数原文），否则卡的"依据"只能是转述。

## 七、排障顺序

1. 先看第 3 行原文，**逐字符**读窗号与标题之间那个符号（`_` 还是 `-`）。
2. 别用 glob／子串判断"文件在不在"，用**目录清单逐字全等**比对。
3. 盘上若是正确串、但确实发生过错误 ⇒ 去**会话日志**找落笔与修复的两次调用。
4. 若日志里也没有 ⇒ 只能记为"据报、无一手面"，**不得当作已核**。

## 八、教训

- **两个 id 都对，不等于引用对。** 引用的正确性在**整串**上，不在关键字段上。
- 手写长中文文件名是本仓的**高危动作**；要么从盘上复制，要么落笔后机器回比一次。
- **同一轮自造即修**的缺陷，事后只能靠日志立证；所以"当时没留证"不等于"没发生"，也不等于"能立卡"——两者都要说清。
