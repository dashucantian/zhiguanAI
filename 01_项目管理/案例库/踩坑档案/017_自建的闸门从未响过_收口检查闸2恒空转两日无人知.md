# 017_自建的闸门从未响过_收口检查闸2恒空转两日无人知

> 记录：2026-10-03 ｜ 窗口：**W1 工程线**（`AI-005·DeepSeek(deepseek-flash)`，Session `W1-DEEPSEEKFLASH-20261003-A`）
> 性质：**已生效两日的缺陷**（检查工具失灵，非数据损坏）
> 取号留证：写入前查 `案例库\踩坑档案\` 现有编号，末号为 `016` ⇒ 取 **017**（§二.5「编号先查后取」）
> 同类：教训 **7.1**「本脚本自身输出的判据亦须被核验」——`收口检查.ps1` 头注里就写着这句，**坏掉的恰恰是脚本自己**

## 一、经过

10-03 收口时，我**明明刚写完** `D-1003-W1a.md`（还提交了），跑 `收口检查.ps1` 却得到：

```
legacy max D = D52 (frozen tail only); today shards: 0 [D-1003-Wxa style]
[NOTE] no D-shard today - ... ; pure exec rounds skip
```

**文件就在那里，闸说没有。** 当日即回查实现，见：

```powershell
Get-ChildItem '01_项目管理\登记分片' -Filter "D-$today-W*x.md"
```

## 二、真因

Windows `-Filter` 的通配符里 **`x` 是字面量字符**，而本目录 README 规定的真实命名是
`W1a`／`W2b`＝**W ＋ 窗号 ＋ 日内序**（例：`D-1003-W1a.md`）。
⇒ 该 filter 只可能匹配 `D-1003-Wx.md`、`D-1003-W1x.md` 这类**根本不存在的名字** ⇒ **恒为空**。

写它的人（我）当时脑子里把 `Wxa` 当成了"W＋任意＋x＋a"的模板，**把模板当成了通配符**。

## 三、为什么坏了整整两日没人发现（这条比缺陷本身更值钱）

1. **它只出 `[NOTE]` 不出 `[告警]`**——设计上"纯执行轮可跳过"，于是"没找到分片"看起来永远像
   "**本轮无需分片**"（正当）。**症状与正常态长得一模一样**（同坑 012 的病根：两种相反的情况长得一样＝没有告警）。
2. 输出里还有 `legacy max D = D52` 这一行**看起来很有内容**，读者的注意力被它吸走；
3. **没有任何东西检查闸门自己**——脚本头注写了"勿把 [OK] 当工作完成"，
   但**没有一个机制去验证"这个闸到底会不会响"**。

## 四、硬证据（建闸当日就是坏的）

| 日期 | 真实存在的 D 分片 | 旧 filter 报数 | 新 filter 报数 |
|---|---|---|---|
| **10-01（建闸当日）** | `D-1001-W1a.md`、`D-1001-W3a.md` | **0** | **2** |
| 10-03 | `D-1003-W1a.md` | **0** | **1** |

⇒ 闸 2 自 10-01 建立起，**每一次运行都在说"今天没有分片"**，包括确有 2 件的那一天。

## 五、为什么危险（不是"少报一个数"）

**一个永远不响的闸，比没有闸更危险**：它给出"**已检查且通过**"的假象。
闸 2 的职责正是让"**该登记而没登记**"必然可见——它失灵时，**漏登记不会有人发现**，
而这正是本目录制度要治的病（KZ-029：登记滞留四起、共享大文件互等）。

## 六、处置（已生效）

1. **修 filter**：`-Filter "D-$today-W*.md"`（提交 `047f952`）；
2. **补"闸门形状自检"**：用宽形状 `D-*-W*.md` 统计历史分片，**若为 0 即告警**
   —— 这样同类形状错误会**自己叫出来**；本日输出 `[OK] 闸2 自检：D 分片命名形状可匹配（历史 41 件）`；
3. 修复前后同一命令对照：`today shards: 0`（无告警）→ `today shards: 1` ＋ 正常 OK 行；
4. **提请立规（候裁——AI 不自立规，§四ter）**：**凡新建闸门，必须留下"它确实会响"的证明**
   （用一个**已知正例**跑一次，看到它报出来，才算建成；只看到它对坏数据沉默，不算证明）。

## 七、可复用的一句话

> **闸门要有"能响"的证明。** 只验证"它对坏数据不说话"，等于什么都没验证——
> 因为它可能对**好数据**也不说话。

本卡只是把实现改回它本该匹配的形状）。
