# 坑 038：派工书里的"这条还没做"可能是过期读数——接手"新建"类派工，先跑一条 `git log` 就能挡住整套重复件

> 〔取号留证〕本卡取 **038**。入卡前实测 `ls 01_项目管理/案例库/踩坑档案/`：现势末号＝**037**、件数＝**37**、`grep -c ^038`＝**0**
> （2026-10-12 21:29:10 `date`＋`ls` 实测）⇒ 001–037 连续无缺号，按规约 §二.5 取 038。
>
> 发现日期：2026-10-12｜发现窗：**W3 人机建构 `d776cb39`（AI-020）**——本窗是**被派工的一方**，坑在"照单新建"这一步前被挡住，未产出重复件。
> 类型：**派工／账面状态类**（与坑 027「地图自己漂了」、坑 028「引用未过身份闸」同族：都是**拿二手读数当一手事实**）
> ｜危害等级：**中高**——它不写错代码，它让**已经入库交付过的一件事被再做一遍**，且新那份与母本并存，从此谁正源说不清。

## 现象

派工书（协调窗 `44443a0e`，2026-10-12 21:1x）把 `ZG-069`《②模板包×6 导入即用原子模板》作为**待办新件**派给本窗，依据是排期表里该条状态＝「**待法师审定**」。

本窗动笔前查盘，实测三条：

1. `git log --oneline -- 07_模板包`（默认**新→旧**）**末行＝最早一笔** `17bd2ad feat(W3): ZG-069 模板包×6 成壳入库（07_模板包 22件·法师放行批04·按纪律⑤路径限定）`，时刻 **09-28 00:01**——**同一条 ZG-069，早已入库**，提交信息里就带着这个号；其后还有两笔：`51e4f87`（09-30 01:30，升 v1.1·法师 09-30 三裁·放行批14）与 `1e3bf04`（**10-10 02:41，系 W3 协调线批量代提 50 件、不是法师审定**）。
   ⚠**本卡初稿把这条写成"首行＝17bd2ad"，方向读反了**（`--oneline` 首行是**最新**那笔 `1e3bf04`），21:45 由协调窗实测回敬、本窗 21:54 自证更正。**要紧的信息恰恰是它之后又被两笔动过**，且最后一笔非审定 ⇒ 少绑一个"序"就把代价评估算错一格（详见 §对策 4）。
2. 后续 `51e4f87` 升 v1.1、`1e3bf04` 批量入库，`07_模板包/README.md` 明载法师 **2026-10-04 裁 4「甲」**：`07_模板包/` ＝ **母本唯一真相源**，并立打包同步规则；盘上实测 **26 件全部 tracked**；
3. 源表 `更新时间` 最新一条＝**09-30 01:21**，10-01 之后 **0 条**（10-12 重拉实测在案）⇒ 那条「待法师审定」是**十余天前的定格**，不是现势。

⇒ **若照单新建**，盘上会出现第二套模板包，而母本是被法师三次（09-28／09-30／10-04）审定过的面——重复不是"多写了几个文件"，是**动摇唯一真相源**。

## 根因

**派工面的判据链少一跳**：状态取自**源表快照**，没有回查**盘上与 git 史**。而本项目的源表是**清单不是排期表**（裁决／承接／计划三列近乎空转，`验收标准／承担者` 填得好），它的"状态"列**没人负责回写**——所以它天然滞后于 git。

第二层放大器：**"待审定"这个字样看着像"有人在管"**，于是引用方默认它是活的；实际它可能是**已审完但没回写**的历史定格。**字面的管理感 ≠ 数据的新鲜度**。

第三层（本窗侧）：接手人容易把派工书当**一手事实**，而它本质是**二手转述**——一手是 `git log` 与文件本身。

## 对策（六条，落成后可逐条核查）

1. **凡派工书写着"新建／尚未做／待审"，动笔前先跑一条 `git log --oneline -- <目标路径>` ＋ `git ls-files <目录> | wc -l`**，两行输出即判"做过没有、入库几件"。成本 <5 秒，本坑唯一有效防线。
2. **引源表状态入结论时，必须同时报源表该列的 `更新时间`**（本例：引一条 09-30 定格的状态去派 10-12 的活）。时刻不报，过期读数就伪装成现势——这是 §二.13「报数须带测量时刻」在**账面状态**上的用法，不是只在物理量上用。
3. **被派工方发现前提不成立 ⇒ 当轮自曝＋按"真增量"重切范围，不整体退回也不整体照办**。本窗即按此办：六包本体一字未动，只做派工要求的**三项真缺口**（每份模板头部三行／只读自检脚本／母本缺失的维那 SOP 模板），并把落点做成**甲／乙两候选**停手报，不自定。
4. **读数必须绑三样：命令＋侧（谁的口径／哪台量具）＋序（时序方向）**。本卡初稿就栽在**序**上：`git log` 默认**新→旧**，我把"首行"当成最早那一笔，于是**漏掉了"母本成壳之后又被两笔动过"这一层事实**（其中 10-10 那笔系批量代提、非法师审定）——而这一层恰恰是评估"改母本要付多大代价"的关键。⇒ 口令：**凡写"首行／末行／最新／最旧"，同句必须带方向与时刻**；位置词单独出现＝不可复算。
5. **判"这事不能进 git"之前，先查同目录有没有先例件**（本窗 21:3x 的实错）：我只查了 `.gitignore:272`（`04_研究调研/` 目录级屏蔽，09-26 加），就断"研究件在 git 眼里不存在、不可提"。协调窗 21:45 回敬现物，本窗 21:54 自证：`git ls-files 04_研究调研` ＝ **4 件确实 tracked**，入库笔 `1f31a08`／`14a4c17` 正文写着「**法师 10-01『入库』裁——目录级 ignore 维持不变，本件单件 `-f` 特例**」。⇒ **规则与既有跟踪并存是常态，不是矛盾**；先例给的路径是**不动"不准修"件、逐件拿字**，不是"动 ignore vs 留盘"二选一。与既有口令「断言项目没有须先报检索面」同源。
6. **引先例（含"您选过甲／上次是这么办的"）须带日期与笔号，并现查有无更晚的同型裁**（2026-10-13 01:54 协调窗 `44443a0e` 函 §一 自曝提请、本窗 02:0x 采纳落卡；本条由协调窗起草原话，本窗只誊入自己那张卡，未改其义）。形状＝该窗 01:19 函据"法师 **10-11** 对同型局面已择甲"派本窗"按甲案自提"，而法师 **10-12 12:5x** 已对同型局面（登记表两窗文字压同一文件）改选「**乙（并批分署）**」，入库笔 `a0b1bc9` 正文 §二 写着「依法师所选'并批分署'逐行归属」并附三窗逐行分署表。⇒ **前四条查的是"盘上状态"的过期读数，这一条查的是"先例"的过期读数**：同一根病灶（二手读数当一手事实），对象换了。口令四条：**①引先例必带日期＋笔号（提交号或文件名），无号即视为推定；②引之前 `git log --since=<该裁定日> --grep=<同型关键词>` 现查有无更晚的同型裁；③⚠这条闸有天然漏面——`--grep` 只看得见**已入库**的笔，**法师刚说、尚未提交的那一字它照不到**（10-13 实证：本窗 02:03 跑此闸得"无第三个更晚同型裁"当时属实，而法师 02:0x 的第四判"归口一家"此刻只活在会话与函件里、无提交笔；此加严系协调窗 `44443a0e` 02:18 急件提请、本窗 02:28 采纳落卡）⇒ **凡查先例，同批再扫两处**：`01_项目管理/信箱/engine/` 近 2 小时 mtime ＋各窗己档末轮；本窗 02:23 已用过一次等效动作（复跑 `git diff -U0` 扫出索引由 11 行变 12 行，比对方通知早到窗）；④"我记得您选过甲"不构成派工依据**——构成依据的是能复算的那一笔。本窗 21:5x 亦犯同型（把 10-11 旧登记当周扫新发现，见 §一 与本窗己档第 5 轮），故此条两边都管：**派工方引先例、研究方引旧登记，同一道闸**。

## 可红反例与正对照

- **反例（本卡怎么知道自己有效）**：新接一单"×× 还没做"，跑 `git log -- <路径>`，**输出里任意一行**（不管最新还是最早）就带着同一个任务号 ⇒ 红。检验量＝**一条命令的输出**，不需要读完派工书。⚠**别把判据写成"首行"**——`git log` 默认新→旧，"首行"这个位置词本身就把时序绑反了（本卡初稿即犯，见 §一.1 订正注记）。
- **正对照（不是逢派工就驳回）**：同一批派工里的 **P7 周扫**与 **P8** 一条都不与盘上冲突（P7 是口径变更"月改周"、P8 明示不需本窗动）⇒ **照办，不提请**。判据是"盘上有没有同号入库笔"，不是"我不信派工"。
