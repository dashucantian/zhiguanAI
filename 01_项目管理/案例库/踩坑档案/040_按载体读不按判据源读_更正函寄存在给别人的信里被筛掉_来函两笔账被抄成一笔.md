## 现象（同轮两笔，同一个根）

### 甲｜更正函**不点名收件窗**，被"按文件名筛信箱"筛掉

10-13 00:2x W3 开工令 §二.2 派我给本窗一句：「卡片本体现在还是 `??` 未入库，**请一次把两笔账清掉**」。我据此在回函里写了一节**「门8 的后半（卡片本体入库）本窗动不了」**，并列了两条理由（法师逐批放行＋`00_案例库说明.md` 压着两窗的字 git 拆不开）。

写完回函（01:07）之后，法师转来 W3 的更正：**同一位协调窗 00:49 那封《复人机建构窗_P11乙验收通过并更正一条引号归属》§三**，标题原话就是「**您 §四 门8 因果方向：照收，且已改我自己派给 VR 窗的措辞**」——**发件比我的回函早 18 分钟**。

而我在 01:08 扫过信箱目录（`ls -1t -l`），那封 00:49 的件**就在列表里**，被我按"文件名写的是`致/复人机建构窗`、与本窗无关"跳过。⇒ **筛掉它的不是没扫，是扫了但按载体筛**。

### 乙｜来函的因果没回判据源核，抄成自己的账面

W3 更正给出的判据源是 `收口检查.ps1:145`：

```powershell
$disk = @(Get-ChildItem -LiteralPath $dir -Filter '*.md' -ErrorAction SilentlyContinue | …)   # :145
if ($c.n -ne $disk.Count) { Bad "案例库索引与盘不符…" }                                        # :150
```

⇒ 门8 数的是**工作树里的 .md 文件数**，**与 git 跟踪状态（`??`／已跟踪）完全无关**。真实因果是**反的**：**只补卡片不补索引才照咬；卡片提不提交根本不改那个数**。本窗 00:3x 补的五行已经让门8 转 `[OK]`（凭据 `output/_shoukou_1013b.txt` §8 原文），这笔账**当时就已清**——而我把它写成"动不了"，等于**用"候放行"给一桩已经做完的事继续挂账**。

## 根因

**两笔都是"顺着载体读，没回判据源"。**

- 甲的载体＝**信头的收件窗名**。但派工面的自我更正**不一定另发一封点名函**，它常常**寄生在回复别人的那封里顺带改口**（因为更正的来源是别人指出的，回信是现场，派工措辞的修订只是同一段的副产品）。⇒ 以"这封不是写给我的"为筛子，**结构上就筛不掉"写给别人但改了我的任务"的件**。
- 乙的载体＝**来函的措辞**。"两笔账"这个词一进来，我就顺着它把两件事当成同一条链（先入库→再平账），**没去读那条闸到底是拿什么当"盘上"**。而这条判据源本窗其实**当天已经读过**——00:3x 为定位索引文件把 `收口检查.ps1:126-160` 整段看过一遍，`Get-ChildItem -Filter '*.md'` 那行当时就在眼里。**读过 ≠ 用它裁过来函**：判据源在手边时，人还是倾向于信来函的因果。

⚠更深一层的害：**账面一旦把"已清的账"写成"清不掉的账"，它就会自我实现**——下一次谁再点这笔，我手里那份"动不了"的理由就成了新证据。这与坑 027「怀疑一个数，要问它多久没被复核了」同根。

## 对策（四条，可逐条核查）

1. **扫信箱的筛子从"收件人"换成"发件窗＋时刻"**：凡**已接其派工的窗**在同一时段的新函，**不论抬头写给谁，一律打开**（本窗面＝`44443a0e`／`d776cb39`／`6c7d4751`／`f7e223f6` 四家）。成本＝多读几封；收益＝派工面的改口不会漏。
2. **引用来函的判据（"要清哪个数"）之前，先回判据源那一行**。判据源已在当天读过的，**必须重读那一行再落笔**——本例 `:145` 就在本窗当天读过的段落里。口令：**来函的因果是"待核引用"，不是事实**。
3. **交件前先跑"该闸能不能自己点名自己"**：本例＝补完索引就实跑一次 `收口检查.ps1`，看到 §8 打 `[OK]` 才写"已清"。⚠同轮反向也成立：**别只靠自己复写的正则**——本窗先用 Python 复刻过一遍计数，真闸跑出来才算数（编码面差异会翻结论，判语 020／KZ-1007-W3e 同族）。
4. **"候放行"只挡提交，不挡补账**：两笔账分开写、分开报——①**索引行账**＝自补即清，不等提交；②**未入库积压账**＝走放行批。队列堵住时**第①笔照办**，否则就是拿"没放行"当"不补索引"的理由（W3 原话：⛔别让"没放行"变成"不补索引"的理由）。

## 可红反例与正对照

- **反例（本卡有效性检验）**：若下轮再有"写给别窗、内含本窗派工改口"的件被跳过——判据＝本窗己档出现"照旧来函措辞"的账面，而**同刻信箱里有一封 mtime 更早的发件窗新函未被引用** ⇒ 红。检验动作＝收口前把 engine 目录按 mtime 列一遍，**发件窗＝派工窗的件逐封读标题**。
- **正对照（不是所有"别人的信"都要读）**：同轮列表里 `20261013-W1-f7e223f6-件E交件`、`20261013-W3-d776cb39-P11乙已落` 两封与本窗任务无交集，**不读不亏**；区分点＝**发件窗是否是本窗派工来源／本窗账面所引**，不看收件人名字。别把对策 1 读成"每轮全量读信"。
