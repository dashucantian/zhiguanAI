# 坑 033：退出报告只活在页面内存里——首跑那份被重载吃掉，而我差点把覆盖上来的假报告记成凭据

> 发现日期：2026-10-12｜发现窗：W1｜VR场景设计（`73336324`，AI-022）｜场景：真机五段全长首跑收口阶段

## 现象

真机第一次五段全长跑（对照组，109 秒）跑完、法师退出后，我去取退出报告。取到的那份：

```
reason: "button"  feedbackAtBaseline: PASS  maxRelDeltaAfterSnap: 0
phaseAtExit: "enter"   phaseElapsedSecAtExit: null   events: [exit]  ← 只有一条
```

乍看**全绿**：PASS、偏差 0、有退出事件。若我照此入账，"五段全长首跑三路回基线通过"就成了一条有凭据的结论。

三条破绽把它顶翻了：
1. `phaseAtExit: "enter"`——他从收束段（gather）退的，不可能是 enter；
2. `events` 只剩一条 `exit`——首跑那 380 秒的 `session_begin`／四次 `synth` 全不见了；
3. `phaseElapsedSecAtExit: null`——`requestExit` 里这一行**无条件赋值**，唯一能让它变 `null` 的路径是赋了个 `NaN`（`JSON.stringify(NaN)` → `null`），而 `NaN` 来自 `stage.phaseAt` 未初始化 ⇒ **这一跑根本没进过会话**。

实测页面年龄坐实：`performance.now()/1000 = 3.9`、`performance.getEntriesByType('navigation')[0].type = "back_forward"` ⇒ **该标签 4 秒前刚被重载**，首跑那份报告连同事件流一起没了；我取到的是重载后有人在 2D 里点了一下「退出」产生的**空跑报告**。

## 根因

**报告的生命周期被当成了它的可信度。**
`window.__stageReport` 只活在页面内存里：刷新、标签休眠、系统回收，任一发生即清零，**不留盘、不报错、也不留下"曾经有过"的痕迹**。而取证动作发生在跑完之后——中间隔着一段"页面随时可能被换掉"的窗口期，我却按"跑完了→报告还在"来排程序。

更深一层：**假的那份比真的那份好看**。真的那份在缺陷态下会报 `FAIL`（三路偏 9.57%），假的那份直接给 `PASS`。凡是"取到的结果比预期干净"，本身就该触发怀疑，而我当时没有这道反射。

## 对策（四条，可逐条核查）

1. **报告类产物须逐拍外取，不等收尾**：本窗实录器自 14:1x 起每 0.5 秒顺带抓一份 `__stageReport`（`r.report = window.__stageReport || null`），**退出即入库，重载也覆盖不掉**。代价只是每拍一次字符串序列化。
2. **取到报告先验"这份是哪一跑生的"**：同批读 `performance.now()`（页面年龄）与 `navigation[0].type`。页面年龄小于该跑时长 ⇒ 报告必非本跑所生，**直接作废重跑**，不做解释。
3. **判据字段须能区分"没发生"与"发生了但值为 0"**：`null`／`NaN`／`0` 三者必须可分辨。本例正是 `null`（NaN 落纸）暴露了真相——所以**修 bug 时不要把 NaN 兜成 0**，那会把唯一的线索抹掉。
4. **"比预期干净"须当触发器**：结果全绿而缺陷态本该报红时，先查取证链，再下结论。本轮若没查，D1／D2 两条真缺陷就会以"首跑 PASS"入档。

## 可红反例与正对照

- **反例（怎么知道本卡有效）**：一份报告里 `reason` 与 `phaseAtExit` 来自不同段、或事件流条数明显少于该跑应有的条数，而采集器照收＝红。检验动作＝**把报告的事件流条数与该跑实录里最后一条的条数对一遍**（本例实录 12 条 vs 报告 1 条，一比就穿）。
- **正对照（不是所有覆盖都是事故）**：同轮负向档取到的第一份是 `reason: system`、第二份是 `reason: button`——那是法师**先系统退、后又点了按钮**，两份都是真报告，`events` 条数逐份递增且都含完整段流。区分点＝**条数是否单调增长、页面年龄是否大于该跑时长**。别把"同一页多份报告"一律当污染。
