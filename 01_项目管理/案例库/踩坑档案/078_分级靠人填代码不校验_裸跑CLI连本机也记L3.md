# 坑 078：分级靠人填，代码不校验——裸跑 CLI 连本机也记 `L3_EGRESS`

## 现象（用户视角，原话）

- 2026-11-01 01:50，本窗实测：**不设** `WORKBENCH_LEVEL`，跑 `run_workbench.py health` 连本机假服务，日志行落
  `level=L3_EGRESS target=http://127.0.0.1:53166`；**设了** `WORKBENCH_LEVEL=L0_LOCAL` 才落本地级。
- 而 README `:96` 写的是：「日志同时带 `level=` 与 `target=`，**假服务跑出的行不会被误读成真实出网**」。
- 先发现者＝监督位 AI-025（2026-11-01 00:3x 抽验回件 §三，判 P3）；本窗复核复现后立案。

## 根因（三层）

1. **取值面**：`level` 直接从 `config.level` 取（`config.py:13` 默认 `L3_EGRESS`），代码没有任何判定。
2. **不可推断**：真实 `opencode serve` 也在回环，**host 无法区分真假服务** ⇒ 这项分级天生只能由调用方声明。
3. **文档把「可设」写成「不会」**：README 那句承诺的是结果，实际只保证能力——**默认值被当成了保证**。

## 解法（三选一或并用）

- (a) **口径改实**：写「默认 `L3_EGRESS`；本地假服务自测须显式设 `L0_LOCAL`，否则记账偏高（偏高不伪造低，方向安全）」。
- (b) **加显式开关**：`--local-fake`，与 `--show-directory` 同型，让「这是我故意标低的」有痕迹。
- (c) **不一致即提示**：`level` 与 `target` 矛盾时（回环却标 L3）打一行 stderr 提示，不阻断。

## 排障顺序（可复用）

见到「分级／审批人／环境／来源」这类**由调用方填**的字段，先问一句：**代码校验它吗**？不校验，就不许在文档里写成保证。

## 教训

一句话：**默认值不是保证，可配置不是已配置；分级字段若由人填，文档只能承诺「可设」，不能承诺「不会误标」。**
