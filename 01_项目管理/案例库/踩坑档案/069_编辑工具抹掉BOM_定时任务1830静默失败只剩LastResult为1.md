# 坑 069：编辑工具抹掉 BOM，定时任务 18:30 静默失败——Last Result=1，日志一行没写

> 〔取号留证〕同上，`069` 前缀零命中 ⇒ 顺延取 069。
> 发现日期：2026-10-21｜发现窗：DSH 承接窗 `fc2ce735`（**记的是我自己的错**）｜触发：`schtasks /query /v` 现查归档任务
> 类型：**编码面静默失效**（与坑 066「按 GBK 解码把 74 行算成 45」同族：都是编码不对而无人察觉）

## 现象

`DSH_C3_Archive_1830` 按时触发过一次（`Last Run Time 2026/10/21 18:30:00`），但 `Last Result: 1`、`c3_archive.log` 停在前一晚 12:07 的 DryRun 那行，**一条新日志都没有**。手工跑 `-DryRun` 才看到真相：脚本被按 GBK 读成乱码，`Unexpected token ')'`、`Missing closing ')'`——**PowerShell 解析阶段就死了，根本没进正文**。

## 根因

`.ps1` 含中文，但文件被写回时丢了 UTF-8 BOM；PowerShell 5.1 无 BOM 即按 ANSI（本机 GBK）解码，中文全成乱码，字符串引号被吞 ⇒ 语法错。

## 处置

按 UTF-8 **带 BOM** 重写该件，`-DryRun` 退码 0；同日晚 18:42 手工补跑，台账归档末行落 `7d39f64`、107 枚值守片在库 107。

## 教训

1. **定时任务的失败是静默的**：交互跑能看到红字，定时跑只剩一个 `Last Result`。所以成功判据必须写进任务本身——**退码 0 ＋ 日志新增行**，缺一即"未验"。
2. 编辑任何 `.ps1` 后，必须现查一次"能不能被 PowerShell 解析"（`-DryRun` 或 `[scriptblock]::Create`），不能靠"文件看着对"。
3. 含中文的脚本一律 UTF-8 带 BOM；这条已在 `AI-开工入口` 与 66 号坑反复出现，属**复发家族**。
