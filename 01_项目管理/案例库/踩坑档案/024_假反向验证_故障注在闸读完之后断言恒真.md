## 现象

给 `state_segmentation.py` 新增四栏读法（形状 1）时，其中一条纪律是「阿毗达摩／干支／占星三栏内容必须留空，
候法师定词汇映射，AI 不得自拟义理」。为守「没响过的闸不算闸」（教训 7.1），本窗给自测加了"反向验证"，原文如下：

```python
# 反向验证：把某一词汇栏偷偷填上自拟映射，本闸必须响
smuggled = json.loads(json.dumps(fake))
lr2 = lens_readings(smuggled)
lr2["lenses"]["ganzhi"]["text"] = "金旺克木"      # 模拟 AI 自拟义理
if lr2["lenses"]["ganzhi"].get("text") is None:
    fails.append("⑤ 反向验证失效：填值后仍读到空（断言不可信）")
```

**它跑得过。它永远跑得过。它什么也没验。**

## 根因

**故障注入的位置错了：注在了"闸读完之后"，而不是"闸读的那份数据上"。**

拆开看三处错：

1. `lr2` 是 `lens_readings()` **已经返回的结果**。往它上面写字段，改的是**一个局部字典**，
   那道真闸（`if ls[k].get("text") is not None: fails.append(...)`）**早已执行完毕**，根本不会再读 `lr2`。
2. 于是那句 `if lr2[...].get("text") is None` 检查的是**我上一行刚赋的值在不在**——
   等价于 `x = 1; assert x is not None`。**恒真断言**。
3. **恒真断言比没有断言更坏**：没有断言，读代码的人知道这里没验；
   有一条名字叫"反向验证"的恒真断言，读代码的人（包括三个月后的我）会认为**这道闸经过负对照**。
   ⇒ 它污染的不是这一次测试，是**后续所有对这套自测的信任**。

**为什么会写成这样**：本窗当时的思路是"我要证明如果有人偷填映射，会被抓到"，
但**手上没有一个能产生'被偷填的返回值'的入口**——`lens_readings()` 自己不会填。
于是就近取了"返回后改一改"这个动作，**用改数据的动作冒充了注入故障的动作**。
两者形状相似（都让某个字段变成非空），**差别只在于改完之后那份数据还会不会再被闸读到**。

## 解法（已落 `state_segmentation.py` 自测 ⑤）

**把断言抽成可重复调用的谓词，再拿"做过手脚的副本"去喂它，要求它必须报。**

```python
def _pend_fails(d):                    # ← 真闸的判据本体，抽出来
    out = []
    for k, _n, _w, verifiable in LENSES:
        col = d.get(k) or {}
        if verifiable:
            ...
            continue
        if col.get("status") != "pending": out.append(...)
        if col.get("text") is not None:    out.append(f"{k} 栏内容应留空候法师定映射（竟有值）")
        if col.get("boundary") != LENS_BOUNDARY: out.append(...)
    return out

fails += ["⑤ " + x for x in _pend_fails(ls)]        # 正对照：真结果必须干净

bad1 = json.loads(a)
bad1["lenses"]["ganzhi"]["text"] = "金旺克木"        # 负对照：同一把尺子量做过的假结果
if not _pend_fails(bad1["lenses"]):
    fails.append("⑤ 反向验证失效：词汇栏被填值却未报警")
```

**关键差别**：`_pend_fails` **在注入之后被调用**。假结果真的过了闸，闸真的报了 ⇒ 负对照成立。
同轮给"禁总分"那道递归扫描闸也配了同样的负对照（塞一个 `focus_score` 键，要求 `_scan` 必须命中）。

实测：`python state_segmentation.py` → `exit 0`，输出
`PASS: …（①双态分段+边界+确定性 / ②短数据弃权 / ③编辑距离 / ④字母表 / ⑤四栏读法含两道反向验证）`。
**若两道负对照任一不响，本次即为 FAIL**（该分支已在代码里，不是注释）。

## 教训（可复用）

1. **⭐反向验证的判据：故障必须注入在"闸还会再读一次"的位置。**
   一句话自检——**「我改完这份数据之后，那道闸还会读它吗？」** 答"不会"⇒ 这条反向验证是装饰品。
2. **恒真断言比缺断言更危险**，因为它伪造了"已验"这个事实。写断言时先问：**它有没有可能失败？**
   想不出失败场景的断言，删掉，别留着充数。
3. **把判据抽成函数，正负对照共用同一把尺子。** 若负对照用的是另一套判断逻辑，
   那你验的是"另一套逻辑能不能抓到"，不是"这道闸能不能抓到"——**同形不同体，照样是假验**。
4. **反向验证要在同一轮里跑出一次"它响了"的证据并留档**（本卡 §解法 末尾那句 PASS 输出即证据）。
   只在代码里写着"如果没响就 FAIL"而从未见过它响，仍属未验。
5. **承坑 023 §教训 6 的排障顺序，再往前加一层**：读数异常时，
   ⓪ **先怀疑"这道闸验过没有"**，① 再怀疑仪器，② 再怀疑数据，③ 最后才怀疑各窗纪律。
   本卡的教训是：⓪ 这一层以前不存在，因为大家默认"有自测＝验过"。
