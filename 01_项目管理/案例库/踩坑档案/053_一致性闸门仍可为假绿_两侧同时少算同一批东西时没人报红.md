# 坑 053：一致性闸门仍可为假绿——两侧同时少算同一批东西时，没人报红

> 建立：2026-10-14 21:2x（date 实取 21:24）｜编号先查后取：`踩坑档案/` 现读最大号 **052**（测 21:2x，`ls` 排序末件）
> 归属：**W3 当值窗本窗自咬**（非法师指出，由本窗装副尺时反证复现）
> 状态：待法师审定

## 现象（用户视角，原话）

法师 10-14 19:15 从 C3 那片里先看到一句：「**代裁落地面全部压在工作树未入库**」——他看到的时间点比我呈凭据早一轮。紧接着 20:0x 我销 P41／P42／P43 三条时，**同一类"没人报红"在页面上复现了一次**：

- 页头自报「现 0 条待裁」；
- 行首尺（`^## P数字＋空格`）也数到 0 条；
- **两侧一致 ⇒ 第十三门当场 `[OK]`**；
- 而活条区里还躺着**三段没有标题领着的正文**（P41—P43 的正文，标题被我的脚本摘走了）。

判据一字没错，页面是坏的。

## 根因（多个坑容易混为一谈）

1. **一致性检验的数学边界**：「A 侧 == B 侧」这类判据，只对**两侧独立数错**有抵抗力；对**两侧同时少算同一批东西**完全无感——因为我删掉的正是它们共同的计数单位（标题行）。这不是"判据写错"，是**判据选型决定了它看不见什么**。
2. **删除脚本的范围算窄了**：定位删除区间时用了「标题行 → 下一个空行」，而本仓待裁单的形制是「标题行／空行／**正文行**／空行」——正文在**第二个**非空行上，于是只删了标题。
3. **同型第二次**（同根＝整段替换或删除后不校验剩余内容）：14:4x 那次补丁脚本清掉整段活区、把 P37 抹了，靠 `git show HEAD:` 逐字取回。**同一个动作一天栽两次，说明缺的是"删完复读页面"这一步，不是"下次小心"。**

## 解法

- **加一把不同轴的尺**（法师 10-14 21:1x 裁 P46「要」）：副尺不数标题，**数段**——活条区以空行分成的每个段，段首若不是 `^## P数字␣`、又不是占位说明行 `^（`、且它前面没有标题段领着 ⇒ 判孤儿段并报告警。它与行首尺**用的不是同一个单位**（段 vs 标题行），所以"两侧同时少算标题"这一形落不进它的盲区。
- **删完必须逐行读活条区**，并把读到的段数写进己档一行（现势自约，未升为闸）。
- **变异测试要按字节还原**：跑完三次注入／删除，用 `sha256` 证内容恒定（不是只把 mtime 擦回去——那是坑 041 那一族）。

## 排障顺序（可复用）

1. 闸门报绿但账面看着不对 ⇒ **先怀疑检查面，别先怀疑数据**；
2. 把判据的**计数单位**写出来（这次是"标题行"），再问一句：**什么东西被删掉时，这个单位会跟着一起消失？** 会 ⇒ 该尺对该失效模式天生盲；
3. 造一个**该尺必须抓到**的样本喂进去（本窗实做＝塞一段无主正文、删一条标题留正文），抓不到 ⇒ 尺在空转；
4. 补一把**用不同单位**的尺（段 vs 标题行），⛔不要给原尺加"数到 0 就红"那类条件——那正是本窗 11:5x 私自加严犯过的错（判语 020）。

## 教训

- **"两侧一致"是必要不充分**：对账型闸门只能证明"两边数同一个对象"，**不能证明那个对象完整**。凡是"A==B 即绿"的判据，都要问一次「有没有一种坏法，让 A 和 B 同时坏成一样的数」。
- **闸门的检查面要与被检对象的形制同源**（承 判语 017「无检查点的规则不等于规则」的反面：有检查点但检查点与被检形状不同源，照样漏）。
- 本轮新落地的一条规矩可复用：**引用提交号须附命令原样输出、收方一律现查**（规约 §二.18 ⑤之一，P43 升全员规矩）——同族病是"上下文里的号看着比盘上更新"。
