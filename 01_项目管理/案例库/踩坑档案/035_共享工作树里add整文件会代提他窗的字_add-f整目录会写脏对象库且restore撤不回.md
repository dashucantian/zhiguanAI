## 现象

一小时内连踩两次，都是"看起来干净、实际已越界"：

**第一次：`git add .gitignore` 差点替别窗提交了三行。**
本窗要在 `.gitignore` 尾部加一段取证例外。加完 `git add .gitignore` → `git diff --cached` 显示 **20 行插入**。逐行读才发现：其中 **3 行不是本窗写的**，是 `6c7d4751`（W3｜图谱双轨）10-10 留在工作副本上、至今未提交的一行例外（`!05_产品与开发/架构可视化/validate-anchors.mjs`）及其注。`git add <单个文件>` 的粒度是**整个文件**，不是"我改的那几行"——**共享工作树里"这个文件"从来不属于一个窗**。发现于提交前，未成事实。

**第二次：撤了暂存，对象库却已经胖了 490MB。**
为避开上面那条，本窗把 `.gitignore` 撤出暂存、改用 `git add -f output/真机_1012`（整目录）想让证据件绕过 ignore 规则——**该目录里压着 100 帧真机屏摄共 519MB**。`git add` 当场把全部 blob 写进 `.git/objects`。发现后 `git restore --staged` 全撤、重新逐件列名 14 件提交，提交内容确实干净（`git show --stat`＝14 files／1.9MB）。**但 `.git` 从 33MB 涨到 526MB**——`restore --staged` 只回退索引，**不回收已写入的对象**（它们成了 unreachable loose objects）。

**第三次（清理动作自己又生一份）**：为诊断"到底哪些是游离对象"跑了 `git fsck --lost-found`——这个旗标会把**每个游离 blob 落地成文件**写进 `.git/lost-found/`，于是又凭空多出 **522MB**。最终 `git prune --expire=now` ＋ 删 `.git/lost-found` 才回到 33MB。

## 根因

**三条同根：把"可逆的表象"当成"可逆的操作"。**

1. `git add <file>` 在**单窗仓库**里等价于"提我这处改动"，在**共享工作树**里不等价——文件的未提交差异可能来自任何一窗，而 `add` 不区分作者。git 也没有"只 add 我这几行"的原生命令。
2. `git restore --staged` 的语义是**索引回退**，不是"撤销 add 的全部副作用"。对象写入是 add 的另一条独立后果，**没有任何提示**。
3. `git fsck --lost-found` 是**修复辅助**，不是只读诊断；只读诊断该用不带 `--lost-found` 的 `git fsck` 或 `git cat-file --batch-check`。

放大器：**四窗共用一个 index**，所以"提交前看一眼 `git diff --cached`"不是好习惯而是**必需闸**——本窗第一次那下如果直接 commit，就把别窗一行未署名的字带进了本窗的提交，且**归属永远查不清**（这正是 KZ-1008-W3a 那笔 `.gitignore` 归属误判的成因形状）。

## 对策（四条，可逐条核查）

1. **共享工作树里 `add` 一律逐件列名，禁目录级、禁 `-A`／`.`**；`-f` 只准配具体文件名（本窗第二次就是栽在 `-f` ＋ 目录）。
2. **提交前必跑 `git diff --cached --name-only` ＋对**每个 M 文件**跑 `git diff --cached <file>` 逐行读归属**——不是抽查。件数核对钩子只数件数，**不辨归属**。
3. **误 add 之后，除 `restore --staged` 外必须补一步对象回收**：`git count-objects -vH` 看 `size`（loose）是否异常，必要时 `git prune --expire=now`。**判据是 `.git` 体积回到操作前，不是"提交内容干净"**。
4. **诊断命令先查副作用再跑**：`git fsck` 只读，`--lost-found` 会写盘（本例 522MB）。同类还有 `git gc`（会重打包共享对象库）。**四窗在场时，任何"顺手清理"都须先声明**。

## 可红反例与正对照

- **反例（怎么知道本卡有效）**：一次提交里出现**别窗字面**（`git show <sha>` 里某行与本窗任务无关且注记着别的窗号／日期）＝红。检验动作＝提交后 `git show --format="" --stat` 对件数，**再 `git show` 通读一遍 diff**；本窗若在第 2 步没逐行读，那 3 行就在库里了。
- **正对照（不是所有共享文件都不能提）**：同轮 `board_config.py` 也是共享文件，但 `git diff --cached` 逐行读后确认 **11 行全属本窗**（一行登记＋注记），且改前 mtime＝10-11 23:24（13 小时无他窗写入）⇒ 可提。**"共享文件"不是禁提理由，"没读过归属"才是**。
