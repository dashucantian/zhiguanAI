# 坑 075：把 v2 线的发行号当 v1 线的落后证据——同一产品两条分发线，版本号不同源

## 现象（用户视角，原话）

- 阶段一官方资料盘点把 OpenCode「发行参考」写成 `2.2.0`（2026-10-27），而试点实读本机为 `1.19.5`；首日记录据此判「本机落后 2.2.0」。

## 根因（多个坑容易混为一谈）

1. 同一产品存在**两条分发线**：v1＝npm 包 `opencode-ai`（本机安装的就是这条）；v2＝npm 包 `@opencode/cli`（官方文档称 Windows 仅独立二进制、**不支持包管理器**）。
2. 盘点只取「最新 changelog 号」当基准，**未绑定本机实际安装的包名／分发线**。
3. 版本号跨线比较——看起来像落后，实为不同产品形态（v2 文档页未出现 `serve`）。

## 解法

- 版本比对先绑「包名＋分发线」：`opencode --version` 与 `npm view <包名> version` 同源比。
- 结论句写清「本机 X（v1 线）／官方 Y（v2 线）」，不写「落后」。
- 跨线升级须另做兼容核验（v2 的 `serve` 是否存在、API 是否同构，均未验）。

## 排障顺序（可复用）

先问「我要比的是哪条线」，再取同线两侧的号；跨线一律不当基准。

## 教训

一句话：**版本号只有绑上包名与分发线才是可比数；跨线比大小＝拿两条产品的号互当基准。**
