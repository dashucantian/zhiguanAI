# 坑 004：凭假设推断算力，把统一内存机误判成"要买显卡"

## 现象

2026-09-04 的调研报告里，本地大模型部署门槛被写成"需要 24GB 显存的 RTX 3090/4090"，并据此把 **GPU 采购列为隐性成本**，暗示法师可能要花钱买显卡。

09-05 实测本机配置后，这个假设**整个不成立**。

## 根因（AI 侧的方法错误，不是技术难题）

报告沿用了"本地大模型 = 需要大显存 N 卡"的通用印象，**没有实测本机**就下了结论。实际本机是：

| 项目 | 实况 |
|------|------|
| 处理器 | AMD Ryzen AI MAX+ 395（Strix Halo，16 核 32 线程） |
| 机型 | ASUS ROG Flow Z13 |
| 内存 | 约 64GB LPDDR5X **统一内存**（CPU 与 GPU 共享同一内存池） |
| 显卡 | Radeon 8060S 核显，**无 NVIDIA 独显** |

统一内存架构下根本不存在"显存不够要卸载到内存"的问题，GPU 可直接访问全部权重——**不需要买任何显卡**。

更深的教训是：这台机器的真正瓶颈不是显存容量，而是**内存带宽**（约 215–256 GB/s）。带宽受限机器上，决定推理速度的是每生成一个字真正参与计算的**激活参数量**，而非总参数量。所以 MoE 架构（如 Qwen3.6-35B-A3B，激活 3B）在这台机器上反而比 Dense 的 Qwen3.8-27B 快 2–6 倍——这个反直觉结论，只有实测本机、理解其架构特性才能得出。

## 解法

1. 任何"本机能不能跑 X"的判断，**先实测本机配置**再说：`Get-CimInstance Win32_Processor / Win32_ComputerSystem / Win32_VideoController`
2. 区分架构类型：独显机看显存容量，统一内存机（Apple Silicon、AMD Strix Halo）看内存总量与带宽
3. 推理速度找**同平台实测数据**（如 Strix Halo 的 llama.cpp benchmark），不要套用 N 卡数据

## 排障顺序（可复用）

涉及"本机能否跑某模型"时：

1. 先实测本机 CPU/GPU/内存/架构类型（独显还是统一内存）
2. 找**同架构平台**的实测速度数据，而非泛泛的"官方推荐配置"
3. 再判断模型量化后体积能否放进可用内存
4. 最后才给结论

## 教训

**不要凭通用印象推断特定机器的能力。** "本地大模型要大显存 N 卡"是独显时代的经验，套到统一内存机上就全错。一次没实测的假设，差点让法师白花钱买显卡、还差点选错模型架构。凡是涉及"本机能不能跑"，实测永远优先于推断——这是 AI 助理最该守的纪律，因为它最容易拿训练数据里的通用印象冒充对本机的判断。

## English Summary

**Symptom:** A 2026-09-04 research report stated local LLM deployment "requires a 24GB VRAM RTX 3090/4090" and listed GPU purchase as a hidden cost. After measuring the actual machine on 09-05, the entire premise collapsed.

**Root cause (a methodological error by the AI, not a technical difficulty):** The report applied the generic impression "local LLM = big NVIDIA VRAM" **without measuring this machine**. Reality: AMD Ryzen AI MAX+ 395 (Strix Halo), ~64GB LPDDR5X **unified memory**, Radeon 8060S iGPU, **no NVIDIA GPU**. On unified memory there is no "VRAM overflow to system RAM" problem at all—the GPU accesses all weights directly. **No GPU purchase needed.**

Deeper lesson: the real bottleneck is **memory bandwidth** (~215–256 GB/s), not capacity. On bandwidth-limited machines, speed is set by **activated parameters per token**, which is why MoE models run 2–6x faster than larger Dense models here—a counterintuitive result only reachable by measuring this machine and understanding its architecture.

**Solution / reusable order:**
1. For any "can this machine run X" question, measure first: `Get-CimInstance Win32_Processor / Win32_ComputerSystem / Win32_VideoController`
2. Distinguish architectures: discrete-GPU boxes → VRAM capacity; unified memory (Apple Silicon, Strix Halo) → total RAM and bandwidth
3. Seek benchmark data from the **same platform**, never transplant NVIDIA numbers
4. Only then conclude

**Lesson:** Never infer a specific machine's capability from generic impressions. An unmeasured assumption nearly caused a pointless GPU purchase and a wrong model-architecture choice. For AI assistants: measuring always beats assuming—generic training-data impressions must never masquerade as judgments about the user's actual machine.
