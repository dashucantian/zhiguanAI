# 坑 076：件内署名齐 ≠ 提交层归因齐——提交落到中性占位 `zhiguanAI-agent`

## 现象（用户视角，原话）

- 2026-10-31 21:14，Qoder 窗 `c73afab0` 提交三项交付（`5b14c1e`）。三件**内文**的 trailer 六字段齐全（Author-Role／Session／Window／Model／Verified-by 都在），但 `git show` 显示 **author＝committer＝`zhiguanAI-agent`**，且提交正文**无任何 trailer**。

## 根因（多个坑容易混为一谈）

1. 提交时未显式 `-c user.name='<身份>'`，git 落到仓库占位身份——**规约设计上这是"身份待查"的兜底，不是"无身份"的通行证**。
2. 件内 trailer 与提交 trailer **是两个层面**：前者是文书自述，后者是 git 层的归因证据；只写前者＝「件里说了我是谁」，git 里查不出来。
3. 「件内六字段齐」被当成「归因齐」——盘上证据链在提交层断了。

## 解法

- 提交前：`-c user.name='Qoder-c73afab0'`（或对应身份）＋提交正文带六字段 trailer。
- 已发生：**不 amend**，出前向补正记录（记明该笔归属、依据＝件内署名＋时刻＋授权函），并函告本人后续照办。
- 复核面：复点他窗交付时，**`--format='%an %cn'` 与 `%B` 一并看**，不只看 `--name-only`。

## 排障顺序（可复用）

看一笔提交：先看 `--name-only`（卷没卷他窗件）→ 再看 author／committer（身份对不对）→ 再看 `%B`（trailer 全不全）。三步缺一，就还没验完。

## 教训

一句话：**件里署名是自述，git 里署名才是证据；提交落到占位身份＝归因断链，得前向补正，不能靠"我在文件里写了我谁"补上。**
