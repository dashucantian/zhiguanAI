# 坑 034：`/json` 列表顺序不等于前台标签，`Page.bringToFront` 也不切标签——按"第一个命中"选目标，选中了看不见的那个

## 现象

真机浏览器（PICO 上的 WebLayer，Chrome/125）同时挂着 6–7 个标签。要把目标页切到前台，试了三条常规路，**三条都不成立**：

| 试法 | 预期 | 实取 |
|---|---|---|
| 取 `/json` 列表**第一个** `type:"page"` 当前台 | 首行＝前台 | 13:56 首行是 `…/mandala?stage=1`，而屏摄显示前台是**驾驶舱** `localhost:8777/` |
| `Page.bringToFront`（对目标 target 发） | 该标签切到前台 | 13:0x 对 `mandala?stage=1` 发，rc 空返回＝"成功"；屏摄却是 `…/vr`——**切了别的标签** |
| `am start -a VIEW -d <url>` | 拉起该 URL 并置前 | 13:5x 发正向档地址，标签**建了**，前台仍停在驾驶舱；再发一次（14:0x）连标签都没新建 |

真正有效的只有一条笨办法：**先确认哪个 target 的文档是活的（`document.body !== null`），对它 `Page.navigate`**——把前台那一格的内容直接换成我要的页面。以及把多余的重复标签 `navigate` 到 `about:blank` 停掉，保证子串唯一命中。

## 根因

**把 CDP 的"目标列表"当成了浏览器的"标签条"。**
`/json` 是**调试目标的枚举**，其顺序由内核实现决定（随 attach 历史变化），与用户看到的标签顺序、与哪个在前台**都没有约定关系**。`Page.bringToFront` 的语义在标准里本就弱（"best-effort 激活该 target 所属页"），在多标签＋VR 合成器的场景下它只做到了"把浏览器窗口带起来"，没做到"换标签"。

放大器：**真机上没有可读的前台标签判据**——`document.visibilityState` 在 VR 合成器里对后台标签也返回 `visible`（10-11 已实测过这条），所以连"我读到的是不是前台"都没法从页面内部证明。

## 对策（三条，可逐条核查）

1. **凡"切前台"的断言，须以画面通道为唯一凭据**：发完操作立刻 `adb exec-out screencap` 看地址栏／徽标，**不看 CDP 返回码**。`bringToFront` 返回 `{}` 只说明"命令被接收"，不说明"标签被切换"。
2. **导航只作用于"文档活着的那个 target"**：判据＝`document.body !== null` ＋ `performance.getEntriesByType('resource').length > 0`。列表顺序、URL 匹配都**不能**用来选前台（本窗两次据此选错）。
3. **重复同名标签必须先归一再录**：`about:blank` 停掉多余项，让 URL 子串唯一命中。**归一动作要写进实录前言**，否则下一轮接手的人仍会撞上同一个歧义。

## 可红反例与正对照

- **反例（怎么知道本卡有效）**：任何"我已把页面切到前台"的表述，若凭据只有 CDP 返回码或列表顺序＝红。检验动作＝**同轮附一张屏摄**，本窗就是靠屏摄才发现 `bringToFront` 切到了 `/vr`。
- **正对照（不是所有场景都要屏摄）**：桌面无头 Edge 的闸（`vr_gates/verify_mandala_stage.py`）单标签、单实例，`/json` 只有一个 page，顺序歧义不存在——那边沿用"取第一个"是安全的。**本卡只适用于多标签真机**。别把这条推广回去给无头闸加负担。
