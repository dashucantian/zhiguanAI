## 〇、设计边界（先说清四条）

1. **义理全留白候 N3**：D0–D4 深度语义、会话级终标签判据、「安静休息」是否独立级、D4 境界名、入定门槛（D2 还是 D3）——全部属《入定状态标注规范 V1 初稿》§七禅师审读会原六问，**本稿不重复开卷、不定任何语义，只留槽位**（`label_vocab_version` 字段，规范冻结后填）。
2. **不新建事件体系**：三机器源已挂在既有契约事件流／manifest 上（`console_server.py:1240` 既有设计决定「事件型别复用 experience，不新建事件体系」）。本索引是**组织层**，不是新数据层——循项目原则「证据不复制，证据只组织」。
3. **指针不复制**：索引每一条目只存**指针＋provenance**，绝不复制证据本体；读数永远回源。
4. **硬约束承接**：数据字典 V1.2 §4——「`05_annotation` 结构待标注字典定义……在对应版本发布前，这些目录只允许存放人工文档，不允许存放未定义结构的数据文件」；总原则「先升字典版本（V1.2→V1.3），再落数据」。**因此任何物化落盘案（§三乙）必须以字典升版为前置**，本稿不绕开。

### 1.3 如实自曝两处现状缺口（本设计顺带暴露）

1. **来源版本号普遍缺失**：`derive_zx_phase` 无算法版本标记；事件流仅带 `CONTRACT_VERSION`。schema 要求每条目必带 `source_version`，现有源补版本属施工面（候 N10/后续批），过渡期如实填「未版本化＋函数名」。
2. **登记表 `post_state` 是摘要不是原值**：原值在 npz meta；索引指针必须指回原值落点，摘要列只作快览（与「指针不复制」同向）。

## 二、共同索引 schema 草案（annotation_index）

### 2.1 设计原则

① **指针不复制**（只存指针＋provenance）；② **来源保留**（多源并排不合并，分歧全保留——循标注规范基本原则 3/4）；③ **效度显式**（每条目必带 `validity_class`，禁裸数——循 FE「未经校准」先例与判语 011「无链接权威声称降档」）；④ **版本随行**（每条目必带 `source_version`）。

### 2.2 条目 schema

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `ref_type` | enum | 是 | `event`（事件流行）／`manifest`／`meta`（npz meta 键）／`file`（02_raw 内文件节）／`registry`（登记表列）／`annotation_doc`（05 层人写文档）／`qc_ref`（03_qc 摘要指针，对应 quality_ref） |
| `pointer` | string | 是 | 精确指针：事件流＝`session_events.jsonl@<ts>\|<kind>`（行号冗余可附）；meta＝`eeg_raw.npz#meta.zx_phase`；manifest＝`session_manifest.json#labels`；registry＝`session_registry.csv#<Zen-ID>#post_state`；文件＝`session_note.txt#events`；标注文档＝`annotation_master_A.md#判定` |
| `ts` | ISO 8601 | 是 | **证据时刻**（非索引生成时刻；补记事件用原时刻，循 `make_event` 既有语义） |
| `actor` | enum | 是 | `subject`／`operator`／`vr`／`device`／`pipeline`（运行派生）／`ai`／`master_A`／`master_B`／`master_C`／`arbitrator`——循标注规范角色系 |
| `kind` | string | 是 | 沿既有事件 kind 词汇（`vr_interaction`／`self_report`／`marker`／`qc_done`／`zx_phase`）＋人层 kind（`self_assessment`／`operator_note`／`master_judgment`／`arbitration`）——**不新造词汇系** |
| `source_version` | string | 是 | 来源版本：事件流＝CONTRACT_VERSION；人层＝标注规范版号；qc 相关＝阈值版本（现行 20260920）；派生算法＝算法版本（现状缺→如实填「未版本化+derive_zx_phase」）；字典面＝V1.2 |
| `validity_class` | enum | 是 | 六档见 §2.3 |
| `note` | string | 否 | 自由备注（如「补交于会话结束 12 分钟后」） |

### 2.3 效度六档（validity_class）

| 档 | 适用 | 权威序 |
|---|---|---|
| `专业判定（权威）` | 导师/仲裁人层标注 | 终标签唯一权威＝仲裁层；分歧层并排保留 |
| `操作员观察` | session_note、operator marker | 事实记录层 |
| `主观自评` | self_report 全部落点 | 主观层，与专业判定**不同维**，不作真值比较 |
| `设备事件·客观可查` | vr_interaction、设备侧 marker 时刻 | 客观行为层 |
| `运行派生·未经校准` | zx_phase 及未来任何算法派生标签 | 只作参考证据呈现，永不进判定链（循「观察指标不得进判定链」既有裁定） |
| `AI假设·未采信` | AI 辅助提示/草稿 | 标注规范 §四.3 口径；禁作为任何一层标注值 |

> 判定链语义（哪档可作什么用）属义理/规则面，候 N3 与规约层，本稿只定**标注分类**不定**使用规则**。

### 2.4 一会话一索引的组织形

- 索引覆盖该 `Zen-ID` 会话全部已知标注相关证据（机器三源＋旁证＋人层件＋qc 摘要指针），条目按 `ts` 排序、同刻按 `actor`。
- 人层六件套尚未产生时（现况），索引仅含机器侧条目＋「人层待建」占位说明——**不虚构人层数据**。

## 三、落库两案（候裁；两案 schema 同一，差别只在物化与否）

### 甲案·读取时聚合视图（本窗倾向）

- **不落任何新文件**。装配器按 §二 schema 现场装配（只读遍历：02_raw 事件流＋manifest＋meta＋登记表＋05 层文档＋03_qc），设计位＝驾驶舱标注卡后端聚合（循 `_dashboard_data` 纯读聚合先例 `:2884-2986`）。
- 数据面建议**并入既有 `GET /api/dashboard` 聚合**（零新端点、契约矩阵零变化）；如后续需独立端点再入契约矩阵（P1-2 面板设计批定）。
- 优点：字典不动、零写授权（N10 不阻塞）、永远现查零漂移、标注卡从「目录计数占位」升级为真读数。缺点：每次现算（单会话事件量 ≤数百条，成本可忽略）；跨窗复用需收敛为共享装配模块（施工面）。

### 乙案·物化索引文件

- 落 `05_annotation/<sid>/annotation_index.json`。**前置三件缺一不可**：① 数据字典升 V1.3（定义本 schema，循「先升字典再落数据」总原则）；② N10 写授权；③ 生成步挂 `ingest_session.py`（02_raw 唯一合法入口族内）或独立批处理，且**记录生成时刻与所读源版本**（防双源漂移）。
- 优点：可离线直查、外部工具免装配。缺点：与活数据漂移风险、写授权成本、字典升版流程成本。
- **甲→乙只是物化与否；乙候 N10，不阻塞甲。**

## 四、与标注规范 V1 初稿的衔接（义理槽位，不填语义）

1. 人层六件套各自成为索引条目：`actor` 对应 `subject/operator/master_A/master_B/arbitrator`；`validity_class=专业判定（权威）`（AI 辅助件除外）；`source_version=标注规范版号`。
2. AI 辅助条目一律 `validity_class=AI假设·未采信`。
3. 分歧展示：索引**只并排不合并**；「一致→仲裁确认／不一致→全保留」的流程语义归规范本体，索引只忠实登记各层存在。
4. `label_vocab_version` 槽位：规范冻结（禅师审定）后填；在此之前索引不携带任何 D0–D4 语义解释。
5. quality_ref：索引以 `qc_ref` 条目指向 `03_quality_control/<sid>/qc.json`，质量状态独立于状态判定（规范 §四流程末位原则不变）。

## 五、乙口径：experiments CSV 特征日志入厂口径（法师 §八.2 指定随 P1-1 设计，**另候裁**）

### 5.1 现状实测

- `experiments/` 177 文件；闭环实验每跑写三表（`closedloop_experiment.py:364-366`）：`{ts}_{tag}_features.csv`（时间偏移/时间/阶段/Delta_dB/Theta_dB…）、`_decisions.csv`（时间偏移/时间/Alpha_dB/基线dB/超基线dB…）、`_events.csv`（时间偏移/时间/事件）；tag 实样 `real-openloop`／`real-closedloop`／`smoke`／`cfgtest`。
- 法师 10-04 已批**甲案**：experiments/ 原地保留＝「历史产物层＋闭环实验活写入目录」，零移动零删除（接线图 v0.1 §七）。

### 5.2 口径两案（候裁）

- **甲案·指针登记＋版本化重算（本窗倾向）**：CSV 本体**不入厂**（留 experiments/ 原地）；仅在索引/登记面登记指针（exp 标识→三表路径＋tag＋生成时刻）。需要特征入 `06_features` 时，由 **P1-3 特征批处理以版本化算法从 02_raw 原始信号重算**（CSV 不当计算真源——循「不复活 `_extract_report_metrics` 正则真源」同一逻辑；历史 CSV 作旁证/对照留证，对不上时追因）。
  - 优点：零移动零复制（与红线 7 同向）；特征口径单一（版本化算法真源）；06_features 不被历史格式污染。
  - 缺点：历史实验值与未来特征值无逐值对应保证（以重算为准）。
- **乙案·原样归档**：三表按字典定义 schema 原样入 `06_features/raw_experiments/`（前置＝字典升版＋N10）。优点：历史可直查。缺点：**两套特征口径并存**（CSV 旧口径 vs 批处理新口径），与「特征真源唯一」方向相逆；且 06/07 现为全空白带（接线图 §四），首块入厂物料即带历史包袱。
- 候裁问句（一句可答）：**experiments CSV 按甲（指针＋重算）还是乙（原样归档）？**
