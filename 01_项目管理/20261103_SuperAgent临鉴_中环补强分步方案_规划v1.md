## 二、它真正给我们的东西：一条结构，不是一堆功能

剥掉宣传与文章里的未实现部分，能站住的是这条链路：

```
事件（有人提请求）
  → 变成可追踪的 work item（不是口头活）
  → 在独立的会话/目录里执行（不与他人工作树混）
  → 结果回到原讨论串（不是另起一件丢给协调位）
  → 且只在被请求或团队规则允许时才动手
```

**注意最后半句**：它自己也写着「只在被请求或规则允许时行动」。所谓「自主」是有闸的自主，不是放任。

对照我们现势，这条链路的四段：

| 段 | 我们的现势 | 缺口 |
|---|---|---|
| 事件→任务 | 靠我手工把来函/法师一句话转成 TASK 行 | **触发来源没有机器可查的字段**（哪句话、哪封函、哪次巡检来的） |
| 可追踪 | 六态状态机 + 任务登记单一真值 | 有了，但**没有「最近活动时刻」**，安静与失联分不出 |
| 隔离执行 | **全部窗共用一个 `D:\Project\zhiguanAI`** | **最大的洞**：「一文件一写者」靠纪律，不靠机制 |
| 回原处交付 | 信箱回件（六段格式） | 半有：回到信箱，不是回到原触发处；**长任务断点无恢复点** |

## 三、三环视角：只在中环有增量

| 环 | 它能不能帮上 | 说明 |
|---|---|---|
| 内环（个人练习-记录-复盘） | **无关** | 它不碰人的修行记录 |
| **中环（多角色协作-交接-验收）** | **有真增量** | 正是我们自诊的「从真实需求到可验收任务还靠人工拼」 |
| 外环（社区复刻-回灌） | **可借打包思路** | 它的「bundle」形态值得学：我们的模板包也可以打成一个可安装件，而不是一堆散文档 |

⇒ 所以这次建构**不铺开**，只做中环四段；外环的打包形态记进待办，等 12.8 营之后再说。

## 五、分步路径（四步，每步带判据与证伪句）

### 第 1 步·四字段先行（本周，零风险，约 0.5 天）

**做什么**：任务登记每条加两项——**触发来源**（哪封函/哪句话/哪次巡检＋时刻）与**最近活动时刻**。

**为什么先做这个**：它最便宜，且是后三步的地基。没有触发来源，「隔离执行」和「恢复点」都无从挂靠。

**判据**：抽 10 条新任务，每条都能从 TASK ID 回到原始触发材料。
**证伪句**：任一条只能答「法师说的」但指不出哪句/哪封，即不成立。

### 第 2 步·隔离执行实验（1–2 周，需一次授权）

**做什么**：让 Qoder 在一类任务上改用**独立工作树**（`git worktree` 或独立 clone 到 `_analysis_tmp`），跑完合回主树。

**为什么这是最大的洞**：现在六窗共用一个工作树，「一文件一写者」全靠自觉。隔离之后，**碰撞从纪律问题变成机制问题**。

**判据**：同一批 3 个任务在隔离树执行，主树零冲突、提交归因逐笔可查（author/committer/`%B` 三层）。
**证伪句**：若主树仍出现他人未提交改动被覆盖，或提交身份仍落 `zhiguanAI-agent` 占位，即不成立（坑 076 同型）。
**需要您一句**：允许建 worktree（这是本机 git 操作，不出网）。

### 第 3 步·运行轨迹与恢复点（2–3 周）

**做什么**：长任务回件加「五项」：输入摘要／独立执行目录或会话／产物／复核者／**最后可复核步骤与失败点**。

**判据**：模拟一次中断，接手者**只凭回件**能恢复到最后一个可复核步骤。
**证伪句**：若接手仍需问执行者关键状态，即不成立。

### 第 4 步·事件入口（候条件，暂不做）

**做什么**：把「来函/巡检发现」变成自动开任务。

**为什么押后**：这一步才真碰到它的「主动监听」，也就真碰到我们的红线——需要您逐项授权出网、凭据白名单、单仓库范围、外发规则、独立监督。**在 1—3 步没跑稳之前做这一步，是给自己造事故面。**

**判据（若将来做）**：自动开出的任务必须带触发原文与时刻，且**不得自动提交/自动回帖**。
**证伪句**：出现「无触发原文的任务」或「机器直接推了代码」，即不成立。
