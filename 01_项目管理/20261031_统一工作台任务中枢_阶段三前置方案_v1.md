## 一、试点带回的两条硬事实

1. **serve 默认无鉴权**：`serve --help` 无 `--auth` 选项；启动即打印 `Warning: OPENCODE_SERVER_PASSWORD is not set; server is unsecured.`；无凭据 `/global/health`、`/session` 均返 200 ⇒ serve 一起即对回环内任意进程开放。
2. **外连未验**：两次运行均现远端 443 连接（`104.20.32.17`／`172.66.173.149`，Cloudflare 段），性质未验；当时按放行留证未再拦。

## 二、鉴权方案三选一（候您点）

| 案 | 做法 | 代价／风险 |
|---|---|---|
| **甲（建议）** | 设 `OPENCODE_SERVER_PASSWORD` 环境变量起服务（启动日志自述其为鉴权开关），验「无凭据 401／有凭据 200」 | 最小改动、可证伪；若该变量实际不生效，当场退乙 |
| 乙 | 本机起只绑回环的反代加 Basic Auth，serve 只让反代连 | 多一个程序件与常驻面，较重 |
| 丙 | 不接 serve，只用 CLI 单次调用 | 无长驻监听面但能力最窄（无会话流／无 abort 语义） |

建议＝**甲**；验不过退乙；丙留作最后手段。

## 三、外连性质核查（须另字）

- 约束：核查须解析／探测远端地址＝**出网动作**，按项目口径须法师字；且只允许 DNS／PTR 反查、whois 段属、TLS 证书主体读取——**不发项目数据、不登录、不下载**。
- **替代路径（不出网，建议先走）**：读 OpenCode 官方文档／隐私条款说明其联网用途，按「文档支持」口径记录并标未验；不足再申请一次最小出网探测。

## 四、批前不变量（接线必守）

- 工作台不把 serve 直接暴露给非本机进程；**鉴权＋回环绑定双条件缺一不接**。
- 自动 orchestration 前须有「停止／取消」实测判据（试点已示 CLI 侧无 `--auth`，停靠进程终止）。
- 台账仍以 `任务登记.md` 为 TASK 正源；OpenCode 会话记录只作执行证据，不另立任务簿。
