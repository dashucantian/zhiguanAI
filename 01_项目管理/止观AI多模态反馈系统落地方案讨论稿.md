## 一、整体对齐：我理解的你的意图

你要的不是产品，是**自己先用起来**：戴上 Pico，眼前有随自己心念变化的景象，耳边有声音，背后有大模型懂你当下的状态并给出引导，脑电把这一切串成闭环。约束条件只有两条——**最低成本**、**最快速度**。

这个理解如果准确，那么昨天那份报告的技术路线需要三处纠偏。这三处纠偏不是为了修正错误，而是因为它们直接决定了你多花多少钱、多等多久。

### 纠偏一：本机不是 NVIDIA 独显机，是 AMD 统一内存机——而且这个事实对你有利

昨天报告假设本地大模型需要"24GB 显存的 RTX 3090/4090"，并据此把 GPU 采购列为隐性成本。实测本机配置：

| 项目 | 实况 |
|------|------|
| 处理器 | AMD Ryzen AI MAX+ 395（Strix Halo，16 核 32 线程） |
| 机型 | ASUS ROG Flow Z13 |
| 内存 | 约 64GB LPDDR5X 统一内存（CPU 与 GPU 共享同一内存池） |
| 显卡 | Radeon 8060S 核显（RDNA 3.5，40 CU），**无 NVIDIA 独显** |

**不需要买显卡。** 统一内存架构下不存在"显存不够要卸载到内存"的问题，GPU 可直接访问全部权重。AMD 支持可变显存技术，128GB 机型最高可分配 96GB 给 GPU；本机 64GB，可分配上限需在 BIOS 中确认（列为待实测项）。

但这里有一个**比省钱更重要的发现**。这台机器的真正瓶颈是内存带宽（约 215–256 GB/s），而带宽受限的机器上，决定推理速度的不是总参数量，而是**每生成一个字真正参与计算的激活参数量**。同一平台的实测数据对比：

| 模型 | 架构 | 量化 | 速度 |
|------|------|------|------|
| Qwen3.8-27B | Dense（稠密） | Q4_K_M | 约 11.7 tok/s，开 MTP 推测解码后 21.2 tok/s |
| Qwen3.8-27B | Dense | UD-Q4_K_XL | 基线 11.8 tok/s，开 MTP 峰值 31.8 tok/s |
| Qwen3.8-27B | Dense | AMD 官方测试 | 最高 24.5 tok/s |
| **Qwen3.6-35B-A3B** | **MoE（混合专家）** | — | **基线 49.5 tok/s，开 MTP 后 69.4 tok/s** |

**参数量更大的 MoE 模型，反而快了 2–6 倍。** 来源：[AMD 官方博客](https://www.amd.com/zh-cn/blogs/2026/run-qwen-3-8-27b-on-amd-ryzen-ai-max-and-radeon-graphics-cards-day-0.html)、[Strix Halo 平台 llama.cpp 性能实测](https://kyuz0.github.io/amd-strix-halo-toolboxes/)

**建议**：把当前部署的 Qwen3.8-27B（Dense）换成 MoE 架构模型（如 Qwen3.6-35B-A3B），并开启 MTP 推测解码。这一项改动不花一分钱，但能让引导语的生成速度从"读得比你打字慢"变成"流畅对话"——直接决定你用起来的主观感受。

### 纠偏二：视觉反馈**不能**用生成式大模型实时渲染——这是整个方案最关键的架构判断

你问的 World Labs 世界模型、视频生成模型能不能用得上，答案是同一个：**做实时视觉反馈用不上，做离线素材生产能用**。

原因是物理性的。VR 头显要求帧级响应，一帧 16.7 毫秒，脑电驱动的视觉变化延迟须控制在 20 毫秒内，否则画面跟不上心念，反馈就失去意义。而生成式模型的延迟量级完全不同：视频生成是秒级到分钟级，3D 场景生成是分钟级。两者差三到五个数量级，没有任何优化能弥合。

正确的架构是**离线生成资产、在线参数化驱动**：

- **离线**（不限时）：用生成式 3D 模型产出禅修场景资产（山、水、光、佛像、曼陀罗），导入 Unity 成为静态场景
- **在线**（毫秒级）：脑电频段功率映射为场景的**参数**——光照强度、粒子密度、水面波动幅度、雾气浓度、色温、动画速度——由 Unity Shader 实时计算

这条路的好处是：视觉表现力可以做得极其丰富（Shader 能表现的渐变、粒子、体积光远超简单色块），但计算量极小，24GB 级别的核显完全扛得住；而且**大模型故障时视觉反馈不受影响**，系统能优雅降级。

**而且你已经有起点了。** 项目目录 [05_产品与开发/VR素材/3D模型](<C:\Users\tiand\OneDrive\zhiguanAI\05_产品与开发\VR素材\3D模型>) 里已有 3 个 GLB 模型（88.4MB + 26.8MB + 28.2MB），这批素材可以直接进 Unity 做第一个场景，不必等生成。

### 纠偏三：Muse SDK 商用授权，对"个人自用"根本不是卡点

Muse SDK 的许可是**非商业用途免费**（测试、原型、艺术项目、个人探索），商业用途才需另行授权。你既然明确不着急商用，那么：

**现在就可以用现有 Muse 头环开始做 VR 视觉闭环，一分钱不花，不必先解决授权问题。**

授权只在产品化阶段才是决定性前提。所以昨天报告把它列为"必须解决的非技术卡点"，在"个人先用起来"这个目标下应该降级为"产品化阶段再处理"。这一条直接省掉了硬件采购的前置阻塞。

## 二、四类技术的可用性判决

### 1. "Om AI 联汇的 VLX 模型"——身份已核实：真实存在，但赛道不对；其中一款开源小模型可收编

你给的报道链接已读，身份核实完毕：**VLX 真实存在**，是杭州联汇科技（Om AI 联汇）2026 年 6 月发布的"面向物理世界的端侧流式多模态模型系列"，含三款——VLX-Flow（流式视频理解）、VLX-Seek（细粒度视觉感知定位）、VLX-Go（具身导航决策）。你看到的报道是 9 月 1 日新发布的 **VLX-VR**（视频深度推理），在 Google DeepMind 与哥伦比亚大学的 MINERVA 基准上以 78.8% 视频问答准确率登顶。V0.1 里"未能确认"的判断作废。

来源：[环球网转载报道](https://ai5g.china.com/ai/1300488/20260903/092026101.html)、[OmAI Lab GitHub](https://github.com/om-ai-lab)

**但对"能不能用得上"，判决分三层：**

| 型号 | 开源状态 | 对本项目的判决 |
|------|---------|---------------|
| VLX-VR | **未开源**，仅云端"开放体验平台" | 用不上：数据须离开本机，且是视频问答模型，不做渲染 |
| VLX-Flow / VLX-Go | GitHub 有仓库（om-ai-lab） | 用不上：定位是机器人/无人机的摄像头流式感知与导航，与禅修 VR 无关 |
| **VLX-Seek 1.5（3B）** | **2026 年 8 月已开源** | ⚠️ **2026-09-10 核校修正：移出候选**。原拟"让大模型看懂禅修真实环境（坐垫、香炉、经书）并纳入对话上下文"，但该模型能力是**细粒度视觉感知定位**（输出目标框，服务无人机/机器人），**非视觉—语言理解**，功能不匹配。详见判语 003 修订注记 |

**结论**：VLX 系列是"物理 AI/具身智能"赛道（机器人看懂世界），不是"生成世界"赛道。期待它做 VR 视觉生成要放下；~~但 VLX-Seek 3B 开源权重可作为阶段 C 的低成本增强项~~ → **2026-09-10 修订：该收编判断亦作废**，VLX 全系列均不进入本项目。原结论"赛道不对"经核校仍成立，且本次修订正是它的又一次印证。

### 2. 李飞飞的世界模型（World Labs / Marble）——用不上

| 判据 | 实况 |
|------|------|
| 是否开源 | 否，仅 Web 应用与 API |
| 能否本地部署 | 否 |
| 能否与脑电实时联动 | 否 |
| 产出物 | 3D 世界/场景，非可交互实时环境 |

### 3. Meta 开源生态——两项能用，三项用不上

| 项目 | 判决 | 理由 |
|------|------|------|
| Habitat（具身智能仿真） | **能用** | Apache-2.0 开源，可在本机跑仿真渲染；但它是引擎框架，场景资产需自建 |
| PyTorch3D | **能用** | Apache-2.0，3D 深度学习工具库，可用于场景处理 |
| Codec Avatars | 用不上 | 未开源 |
| Movie Gen | 用不上 | 仅论文级权重，27B 参数超本机合理负载，且非实时 |
| sEMG 腕带 | 用不上 | 仅学术论文，无开源代码、数据或 SDK |

来源：[habitat-lab](https://github.com/facebookresearch/habitat-lab)

**但要说实话**：Habitat 是为具身智能研究设计的仿真框架，拿它做禅修 VR 场景是杀鸡用牛刀，学习成本高、收益低。**直接用 Unity + Pico 官方 SDK 更快**。Habitat 的价值在于未来若要做"AI 智能体在禅修场景中自主行为"的研究，那时再引入。

### 4. 开源视频/3D 生成模型——3D 离线生成能用，视频生成用不上

| 类型 | 代表 | 判决 | 理由 |
|------|------|------|------|
| 视频生成 | Wan、HunyuanVideo、CogVideoX、LTX-Video | **用不上** | 生成延迟秒至分钟级，无法满足帧级实时反馈 |
| 3D 场景/物体生成 | ~~TRELLIS（MIT）、TripoSR（MIT）~~ | **⚠️2026-09-10 核校修正** | **TRELLIS 本机不可行**：MIT 协议无误，但**硬性要求 NVIDIA GPU＋CUDA，官方不支持 AMD，社区仅有 Apple Silicon 移植、无 ROCm 移植**；本机无 N 卡，必须走云 GPU。**TripoSR 本机可行且支持纯 CPU**（约 6GB）。两者均只能离线分钟级生成静态资产，**不能实时驱动变化** |

来源：[TRELLIS](https://github.com/microsoft/TRELLIS)、[TripoSR](https://github.com/VAST-AI-Research/TripoSR)

**推荐组合（2026-09-10 修订版）**：**本机 TripoSR（CPU 出粗模）＋ Stable Diffusion 3.5（DirectML/ONNX 出贴图与概念图，Stability AI 官方与 AMD 合作有优化版）＋ Open3D（后处理，v0.19 支持 SYCL 含 AMD）** → 导入 Unity + Pico SDK → 脑电经 Python 桥接（OSC 或 WebSocket）驱动 Shader 参数 → 本地千问负责会话引导与训练总结（不在实时渲染管线内）。**高质量网格若确有需要，走云 GPU 跑 TRELLIS**——禅修场景素材不含个人敏感信息，按法师裁定可出网。

## 三、硬件三条路线的决策建议

先给结论：**三条路线不是互斥选择，而是分时段推进。现在不换硬件，并行推进 NeuraDock 采购，BrainBit 留作产品化备选，自研放弃。**

### 路线判决总表

| 路线 | 成本 | 周期 | 判决 |
|------|------|------|------|
| 继续用现有 Muse S | 0 元 | 立刻 | **立即启动**（个人自用许可足够） |
| NeuraDock 7 通道 | 数千元 | **待确认交期** | **并行推进采购**（数据质量最优，但有交付风险） |
| BrainBit Headband | $499（约 3600 元） | 1–2 周 | **暂缓**（产品化阶段再启动，授权风险已消除） |
| 自研组装 | 实际 $400–800 + 3–6 个月 | 不推荐 | **放弃** |

### 路线一：现有 Muse 立即用起来

Muse S（第 3 代）提供 256Hz 原始脑电开放访问，无额外费用，是科研文献中使用最广的低成本脑电设备。你的声音闭环已在它上面跑通，采集代码、质检闸门、数据治理链路全部现成。

**唯一要做的是把数据出口从"声音"扩展为"声音＋VR"**，脑电采集层完全不动。这符合项目既定的单一硬件层原则。

### 路线二：NeuraDock 7 通道——技术上最适合禅修，但交付是决定性风险

我从本地材料核实到的规格：

| 项目 | 规格 |
|------|------|
| 通道数 | 7 通道干电极 |
| **电极布局** | **O1、O2、Oz、PO3、PO4、CP5、CP6** |
| 采样率/精度 | 250 Hz，24-bit ADC（TI ADS1299） |
| 噪声/共模抑制 | 输入噪声 <1.5 μV p-p，CMRR 110 dB |
| 连接 | BLE（Nordic nRF52840）＋ USB Type-C |
| 续航 | 约 6 小时 |
| 开源内容 | 硬件接口规范、机械 CAD、Python SDK、基础信号质量算法、智能体分析工具 |
| 许可 | 软件 MIT，硬件 CERN-OHL-W，CAD CC BY-SA 4.0 |
| 不开源 | 噪音屏蔽核心能力、专属电路设计 |

**这里有一个专业判断值得你注意**：NeuraDock 的电极布局是**枕顶区**（O1/O2/Oz 枕叶、PO3/PO4 顶枕、CP5/CP6 中颞），而 Muse 的电极位置是 Fpz、AF7、AF8、TP9、TP10，属**前额区**。禅修状态研究中最核心的 Alpha 波（8–13Hz）在枕叶最强，Theta 波在顶中线最强——**NeuraDock 的布点对禅修监测的科学性显著优于 Muse**。这不是营销话术，是电极位置与目标频段的匹配问题。

**但风险同样明确**：

按 2026-09-02 会谈共识，走**基础采购模式**（数千元，含开源基础算法与基础支持）即可，不需要定制开发——定制开发是产品化阶段的事。

### 路线四：自研组装——放弃，理由如下

诚实结论：不值得走。

- **模拟前端是硬门槛**：ADS1299 芯片原理图虽开源，但 PCB 布局对噪声极度敏感，非硬件背景者首次打板成功率极低
- **安全隔离是硬要求**：EEG 设备直接接触人体，必须电池供电＋光耦隔离，设计不当有电击风险
- **干电极是专利壁垒**：机械结构与镀层工艺（BrainBit 即持有干电极专利），自制干电极信噪比远不如成品
- **成本并不低**：BOM＋打样＋电极＋示波器实际支出 $400–800，已接近 BrainBit 售价
- **周期严重冲突**：从零到可用信号通常需 3–6 个月反复迭代，与"最快速度用起来"直接矛盾

唯一值得自研的场景是需要 16 通道以上且预算受限——你的项目不是这个情况。

### 明确表态：不需要 Agent 军团，而且它会是负担

四个理由：

1. **协调成本大于收益**：多 Agent 编排框架本身需要数周学习调试，对一个总量几个月、单人主导的项目，搭框架的时间可能超过直接编码的时间。
2. **上下文丢失严重**：Unity C#、脑电信号处理、大模型桥接三条线高度耦合，Agent 之间传递上下文的信息损耗远大于并行收益。
3. **验收瓶颈在人**：VR 佩戴体验、禅修反馈节奏、脑电噪声阈值这些核心判断只有你能做。Agent 产出再多，也得你逐一验证——并行不减少验收时间。
4. **单人项目的真正瓶颈是决策，不是产能**：AI 助理已能把编码效率提升数倍，再加军团边际收益递减。

**唯一确有多 Agent 价值的环节是技术选型调研**——一次性并行、产出可核验、不需要持续编排。**今天这轮就是**：四路并行调研（多模态模型选型、硬件对比、本地 NeuraDock 材料核实、Agent 平台核实），一次拿回结论。这个模式以后在遇到新的选型决策时复用即可。

## 七、本地开源模型选型结论（2026-09-05 深夜）

三个角色各给首选与备选，全部开源权重，全部放得进 64GB 统一内存：

| 角色 | 首选 | 关键数字 | 备选 |
|------|------|---------|------|
| A 禅修引导对话 | **Qwen3-30B-A3B（Q4_K_M，约 18.6GB）** | Strix Halo 同类机实测：短上下文约 100 tok/s、20K 上下文约 50 tok/s；Apache-2.0 | gpt-oss-20b（12GB，Apache-2.0，中文禅修语境弱） |
| B 中文语音引导（TTS） | **CosyVoice2-0.5B（约 2GB）** | 流式首包 150ms、RTF<0.3（NVIDIA 实测）；3 秒零样本声音克隆，可固定一位平和音色；Apache-2.0 | Kokoro-82M（82MB，CPU RTF 0.5–0.8，极轻） |
| C 中文语音识别（可选） | **SenseVoiceSmall（INT8 约 230MB）** | 中文准确率 >95%，ONNX 跨平台；MIT/Apache-2.0 | Paraformer-Large（约 1GB，精度更高） |

三模型同机共存核算：18.6＋2＋0.23 ≈ **21GB**，64GB 余约 43GB，足够 VR 渲染与系统开销。

来源：[Strix Halo 实测 Qwen3-30B-A3B](https://aiweekly.co/node/2422)、[CosyVoice2 论文](https://arxiv.org/html/2412.10117v1)、[SenseVoice 许可讨论](https://github.com/FunAudioLLM/SenseVoice/issues/286)

**诚实标注**：角色 A 有本机同类实测，可直接换；角色 B、C 的速度数字来自 NVIDIA GPU 或他机实测，**AMD 平台无同类实测**，属"架构推断＋跨平台兼容"判断，接入阶段 C 前须在本机实测 RTF 复核。

## 九、V0.3 修订记录（2026-09-09，依据 EEG/OpenBCI 借鉴研究与定向核验）

研究成果：[20260907_EEG与OpenBCI工程文章借鉴性研究_v1.md](<C:\Users\tiand\OneDrive\zhiguanAI\04_研究调研\EEG与AI\20260907_EEG与OpenBCI工程文章借鉴性研究_v1.md>)、[20260907_借鉴项定向核验对照表_v1.md](<C:\Users\tiand\OneDrive\zhiguanAI\04_研究调研\EEG与AI\20260907_借鉴项定向核验对照表_v1.md>)；案例沉淀：判语 009／010／011。

### 1. 价值口径修正：反馈闭环是"镜子"，不是"训练器"（判语 009）

JMIR 2025 预注册元分析（16 项 RCT／763 人，其中 11 项用 Muse）显示：消费级正念神经反馈对认知（g=0.07）、正念水平（g=0.02）、生理健康（g=0.11）均无对照优势，**脑靶标调制未获证据**，心理痛苦仅小幅下降（g=−0.16）且可能来自"neurosuggestion"（安慰剂）。据此本方案的反馈叙事口径统一为"**可观测、可复盘的大脑状态镜子**"——这与法师警惕"指标外求"的立场一致，指标用于复盘、不用于当场评分，不用于对外承诺功效。**宣发红线**：任何材料不得出现"提升专注/深化禅修 X%"类功效句。反向利好：元分析点名建议的"更充分校准与设备个体化"正是我们 B6／C6 的方向，负向结果反而印证差异化点。

### 2. 校准块参数定稿（新增任务 B7）

借鉴文章一并经文献核验：神经反馈正式训练前做基线校准属领域标准操作，参数采用 **Alpha 带 = IAPF±2 Hz、Theta 带 = 4 Hz 至 IAPF−3 Hz**（有已发表方案给出同一定义）。两点注意写入规范：① IAF 判定无行业统一标准，须**记录自家判定算法版本**；② 峰频在训练过程中会漂移，**定期重校准，不一次定终身**。

### 3. 眨眼/伪迹剔除方法替换（新增任务 B7，判语 010）

原拟照搬博客"固定 >150 μV 阈值"，核验中被原始研究证伪：固定 μV 判据检出率强烈依赖离眼距离（枕顶区几乎检不到眨眼）、高通滤波后进一步恶化、漏检眨眼会在顶叶伪装出类似 P3 的晚期正波——**枕顶区恰是禅修分析的要害位置**。改为：在线逐通道分位数自适应阈值做试次级标记，离线 FASTER（敏感特异性均 >90%）／RELAX／EEGPrep 级复算，两套结果均写入 meta。

### 4. 冷启动模板（新增任务 C6）

"一人一模型"获跨被试泛化文献强支持；补全项：新练习者首采前用既有练习者数据预训练＋**欧氏对齐（EA）／黎曼切空间对齐（TSA）**做零参数跨人适配，把首次校准成本压到分钟级，首日即出有意义反馈。

### 5. 假设与验证纪律

- **疲劳放缓策略**（反馈速率随疲劳下降）：定向核验未检索到直接文献支持，**保持假设地位**，列入我们自己的 A/B 验证项，不写进对外材料。
- **E5 多人测试**验收升级：至少设"有反馈/伪反馈"两态＋不良反应记录字段（文献平均水准之下正是这些缺口，低成本即可超越）。
- **文献证据分级三规则**（判语 011，建议并入数据治理规范）：元分析优先于单篇；无仓库链接的"开源"声称降档为不可复现；我方验证至少设伪反馈对照。

## 十、三环互证六对映射（2026-09-10 固化，依据法师对五字诀稿裁定）

来源：《止观VR禅修五字诀提炼稿》v1.1 §三 ＋ 《整体贯通与日用环补全方案讨论稿》§4.4。原五字诀稿"内外双闭环互证四对"经日用环补全后扩为六对，法师裁定并入本节固化。

### 1. 三环结构

| 环 | 名称 | 五相 | 时间尺度 | 承载 |
|---|---|---|---|---|
| 环一 | 座上毫秒环 | 入 → 照 → 运 → 入 | 延迟 ≤250ms、视觉响应 ≥4s、指标推送 <1s | 机内闭环，只走参数化 Shader |
| **环二** | **日用长程环** | **出 → 入** | **日／周级** | **可穿戴＋手机记录，基线协变量**（本轮补全，详见贯通稿 §三） |
| 环三 | 生态印证环 | 融 → 出 → 通 | 周／月级 | 判语沉淀、印证矩阵、社区回流、对外叙事 |

环一不含"融"，故大模型故障时系统优雅降级——**内环可靠性来自它不含生成式模型**。环二输出（基线、重校准触发、EA/TSA 冷启动模板）是环一的输入配置，**这条回边在代码里已存在**（ZG-046 定期重校准、C6 冷启动模板）。

### 2. 六对互证映射

| 环 | 对照项 | 互证方式 | 管辖判语／红线 |
|---|---|---|---|
| 环一内 | 频段功率 ↔ 禅修状态判语 | 指标只用于复盘对照，**不当场评分** | 判语 009 |
| 环一内 | 虚拟之相 ↔ 真实之觉 | 借假修真；相是手段、觉是目的，双重重叠感是检验点 | 判语 009／会议决策 3 |
| 环一内 | 在线自适应阈值 ↔ 离线 FASTER 复算 | 两套结果均写入 meta，互不覆盖，**差异即信息** | 判语 010 |
| **环一↔环二** | **座上实时荷载 S ↔ 日用基线** | **控制基线后 EEG 指标是否仍有信息量（增量效度自检）** | 判语 011／《递归的生命对齐方案》§二.4 |
| **环二内** | **主观自评 Eⁿ ↔ 客观记录 Eᵈ** | **标注是对 Eⁿ 的结构化，不修改 Eᵈ** | 判语 013／对齐方案 §二.1 |
| 全环 | 系统可调参数 ↔ 练习者自设目标 | 系统不得优化练习者自设目标以外的任何目标 | **ZG-052**（环二风险最高） |

加粗两对均由日用环供数——**这是日用环在印证结构上不可替代之处**：没有环二，"增量效度"无数据前提，H3 印证收敛性少一相不可检验。

### 3. 与 M4 印证建构轴的关系

09-10 法师已将《隐显协同生成建模方案》M4 印证矩阵的建构轴由状态量"安定"改为**过程五相「入·照·运·融·出」**。本节六对映射即五相在环上的互证落点，两者同源：五相是建构轴，六对是轴上各相之间的印证关系。

### 4. 骨＋皮双轨表述（法师已定）

对外宣发标准表述式：**「入照运融出——安住、觉察、调伏、慧观、日用」**。骨轨（入照运融出）用于架构、建模、印证建构轴；皮轨（安住/觉察/调伏/慧观/日用，取自一页纸原文关键词）仅作解释性副题，不得单独成轴、不得替换骨轨，同受判语 009 宣发红线约束（不得配功效句）。

### 5. 五相现状与"出"相缺口

| 相 | 印证可算性 | 说明 |
|---|---|---|
| 入／照／运 | 四路可算 | EEG＋动力学＋自评＋师评 |
| 融 | 半可 | 引导语音诱发的 EEG 响应与自发态存在混淆，需对照设计 |
| **出** | **空** | 摘下头显后无 EEG；**日用环未启动**——当前唯一结构性缺口 |

解阻前置＝日用环一阶段（字段表＋控制台子模块＋增量效度自检首跑，三项零采购、用已入库数据可启动）。推进次序建议：先跑三相 → 同期启日用环 → 融相延后 → 五相齐备后 H3 首次可检验。
