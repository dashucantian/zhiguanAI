## 三、VR 场景 V2 技术状态（vr_feedback.html）

### 3.1 算法：H-A′ 因果滚动分位数
- **背景**：09-10 三重分析发现 S.a 贴底死区，09-10 晚我按 q1q3 收窄静态 CAL 区间 → **失败**，灵敏度提 4.9 倍同时噪声也提 4.9 倍，三段真机触顶率 19.8%/41.0%/48.9%，法师 09-11 实测反馈"会闪、有跳跃感、对禅修构成扰动"。
- **修订**：H-A（固定个人基线）被三段数据证伪（A单调降 / B平稳 / C倒U，形态互斥），改为 H-A′ **因果滚动分位数**——只用过去数据，自动居中、自动缩放量程。
- **实装常量**（均在 `vr_feedback.html` 的 `ALGO`）：`histSec=300`（5分钟历史窗，**按时间秒定义而非 epoch 计数**，因后端每2秒出新值而非离线验证的5秒步进）、EMA `τ=12s`、`GAIN`。
- **实测效果**：中位 S.a 0.080→0.368；触顶 0%（原 30.7%/11.9%/43.1%）；|Δ|p90 降至 0.0038–0.0046；帧级 max jump 0.2874→0.0205（**改善 14 倍**）。
- **移植等价性**：`equiv_test.py` 提取页面真实 JS 与 Python 验证基准逐点比对，三段 664/1261/1282 样本 **偏差 0.00e+00**。

### 3.2 四维分工（对齐方案 §3.2）
| 维度 | 载体 | 周期 |
|---|---|---|
| ①底色 | 天穹色调（`THEME.tau`） | 60s，帧率无关 |
| ②中程 | 水面辉光、粒子透明度 | EMA τ=12s |
| ③短程 | 光球胀缩（引导所缘） | 10s（6次/分） |
| ④现实锚 | 水面极缓慢起伏 | 300s |

- 水面图样完整重复周期实测 **314.2 秒**（>注意窗4倍，不构成机械循环感）；同通道拍频周期 78.5s/157.1s。
- 各要素周期天然互质（水面四分量的空间频率差 75 倍，分属顶点位移与片元纹理，不竞争同一通道）。
- 修复了一处帧率相关 bug：主题色原用 `lerp(...,0.04)` 固定系数（VR 90fps 比桌面 60fps 快 1.5 倍），改连续形式 `1-exp(-dt/τ)`。

### 3.3 呼吸锚（重要义理定位）
- **原状**：`rate = S.hr>40 ? S.hr/60*0.1 : 0.08`，而本机无 PPG，`hr` 恒为 `None`→0，**永远走 0.08 固定分支**，代码注释却写"跟随心率"——法师 09-11 质疑"它好像是固定节奏"，**观察完全正确**。
- **已实测排除**：呼吸无法从脑电反推（跨通道 CV 0.40–0.47，远超 0.25 判据；长程能量波动 5.9 倍）。
- **处置**：改为显式 `GUIDE`（默认 6次/分、可调），代码注释与 HUD 如实标注**「引导所缘，非测量」**。守红线9（不得把缺失传感器伪装成生理测量）。

### 3.4 粒子避让
- 粒子只垂直上升、水平坐标终生不变 → 用水平 footprint 判定即可，**无需射线检测，零运行时开销**。触碰即原地重生到模型范围外（粒子数恒定，不产生密度突降）。
- 实测：载入时重排 19–22 个 → 重排后残留 0，运行数帧后仍 0。

### 3.5 声音通路
- **架构真相**：后端 `closedloop_controller.py` + `IsoEngine` 早有完整音频决策层（2分钟基线自适应、节拍 8–14Hz、音量限速），但 `vr_feedback.html` 对其**零引用**——视觉走前端静态 CAL、音频走 closedloop，属两条平行路径（撞"统一架构不造冗余"红线）。
- **处置**：监测路径复用既有决策器（`add_baseline`→`finalize_baseline`→`update` 返回 `(beat,vol,note)`，纯计算无副作用），tick 附加式增加 `beat/vol/audio_phase` 字段；前端用 **Web Audio AudioWorklet** 渲染（`IsoEngine` 走 `sounddevice` 只到电脑扬声器，物理上无法进头显，故输出层必须在前端，决策层复用后端）。
- 引导版声音为前端自主生成（10Hz 节拍、vol 0.16），**默认静音**，点「声音：关」可切。
- 端到端实测：tick 确带 `beat=10.0 vol=0.05 audio_phase=baseline`；Worklet 与相位连续参考偏差 **2.540e-12**。

## 五、推流故障根治（09-13，本窗口最后一项大工作）

### 5.1 故障与根因
- **现象**：纯监测采集时界面永久停在「正在连接数据源…」，波形/频段/PSD 全空；但 `/api/monitor/status` 正常返回 `recording`。
- **法师怀疑**是 09-08「纯监测与闭环反馈合并到一个界面」所致 → **git 考古证明不是**：单消费 SSE 设计从最初发布（`89996d4`）就存在，合并大改（`10f7f65`）只改前端入口与仪表卡，未动推流架构。
- **真根因**：SSE 生成器用 `run_in_executor(None, lambda: q.get(timeout=1.0))` 阻塞取**单消费队列** → 每连接长期占一个默认线程池线程（上限 `min(32, cpu+4)`）；`EventSource` 断线自动重连不断堆积未退出的生成器 → **线程池饥饿** → 新连接永远 yield 不出第一条数据，EventSource 处于 pending（**既不触发 onerror 也收不到消息**）。而 status 是普通 async 接口、不依赖该线程池，故照常返回 recording。
- **决定性证据**：以第二观察客户端接入推流，10 秒收 55 条 tick、packets 137→2986、四通道波形正常；而队列里**还压着 18:52:33 开始采集那一刻的消息**——13 分钟前端零消费。
- **叠加缺陷**：前端 `monEs.onerror = () => {}` 吞掉一切错误，全文件零重连逻辑；服务端无文件日志（异常只打到启动进程 stdout）。

### 5.2 修复
- **后端**：单消费 `queue.Queue` → `EventBroadcaster` 广播注册表（每连接独立 `asyncio.Queue`，非阻塞订阅，不占线程池）。`MONITOR.events` / `SESSION.events` 保留为**兼容属性**指向 legacy 队列（`neuradock_console_selftest` 直接消费它，须不破）。
- **同构缺陷一并修**：`ExperimentSession` 原为同样写法，4 处 `self.events.put` 改 `publish`。
- **前端**：`pollStatus`（既有 3 秒轮询，未新建定时器）内加看门狗——检测 `monLastEventAt` 超时即主动重连；`onerror` 不再吞错；断流时界面如实显示「⚠推流 Ns 未更新」，不再静默黑屏。

### 5.3 实测证据
- 6 连接并发各收 22–23 条（理论 24），**极差 1**；
- **70 轮重连后线程数 53→53 零增长**（根因直接证据）；
- 切断事件流后 t+4.5s 界面出现告警、**t+7.5s `re=1` 看门狗触发重连、0.2s 内恢复**；
- 全程零 JS 异常；`closedloop_selftest` PASS、`neuradock_console_selftest` 退出码 0 PASS、`validate_console.py` PASS。
- **注意**：以上压测全部用**模拟源**（可反复造故障、不占硬件），**真机蓝牙路径未经复测**。

## 七、本窗口的方法论教训（新窗口必读，避免重犯）

### 7.1 验证脚本累计 6 个判据 bug —— 同源：「拿想当然的机制当事实」
1. 把正则当字面量字符串比较（`r"a\.b" in html` 永不匹配）
2. 把**低通滤波时间常数**当振荡器周期做互质判定（τ 不存在相位对齐问题）
3. 块注释未剥离，致注释里的历史数字被当成代码误报
4. `lcm_frac` 分母误用 LCM（应为 GCD），把 314 秒算成 3.2 秒
5. **WebSocket 建立只发 `Network.webSocketCreated`，不发 `requestWillBeSent`** —— 只监听后者会误报"脑电版回归不再连 ws"
6. 逐字节 `r.read(1)` 致多线程 GIL 竞争，把**测量端瓶颈**误判为服务端饿死

另有三处同类错误：
- 测试读错元素 ID（`monMsgBox` 实为 `monMsg`），致"提示未显示"假阴性
- `--ignore-certificate-errors` **掩盖了真实证书校验行为**，使"SW 注册成功"当时并未在真实校验下验证过
- 看门狗测试注入 `monLastEventAt` 老化**无效**（事件流正常会立刻刷新回当前时刻），须改 `monEs.close()` 才能真正切断

**处置纪律**：判据错误**不得靠放宽标准掩盖**，须查清物理机制后修正判据。本窗口 6 次全部如此处理。

### 7.2 环境类坑（Windows PowerShell 5.1）
- **内联 `python -c "..."` 的引号会被吞**（本窗口至少 3 次失败）→ 一律改写 `.py` 脚本文件再跑
- **不支持三元 `?:`** → 用 `if/else`
- **`2>&1` 会把原生命令 stderr 包成 ErrorRecord**，致 `$?` 假失败 → 用 `$LASTEXITCODE` 判真实退出码（`neuradock_console_selftest` 曾因此被误判为失败，实为 PASS）
- `Select-Object -First N` 提前关闭管道会使 git 收到 broken pipe、退出码 1（提交其实成功）
- **Glob 工具对中文路径不灵** → 用绝对路径 + PowerShell `Get-ChildItem`

### 7.3 反复出现的根本教训
**「编译通过 / 语法通过 ≠ 运行时正确」** —— 本窗口第 7~9 例。推流故障本身就是编译通过、静态校验通过的运行时缺陷。凡涉及运行时行为的改动，必须真实加载/真实并发/真实断流实测，不能止步于 `node --check`、`py_compile`、`validate_console.py`。
