## 0. 目的与用法

1. **目的**：从每条工作线抽真实任务，让三个本地模型各跑一遍，盲评打分，量化"哪个模型在哪类活上更可用"，把模型选用从经验判断变成可复现实测。
2. **怎么用**：每个任务 = 一份**冻结的固定输入** ＋ 明确产出要求。**同一提示词、同一生成参数**发给每个候选模型（见 §4、§5），收集输出后交裁判按 §2 量表评分。
3. **裁判隔离原则**（呼应经验五）：Qwen-Max 只做**裁判**时质量最高；若它同时跑了某个任务，其自身产出**不得由自己打分**，须换本地模型评或法师复核。
4. **本集定位是定性筛选，不是定量排名**：每线 3–4 个任务、单线数据点有限，只能支撑"哪个模型大致适合哪类活"的方向性结论，不足以做统计显著性排名。要出可引用的排名数字，须先扩至每线 ≥8 个任务。
5. **本集为种子集**：新任务一律来自实际工作产物或项目自有模拟器，**不虚构业务场景**。

## 2. 通用评分量表

采用 **"红线一票否决 ＋ 四维量化"**。每个任务满分 100。

### 2.1 红线闸门（Veto）— 先于一切
任一条命中 → **该候选直接判 0 分、淘汰**，其余维度不再计分：
- **数据违规**：产出含原始脑电／学员姓名／督导内容／法师声纹等本应本地处理的内容；
- **编造引用**：捏造政策条文、版本号、网址、机构发文（尤其"权威背书型"编造，见经验二③）；
- **张冠李戴**：把两个独立项目／工具混为一谈；
- **【整改新增】反问已知前提**：项目档案中**有明确、无歧义陈述**的事实（硬件规格、数据边界、既有判决等），模型反过来要求提供、或声称其不存在。本轮实测中此类失分最重（见经验一）。
  - ⚠️**豁免条款（防误伤，裁判必读）**：若背景文档对该点**表述模糊、存在歧义或根本未覆盖**，模型提出澄清或标注"存疑"，**不仅不触红线，反而是经验三所鼓励的诚实行为，应在 A 维度加分**。裁判须**先确认"该前提在喂入的背景中是否真的明确写过"**，再决定是否触发。**严禁用本条惩罚诚实。**
  - 设立本条的缘由：本条与经验三存在表面张力，故必须靠豁免条款划清界线——**惩罚的是"明明给了还装不知道"，不是"不知道却说知道"**。后者才是真正危险的那一类。

> 设计意图：这是我们这次实测最血的教训——**结论对、依据假，比结论错更危险**。故红线违规零容忍。

### 2.2 四维量化（红线通过后）

| 维度 | 权重 | 评分要点 |
|---|---|---|
| **A. 准确性** | 35% | 事实／数据／规格正确；不臆造数字、版本号、时间；不确定处是否如实标注"存疑"（经验三） |
| **B. 项目契合度** | 25% | 是否贴合止观项目语境与既有判语体系，而非通用套话；**是否真的用到了喂给它的项目档案**（经验一） |
| **C. 可执行性** | 25% | 产出能否直接落地（具体步骤／路径／文件名），而非漂亮但空的框架 |
| **D. 完整性与格式** | 15% | 是否满足全部要求、格式是否符合规范（如 BIDS、决策日志格式） |

**最终分 = 100 × (0.35A + 0.25B + 0.25C + 0.15D)**，红线违规则记 0。

## 4. 生成参数规范【整改新增 · 阻断项】

**不固定参数就谈不上"可复现"**。同一提示词在不同 temperature 下产出差异巨大，三次跑的结果不可比。本轮所有评测必须遵守：

| 参数 | 固定值 | 说明 |
|---|---|---|
| **temperature** | 0.3 | 评测求稳定可比，不求创造性；若某任务明确需要发散（如 L3-01 引导语设计），单独标注并在记录表注明实际值 |
| **top_p** | 0.9 | 三模型一致 |
| **max_tokens** | 4096 | 足够完成全部任务；防止长输出被截断影响 D 维度评分 |
| **system prompt** | **统一为空** | 不得给任何模型额外人设或提示，否则违背"同一提示词"原则 |
| **上下文窗口** | 各模型默认最大 | 记录实际值 |
| **thinking／推理模式** | **统一关闭**（若某模型仅有推理模式则记录并标注） | 开与不开对延迟和产出结构影响极大，必须一致 |
| **seed** | **42**（固定） | ⚠️**复审补入**：不固定 seed 则即便 temperature=0.3 仍是非确定性输出，同参不同果。llama.cpp／LM Studio 支持该参数；**若某模型或后端不支持，须在记录表注明"seed 未生效"，该结果标注【弱可复现】** |
| **重复次数** | 每任务每模型 **1 次** | v1 先求覆盖面；扩集后再考虑 3 次取均值（届时须保持 seed 不同以测稳定性） |

**记录义务**：跑完后在 §8 记录表附一张"实际参数表"，逐项写明真实使用值。**任何一项偏离上表，该次结果标注【不可比】，不得写入路由表。**

## 5. 输入交付方式【整改新增 · 重要项】

**本地模型在 LM Studio 里无法自行读取文件系统**——原稿多数任务只给文件路径，执行者拿到任务卡后无从下手。统一规则：

| 输入规模 | 交付方式 |
|---|---|
| ≤ 8K token | **全文贴入提示词**（首选，最公平） |
| 8K–32K token | 贴入**全文关键段落 ＋ 结构目录**，并在提示词中说明"以下为节选" |
| > 32K token | 该任务**暂不纳入 v1**，待 RAG 知识库建成后另议 |

**统一前缀**（每个任务提示词开头逐字一致地加）：

```
你是止观AI项目的AI助理。以下是本项目的关键背景，请先读取再作答。

【项目背景】
{粘贴 AI-开工入口.md 全文 ＋ 决策日志相关条目}

【本次任务】
{任务描述}

【输入素材】
{按上表方式交付的素材}
```
