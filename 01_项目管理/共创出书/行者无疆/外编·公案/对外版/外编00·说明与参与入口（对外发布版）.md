## 一、为什么书里要有这一编

正编讲**发生了什么**（编年纪事），别编讲**为什么这样想**（义理提炼），外编讲**你可以怎么做**。

三编分工源于项目记录体系的五层流转：素材层（记莂）→ 叙事层（灯录）→ 案例层（公案）→ 发布层（刊刻流通）→ 社区层（丛林共修）。正编对应叙事层，别编是案例层与方案文档的义理投影，**外编直接落在案例层与社区层**。

项目案例库的说明里有一句话，是这一编的全部理由：

> **叙事与案例，是同一批素材的两种提炼**：一次攻坚 → 一个纪事章节（讲人讲事）＋ 若干案例卡（讲方法讲判决）。

所以外编的内容不是新写的，是从项目案例库已有的判语卡与踩坑档案里选出来、脱敏、改写为书内体例。**这一编不新建任何判断，只把已有判断交到读者手上。**

法师在 2026-09-08 夜谈里说过传播这件事的机理：

> "先是小圈子达成一种共识，然后慢慢扩散——**为什么你会认同？你有感同身受，那么你有，别人也会有。**"

> "**人都不傻。到时候大家都会明白，不需要教化**……比如说我做了，我这个并不是教化，它就是一种分享。"

外编就是"分享"这一半的落点：不说服谁，把走过的路、踩过的坑、否决过的方案摊开，读者自己判断能不能用。

## 二、收录标准（四条）

从案例库的判语卡与踩坑档案里选，按以下四条判定：

| # | 标准 | 说明 |
|---|------|------|
| 1 | **自足性** | 一个完全不了解本项目的陌生读者，只读这一张能否看懂？严重依赖内部上下文（五字诀、灵魂假设、任务编号、特定合作方）者降档 |
| 2 | **含被否方案** | 判语体例要求写"被否方案"。**含被否方案者优先收录**——"为什么不那样做"才是公案的核心，只讲结论的卡不是公案 |
| 3 | **可迁移性** | 教训能否用到读者自己的项目上？只对内有意义者（如特定任务编号的流转）不收 |
| 4 | **脱敏可行性** | 含内部或敏感内容（商务数字、未定型合作条款、学员信息、僧团事务）者，须能脱敏后收录；脱敏后若失去判断依据，则不收 |

**收录结构**：判语精选十张（另两张因义理已在别编完整展开，此处只存判决与教训；一张因专业性太强未收，指向案例库原卡备查）；踩坑精选六篇（另两篇专业向摘录）；复现路径两篇全文收入。**清单与对应编号见文末《素材来源》。**

## 三、参与入口

外编的终点不是"读完"，是"参与"。四种入口，由浅入深。

### 入口一：复刻（最低门槛）

- **开源仓**：项目代码已推送至公开 GitHub 仓（正编第三章记此事：约 150 个文件、自研内容 20 余件）。
- **复现路径**：外编 03、04 两篇。**注意前置条件**——两篇都要求你**已经有一套可运行的系统**（一篇要求已有声音神经反馈闭环，一篇要求已有单一设备＋单一入口的采集系统），是**进阶扩展指南**，不是从零教程。
- **踩坑档案**：外编 02 六篇。**建议先读踩坑再动手**，六个坑里有四个是"改代码之前先查别的"。

法师在 09-08 夜谈里讲过复刻路径：

> "一个人、两个人、三个人这样去扩展……有兴趣、有条件的慢慢上手探索实践，脑电的、VR 的，就可以先开始模仿或复刻，或是在这个里面再去迭代。"

### 入口二：共析（中等门槛）

对已有数据与判决提出质疑。**这个项目欢迎反驳，而且有承接反驳的机制**：

- 判语体例本身要求写"被否方案"——你的反驳可以成为下一张卡的被否方案，或成为一条修订注记。
- 有一张判语就是现成范例：原判决里有一节后来作废，处理办法是**追加修订注记、原判决不删改**。
- 另一张判语要求"我方验证至少设伪反馈对照＋不良反应记录"——若你的验证设计比这更严，那就是对这套方法的改进。

项目组成员温伟东在 09-08 夜谈里的一句质疑（"这个东西对我们来说没有任何用处啊"）被如实保留在正编第四章，**没有因为是质疑就删掉**；项目的建模方案还把他列为"分歧登记第一读者"。**这是这个项目对待反驳的实际做法，不是姿态。**

### 入口三：共建任务（较高门槛）

项目用云端任务表管理全部待办，规则两条（正编第三章记此事）：

- **单一真相源**：事只在这一张表里算数。
- **验收标准为必填，无验收标准不进表**——方案原文："有验收标准才配进表，这本身就是对项目最好的过滤。"

若你要提共建任务，请附验收标准。**没有验收标准的提议不会进表**，这条对项目内部成员同样适用。

### 入口四：实践记录（回流）

你若复刻或共修，欢迎按以下最小模板记录，脱敏后回流：

```
【实践记录】
- 你的环境（设备／系统／头显／Python 版本）：
- 你照哪一篇做的：
- 卡在哪一步（原话照录，不要润色）：
- 你怎么绕过去的：
- 若没绕过去，你排查到哪一层：
- 你认为文档哪里写错了或漏了：
```

**"卡在哪一步"请照录原话。**案例库踩坑档案的体例就是"现象（用户视角，**原话**）→根因→解法→排障顺序"——原话比润色后的描述有用得多，因为根因往往就藏在原话的措辞里。

〔AI 理解〕这条回流通道对应项目记录体系的社区层（"让他人参与并回流"），也对应建模方案**生态复刻层**的"社区回流即最宽印证"：**他人复刻数据（脱敏）进印证矩阵**。也就是说，你的实践记录不只是给后来者看的文档，它可能成为模型真值生成的一路映射。

## 四、边界与红线（本编适用）

1. **发布前脱敏**：案例卡默认内部级，本编所收全部为脱敏改写版；对外发布仍须法师逐篇审定。
2. **不含学员数据与原始脑电**：本编所收各卡均不含学员个人信息、脑电原始数据、僧团内部事务。
3. **商务数字不入书**：含采购金额的卡已删去该节；合作方评价按中性化处理。
4. **不配功效句**：本编任何表述不得出现"提升专注 X%""深化禅修 X%"类句式。
5. **痛苦不作修行解读**：读者若在实践中出现痛苦或危机状态，**唯一正确的动作是寻求师长与专业帮助**；**本编任何一篇都不提供"这是突破前兆"一类解读。**
6. **判决可修订，修订不删改原判决**：原判决保留、追加修订注记。
