## 阶段一：架构决策（1–2 天）

### 1.1 确定视觉渲染方案

**决策点**：Unity 原生 vs WebXR

| 方案 | 优势 | 劣势 | 适用场景 |
|------|------|------|----------|
| Unity 原生 | 性能最优，生态成熟 | 需要安装 Unity，学习成本高 | 长期产品化 |
| WebXR | 零安装，跨平台，开发快 | 性能略低，浏览器兼容性限制 | 快速验证、原型开发 |

**本项目选择**：WebXR（理由：本机未装 Unity，优先快速验证）

**关键判据**：
- 如果已有 Unity 经验且计划长期迭代 → Unity
- 如果需要快速验证或团队有 Web 开发背景 → WebXR

〔AI 理解〕这一决策与《判语精选》里"VR 首落地走 WebXR"那张卡同源。"零安装"在本项目语境下不是便利问题，是**周期问题**——等 Unity 安装和学习是几周的事，与"最快速度用起来"直接冲突。

### 1.2 确定数据传输架构

**决策点**：直连 vs WebSocket 桥接

| 方案 | 优势 | 劣势 |
|------|------|------|
| 直连（VR 直接连蓝牙） | 延迟最低 | 头显蓝牙栈不稳定，易断连 |
| WebSocket 桥接（PC 中转） | 稳定，可复用现有后端 | 增加一跳延迟（<50ms，可接受） |

**本项目选择**：WebSocket 桥接（理由：蓝牙稳定性是已知痛点，见外编 02 第三坑）

**架构**：
```
Muse 头环 → PC 蓝牙 → Python 后端 → WebSocket → VR 浏览器
```

## 阶段二：后端改造（3–5 天）

### 2.1 添加 WebSocket 服务

**目标**：在现有 HTTP API 基础上，增加 WebSocket 端点，实时推送脑电指标。

**关键代码**：
```python
from fastapi import WebSocket

@app.websocket("/ws/vr")
async def vr_ws(websocket: WebSocket):
    await websocket.accept()
    try:
        while True:
            # 从现有数据流获取最新指标
            metrics = get_latest_metrics()
            await websocket.send_json(metrics)
            await asyncio.sleep(0.25)  # 4Hz 推送
    except WebSocketDisconnect:
        pass
```

**注意事项**：
- 推送频率 4Hz 足够（**VR 视觉反馈不需要 256Hz 原始波形**）
- 包含字段：timestamp, alpha, beta, theta, delta, attention, meditation
- 异常处理：客户端断开时优雅退出

### 2.2 添加 HTTPS 支持（关键！）

**为什么必须 HTTPS**：WebXR 规范要求安全上下文（Secure Context），**只有 HTTPS 或 localhost 才能访问 `navigator.xr`**。局域网 HTTP 地址（如 `http://192.168.x.x`）会被浏览器拒绝。（完整排障见外编 02 第一坑）

**解决方案**：自签名证书

**步骤**：

1. 生成证书（用 `cryptography` 幂等生成）：
   ```python
   from cryptography import x509
   from cryptography.x509.oid import NameOID
   from cryptography.hazmat.primitives import hashes, serialization
   from cryptography.hazmat.primitives.asymmetric import rsa
   import datetime

   key = rsa.generate_private_key(public_exponent=65537, key_size=2048)
   subject = issuer = x509.Name([
       x509.NameAttribute(NameOID.COMMON_NAME, u"localhost"),
   ])
   cert = x509.CertificateBuilder().subject_name(
       subject
   ).issuer_name(
       issuer
   ).public_key(
       key.public_key()
   ).serial_number(
       x509.random_serial_number()
   ).not_valid_before(
       datetime.datetime.utcnow()
   ).not_valid_after(
       datetime.datetime.utcnow() + datetime.timedelta(days=365)
   ).sign(key, hashes.SHA256())

   with open("cert.pem", "wb") as f:
       f.write(cert.public_bytes(serialization.Encoding.PEM))
   with open("key.pem", "wb") as f:
       f.write(key.private_bytes(
           encoding=serialization.Encoding.PEM,
           format=serialization.PrivateFormat.TraditionalOpenSSL,
           encryption_algorithm=serialization.NoEncryption()
       ))
   ```

2. 配置服务端使用 HTTPS（双端口，HTTP 与 HTTPS 并行）：
   ```python
   import uvicorn
   uvicorn.run(
       app,
       host="0.0.0.0",
       port=8778,
       ssl_keyfile="key.pem",
       ssl_certfile="cert.pem"
   )
   ```

3. 头显浏览器首次访问时，手动信任证书（点击"高级" → "继续访问"）

**踩坑预警**：
- 证书有效期建议 1 年，过期需重新生成
- **不要用 `localhost` 作为 IP 地址**，用实际局域网 IP（如 `192.168.1.105`）
- 如果报"证书不受信任"，这是正常的，手动信任即可

## 阶段三：VR 前端开发（5–7 天）

### 3.1 搭建 WebXR 基础框架

**技术栈**：
- Three.js（3D 渲染）
- WebXR API（VR 模式）
- WebSocket（数据接收）

**最小可运行示例**：
```html
<!DOCTYPE html>
<html>
<head>
    <meta charset="utf-8">
    <title>VR 神经反馈</title>
    <script src="https://cdn.jsdelivr.net/npm/three@0.160.0/build/three.min.js"></script>
</head>
<body>
    <script>
        // 初始化 Three.js
        const scene = new THREE.Scene();
        const camera = new THREE.PerspectiveCamera(75, window.innerWidth / window.innerHeight, 0.1, 1000);
        const renderer = new THREE.WebGLRenderer({ antialias: true });
        renderer.setSize(window.innerWidth, window.innerHeight);
        renderer.xr.enabled = true;
        document.body.appendChild(renderer.domElement);

        // 添加场景内容
        const geometry = new THREE.BoxGeometry();
        const material = new THREE.MeshStandardMaterial({ color: 0x00ff00 });
        const cube = new THREE.Mesh(geometry, material);
        scene.add(cube);

        const light = new THREE.PointLight(0xffffff, 1, 100);
        light.position.set(10, 10, 10);
        scene.add(light);

        // WebSocket 连接
        const ws = new WebSocket('wss://192.168.1.105:8778/ws/vr');
        ws.onmessage = (event) => {
            const data = JSON.parse(event.data);
            // 根据脑电数据更新场景
            cube.scale.setScalar(1 + data.attention * 0.5);
        };

        // 渲染循环
        renderer.setAnimationLoop(() => {
            cube.rotation.x += 0.01;
            cube.rotation.y += 0.01;
            renderer.render(scene, camera);
        });

        // 进入 VR 模式
        navigator.xr.requestSession('immersive-vr').then((session) => {
            renderer.xr.setSession(session);
        });
    </script>
</body>
</html>
```

〔AI 理解〕示例里 `three.min.js` 走的是 CDN。**本项目实际把 three.js 本地化到了资产目录，使页面完全离线可用**——这是《判语精选》里"VR 首落地走 WebXR"那张卡的要求之一（离线可用）。读者复现时若要离线运行，需把 three.js 下载到本地引用。

### 3.2 设计视觉反馈映射

**关键决策**：哪些脑电指标映射到什么视觉元素？

**参考方案（本项目实际采用）**：

| 脑电指标 | 视觉元素 | 映射逻辑 |
|----------|----------|----------|
| attention | 心息之珠亮度 | `brightness = 0.3 + attention * 0.7` |
| meditation | 水面涟漪扩散速度 | `speed = meditation * 2` |
| alpha | 雾气浓度 | `fogDensity = 0.1 - alpha * 0.05` |
| theta | 粒子系统密度 | `particleCount = theta * 100` |

**设计原则**：
1. **正反馈优先**：专注度提升 → 视觉变亮／变清晰（鼓励用户保持专注）
2. **避免过度刺激**：变化要平滑，不要突变（用插值或缓动函数）
3. **多通道并行**：同时映射多个指标，但每个通道独立，避免相互干扰

〔AI 理解〕原则 2"避免过度刺激"对应法师 09-08 夜谈里讲的"度"——奥妙在把握刺激度（认知负荷，投入与产出的关系），**过了就形成躁动、过度反馈**。映射参数的调整不是纯工程问题，它直接关系到反馈是"关照"还是"打扰"。

原则 1"正反馈优先"须与《判语精选》里"镜子非训练器"那张卡并读：镜子照见状态，**不当场评分**。视觉变亮是状态的呈现，不是对练习者的打分——这一界线一旦模糊，镜子就滑向训练器。

### 3.3 优化性能

**目标**：90Hz 稳定帧率（Pico 4 Ultra 要求）

**优化手段**：
1. **降低推送频率**：后端 4Hz 推送，前端用插值平滑到 90Hz
2. **减少 Draw Call**：合并几何体，使用 InstancedMesh
3. **LOD（Level of Detail）**：远处物体用低模
4. **纹理压缩**：使用 KTX2 格式

**监控工具**：
- 头显浏览器内置性能面板（FPS、内存、GPU 占用）
- Chrome DevTools Remote Debugging（通过 USB 连接）

## 阶段四：联调与测试（3–5 天）

### 4.1 局域网连通性测试

**检查清单**：
- [ ] PC 和头显在同一 Wi-Fi（同一网段，如 192.168.1.x）
- [ ] PC 防火墙放行 8778 端口（HTTPS）
- [ ] 头显浏览器能访问 `https://192.168.1.105:8778/vr`
- [ ] 手动信任自签名证书

**常见问题**：
1. **头显显示"已离线"**：检查端口是否被旧进程占用（见外编 02 第二坑）
2. **无法进入 VR 模式**：检查是否用 HTTPS（见外编 02 第一坑）
3. **WebSocket 连接失败**：检查 wss:// 协议（不是 ws://）

### 4.2 蓝牙稳定性测试

**测试方法**：
1. 启动闭环实验，连续运行 30 分钟
2. 监控数据流是否有静默断连（>18 秒无数据）
3. 记录断连次数和恢复时间

**预期结果**：
- 理想：0 次断连
- 可接受：1–2 次断连，每次恢复时间 <5 秒
- 不可接受：频繁断连（>5 次／30 分钟）

**如果频繁断连**：
1. 检查头环电量（<20% 时信号弱）
2. 检查 PC 蓝牙驱动版本（更新到最新）
3. 考虑改用专用蓝牙适配器（本项目采用，见外编 02 第三坑与附二）

### 4.3 用户体验测试

**测试维度**：
1. **视觉舒适度**：是否有眩晕感？（如果有，降低运动速度或减少粒子）
2. **反馈直观性**：用户能否理解视觉变化与自身状态的关联？
3. **沉浸感**：是否能帮助用户进入放松／专注状态？

**测试方法**：
- 让 3–5 名志愿者各体验 15 分钟——**须先取得知情同意**：说明采集内容与用途、可随时退出、数据如何脱敏与保存
- 收集主观评分（1–10 分）和定性反馈
- **同时记录不良反应**（眩晕、不适、情绪波动），并写明中止条件与求助指引——这一条与"我方验证至少设伪反馈对照＋不良反应记录"同源
- 根据反馈调整视觉参数

〔AI 理解〕测试维度 3"沉浸感"的措辞需谨慎：本项目的反馈定位是镜子（见《判语精选》相应那张卡），**不是"让用户沉浸到离不开"**。"痛苦不得解读为相变前兆"那条红线在此适用——若用户体验测试发现"沉浸感"强到产生依赖倾向，那不是优化目标，是警示信号（法师 09-08 夜谈讲的"成瘾与可调性"，详见别编 02）。
