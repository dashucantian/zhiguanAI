# AI 调用管家

管你手上三个订阅：**OpenCode Go**（美元额度）、**百炼 Token Plan**（Credits）、**Qoder 积分**。
它做三件事：告诉你这个活该走哪个订阅、用一个本机代理自动分流、把每一笔花的钱记在本地账本上。

全在本机跑。密钥只从环境变量读，不落盘、不进日志、账本文件不进版本库。

---

## 一、第一次用（三步）

**第一步：双击 `调用管家.cmd`**
弹出一个中文菜单，按序号选就行。

**第二步：把三个订阅的剩余额度抄进去**
菜单里选「录额度」，把百炼和 Qoder 的剩余积分填进去（抄官网上的数字即可）。
OpenCode Go 不用抄，它的每模型封顶是固定的，管家自己知道。

> **一个渠道可以分好几个池。** Qoder 就有三个池（套餐内积分、资源包、Qwen 专属积分），
> 到期日各不相同，得分开录，管家才能提醒你哪个快过期。录的时候它会问「这是哪个池子」。
> 同样，每个池的到期日、刷新日也一起填进去。

**第三步（可选，但省事）：把客户端指到本机代理**
见下面第三节。不做也能用，只是省不了自动分流。

## 三、接本机代理（自动分流的正戏）

**代理是干什么的**：你的编码客户端（Claude Code、Kilo Code、jcode 等）本来直接打 OpenCode，
现在改打本机的代理。代理按规则挑一个最省的模型再转发出去，同时把这一笔记进账本。

**为什么值得**：OpenCode 官方的「预计请求数」是按每次 7 万多 token 算的，
你的实际每次用了二十几万 token，所以消耗比预估快好几倍。代理能实时看到实际 token 数，
并且把贵模型自动换成便宜的，这是省钱的主要来源。

**怎么接**：

1. 先起代理：双击 `启动代理.cmd`（窗口开着别关）。
2. 菜单里选「配置」，照着打印出来的片段填进你的客户端：
   - 接口地址填 `http://127.0.0.1:8791/v1`
   - 模型名填 `auto`（写 `auto` 才会自动选；写死模型名就照你指定的走）
   - 密钥填不填都行；要填就填你自己定的那串，并且客户端和代理两边一致

**接 Go 通道时，代理自动替你补两样东西**，你自己不用管：
- 一个会话头（Go 上游缺了会直接报 400）。
- 一个像浏览器的客户端标识（Go 上游前面挡着 Cloudflare，用默认标识会被挡成 403）。

**代理的规矩**：
- 只绑本机 `127.0.0.1`，别的机器连不上。
- 上游密钥只从环境变量 `OPENCODE_API_KEY` 读，代理不代你从任何地方找密钥。
- 某个模型这个月用满封顶的九成，就自动不再用它，改用更省的；全打满就退到免费模型。
- 上下文特别大时，自动避开封顶只有 15 美元的那几个贵模型。
- 每次调用在 `数据\审计.log` 留一行，带任务号、时刻、HTTP 码、花费、耗时。

**还有一条容易踩的账**：
Go 的额度除了「这个月多少美元」，还有更细的三层窗口——5 小时占两成、一周占五成、一个月占满。
**月度还剩一半，也可能因为某个 5 小时窗口烧穿了而被限速**（2026-11-03 零点那 13 分钟连打 42 次，
把 grok-4.7 的 5 小时窗口烧到 129% 就是这么来的）。代理会盯着这三个窗口，
接近上限时提前提醒并改派更省的模型。

**Windows 上设环境变量**（只对当前窗口有效，关掉就没了，不落盘）：

```
set AI_ROUTER_TOKEN=你自己定的一串字符
set OPENCODE_API_KEY=你的Go密钥
set TOKEN_PLAN_API_KEY=你的百炼密钥
set AI_ROUTER_PORT=8791
```

**要长期生效，就设成用户级环境变量**（系统里存着，开任何程序都带着）：

1. 按 Win 键，输「环境变量」，点「编辑系统环境变量」。
2. 在上半格「用户变量」那栏，点「新建」。
3. 变量名照抄（比如 `TOKEN_PLAN_API_KEY`），一字不差、别加空格。
4. 变量值粘密钥进去，点确定。
5. 密钥不用告诉任何 AI、也不发任何对话——它只进您自己电脑。

设完**不用重启电脑，也不用重启代理**：代理每次判断池的可用性都现去读一遍用户级环境变量。
想确认设上了：开一个新的命令提示符窗口，敲 `echo %TOKEN_PLAN_API_KEY%`，能打出来就成了。

**2026-11-06 现状（免得再照着设一遍）**：
- `TOKEN_PLAN_API_KEY` **已经设好了**——法师授权本窗读 DSH 凭据后，由本窗写入用户级环境变量，
  值取的是 DSH 里的 `DSH_API_KEY`（114 位，sk- 开头）。**这把钥匙真打 Token Plan 入口回 200**，
  打百炼 DashScope 入口回 401 ⇒ 它是 **Token Plan 的密钥**，不是百炼通用密钥。
- 用户级另有一个 `QIANWEN_API_KEY`（115 位）。它跟上面那把**不是同一把**（从第 16 位起就不同），
  打 Token Plan 与百炼两个入口**都是 401** ⇒ **这把不能用**，留着不影响管家（管家不读它）。
- **想自己核对一把密钥能不能用**：双击 `验百炼密钥.cmd`。它会列出用户级所有跟百炼有关的变量名
  （只列名、长度、形状，**不打印值**）、点名管家读的是哪个、然后把每个候选变量真打两个入口，
  只报 HTTP 码与回话。密钥值全程只在内存里，不落盘、不进日志。
- **现在默认走哪条路**：Go 的月度总额度已经用尽，上游改按充值余额计费；
  所以管家把百炼／Token Plan 提到 Go 前面，**默认调用吃 Credits，不烧那 10 美元余额**。
  余额现状与去向见第十五节，飞书两个群的接法见第二十节。

## 八、跟 EasyCLIProxyAPI 什么关系

**原来两回事，现在接上了。**

2026-11-04 的实测结论：
- 真正在烧 Go 额度的是 **DSH**，它直连 `https://opencode.ai/zen/go/v1`。
- EasyCLIProxyAPI 里那个 `openai-compatibility` 组指的是 `https://opencode.ai/inference/v1`，
  **那是另一条计费路径，不是 Go**；同一个密钥在那儿 31 次全失败（付费模型报 402、免费模型报 429）。
- 所以 EasyCLIProxyAPI **既没消耗你的 Go 额度，也不是 Go 通道的正确接法**。

2026-11-05 法师准了第六条：CPA 那个 OpenCode 组改指 Go 路径。**实测下来直连接不成**，
改成了经管家中转——详见第十六节。

**留不留它**：只留 Codex OAuth 账号池和协议转换的话，就留着；
若只是为了走 Go，那就别用它，直接用本代理。

## 九、把调用挂到任务号上（跟任务中枢对接的那根轴）

**为什么**：任务中枢管「谁在做什么」，任务看板管「进度到哪」。
只有这个管家知道「这条任务花了多少钱」。两边要接上，缺的就是**任务号**这一根轴——
任务号一旦挂上，成本就能按任务回流，看板能按任务显示花费，巡检也能在额度触顶时点名是哪条任务烧的。

**任务号从哪来**（先到先得）：

1. 客户端带的头 `x-task-id`（最准，每个客户端各挂各的）；
2. 面板里「设当前任务」设的（**一次设定，所有走本代理的调用都算在这个任务号下**，不用改任何客户端）；
3. 代理环境变量 `AI_ROUTER_TASK_ID`（启动时的默认）；
4. 都没有 → 记「未标记」（**不猜、不编**，事后一眼看出哪些活没挂上任务）。

**怎么设**（面板里选「设当前任务」）：

```
python ai_router/cli.py 设当前任务 --设置 TASK-20261104-02 --工作区 D:/Project/zhiguanAI
python ai_router/cli.py 按任务看账
```

**给每个客户端各挂各的**（面板里选「配置」会打印同样的片段）：
- OpenCode：provider 的 `options` 里加 `"headers": {"x-task-id": "TASK-20261104-02"}`
- Codex：`~/.codex/config.toml` 的 `[model_providers.ai-router]` 里加 `http_headers = { "x-task-id" = "TASK-20261104-02" }`
- DSH：`settings.yaml` 的 provider 下加 `headers: {"x-task-id": "..."}`
- Claude Code：`settings.json` 的 `env` 里加 `ANTHROPIC_CUSTOM_HEADERS="x-task-id: TASK-20261104-02"`
  （这一条**以你手上版本为准**，本机没装 Claude Code，没验过；不认这个变量就退回「设当前任务」，效果一样）

**两条限制**：
- HTTP 头只能带 ASCII 字符，所以**头里的任务号用英文或数字**（`TASK-20261104-02` 这种）；
  中文任务名走「设当前任务」那条路。
- 任务号会被清洗：换行、空格、竖杠等换成横杠，截到 64 字符——否则一条脏任务号能拼出一条假日志。

## 十、派工前先问一句（派工选型）

**为什么有这条**：任务中枢派工时，最容易漏的是「这个活该走哪条通道、大概花多少」。
人凭印象派，常见结果是本该走免费模型的活扔进了贵模型，或者反过来。
派工选型就是把路由层已有的判断整理成一段**能直接抄进派工单的话**。

**怎么用**：

```
python ai_router/cli.py 派工选型 --任务 改码 --上下文 中 --无人值守 --任务号 TASK-20261104-02
python ai_router/cli.py 派工选型 --任务 写作 --上下文 小 --任务号 TASK-20261104-02 --一行
```

**出长这样**：

```
【调用安排】TASK-20261104-02
活类：改码｜上下文：中（约 80000 token）｜无人值守：是
走哪条通道：OpenCode Go
用哪个模型：deepseek-v4.1-flash
预计花费：约 0.03 美元（按输入 80000 token、输出 2000 token 估，实际以账本为准）
为什么：无人值守的活走 OpenCode Go 的本机代理，按规则选最省的模型。
本月封顶余量：deepseek-v4.1-flash 封顶 100 美元，已用 8.95，还剩 91.05 美元
5 小时窗口占用：0%
一周窗口占用：18%
备选：beam-free、iceman-contributor-free、qoder、bailian
（生成时刻 2026-11-05 00:19:26；本段由本机调用管家生成，不写中枢、不改源表）
```

**一行版**（塞进表格或对话里）：
`TASK-20261104-02｜OpenCode Go｜deepseek-v4.1-flash｜预计 0.03 美元`

**边界**：
- 这是**只读出口**：它不写中枢、不改源表、不往账本写任何东西。谁把这段贴进派工单，是人的动作。
- 「预计花费」是按输入 token 与输出 2000 token 估的**估算值**，不是账单；实际以账本为准。
- 任务号不给时取本机「当前任务」设定；两处都没有会记「未标记」，并在结论里提醒你先去挂上。
- 「要联网搜索、图像、语音这类 Harness 能力」加 `--要联网搜索`，它会指到百炼 Harness。

## 十一、账本对账（任务号对不对得上）

**为什么有这条**：任务号唯一的正源是 `01_项目管理\任务登记.md` 里的 `TASK-YYYYMMDD-NN`。
账本是本机自己写的，万一某个号写错、写成别的系统编号、或者压根没挂上，得能一眼看出来，
而不是等到月底对不上才发愁。

**怎么用**：面板里选「对账」，或命令行 `python ai_router/cli.py 对账`。

**出四态**（口径照协调位 11-04 的裁）：

| 判定 | 什么意思 | 管家怎么办 |
|---|---|---|
| 合 | 这个号在任务登记里 | 正常入账 |
| 未标记 | 没挂上任务 | 单列一行，**必须看得见** |
| 外部号 | 像是别的系统的号（飞书 `ZG-xxx`、窗口号） | 原样记着，不猜、不改、不丢 |
| 笔误 | 跟某个已登记号只差写法（如少了分隔符） | 原样记着，等人确认 |

**为什么允许「未标记」**：不给出口，跑批和临时调用就会把号乱填一气；
给了出口但让它可见，才对得上账。**藏起来的未标记比明写出来的未标记危险。**

**工作区栏**：账本每行还记「工作区」。
面板「对账」会把它列出来，并指出这个路径**在不在盘**、**是不是隔离执行树**（在 `_worktrees` 之下且真实存在）。
代理记账时也会自动补：任务号对应的隔离树若在盘，就把它的路径填上——填的是实测存在的路径，不是随手写的字符串。
面板「设当前任务」同理：不给 `--工作区` 时，它自己去查这个任务号的隔离树在不在盘，在盘才填真路径，不在盘就留空并提示；人显式给的路径照用。

## 十二、五个客户端指向代理（现成写法）

**先起代理**，再照下面改客户端。改之前先备份原文件。

**代理提供三条入站路径**（不止一条，因为四个客户端说的不是同一种话）：

| 客户端 | 它打哪条路径 | 代理转给上游的哪条 |
|---|---|---|
| OpenCode、Kilo Code 一类 OpenAI 兼容客户端 | `/v1/chat/completions` | Go 通道的 chat 端点 |
| Codex（`wire_api = "responses"`） | `/v1/responses` | Go 通道的 responses 端点 |
| Claude Code | `/v1/messages` | Go 通道的 Anthropic 端点 |

**模型清单**：`GET http://127.0.0.1:8791/v1/models` 退 200，返回 `{"object":"list","data":[…]}`，
另开别名 `/models`（同 200）防不同客户端路径习惯不同。清单里的 id 全部取自 `plans.py` 的 `CAP_GO` 键
（`plans.model_ids()`），**别处不再另立一份模型表**。拉清单这一路不写账本。

**每个客户端都加两个头**：

| 头 | 放什么 | 作用 |
|---|---|---|
| `x-task-id` | 任务号，如 `TASK-20261105-01` | 这笔账挂到哪个任务名下 |
| `x-ai-router-client` | 客户端自己的名字，如 `dsh` | 账本「客户端」栏分开记账（OpenCode 与 DSH 同走 chat 协议，靠这个才分得开） |

**四处现成写法**（本机实测各出一次真实回答，账本各落一笔）：

- OpenCode：`~/.config/opencode/opencode.json` 的 provider 里把 `baseURL` 指 `http://127.0.0.1:8791/v1`，
  加 `headers: {"x-task-id": "..."}`；模型表按清单重排。

## 十四、三个池，依次兜底

管家现在管三个池（同一个订阅可以拆成好几个池，这三个是三个不同的去处）：

| 池 | 去处 | 钱怎么算 | 什么时候算能用 |
|---|---|---|---|
| 本地 Qwen | 本机 8080 口的 Qwen3.8-27B | 不花钱 | 那个口上有服务 |
| 百炼／Token Plan | 阿里云百炼（两个入口，同一份 Credits） | 按量计费 | 环境变量 TOKEN_PLAN_API_KEY 设了 |
| OpenCode Go | opencode.ai 的 Go 通道 | 每模型美元封顶，外加 5 小时／周／月三层窗口；月额度用尽后改走充值余额按量计费 | 密钥设了，且（订阅额度还有且该模型没打满封顶、三层窗口没烧穿）或（充值余额还有钱） |

**兜底顺序是：本地 → 百炼／Token Plan → Go。**
理由：本地不花钱；百炼按量、封顶在 Credits 上；Go 最贵——它按模型算美元封顶，还叠三层窗口，
最容易被限速。所以能往前面的池走，就不占 Go 的额度。

**点名的模型走哪个池**：你点名一个模型，它先去找那个模型本来属于的池；
那个池接不了才按上面的顺序往后退。写 `auto` 则是从 Go 的清单里挑最省的一个。

**Go 正在走充值余额时，规矩变一条（2026-11-06 法师定）**：
Go 的月度总额度用尽之后，上游会自动改按充值余额计费。这时候每一笔都在烧那 10 美元的余额，
所以管家把**百炼／Token Plan 提到 Go 前面**：只要百炼那边有等价模型，就先走百炼（吃 Credits，不烧美元），
三个池里百炼也接不了时，才轮到 Go。**点名的模型仍按点名语义走**——
只属于 Go 池的名字（比如 mimo-v2.6-flash）点了就是走 Go，这一条没变。

**协议的硬限制**：本地和百炼两个池只说 OpenAI 兼容的「对话」这一种话。
客户端若打的是 Codex 那种 responses 协议，或 Claude 那种 messages 协议，而选到了非 Go 池，
代理退 503 并写明「这条协议只有 OpenCode Go 支持」——它不偷偷换协议。

**三个池都接不了的时候**：退 503，并把每个池为什么接不了逐条说清楚
（Go 是额度用尽还是窗口烧穿、百炼是密钥没设还是没服务）。
这一笔虽然没花钱，**照样进审计日志**，行里写着「拒接」和是谁来撞墙——
不花钱的账也得能查。

## 十六、CPA（EasyCLIProxyAPI）现在怎么跟管家接

**为什么不能直连**：旧版 CPA（v8.0.47）不展开 api-key 里的环境变量占位符。
五种写法（`${VAR}`、`$VAR`、`env:VAR`、`%VAR%`、`{{VAR}}`）实测都被原样当成令牌发出去。
也就是说 CPA 要直连 Go，就得把 Go 密钥明文写进它的配置文件——那违反「上游密钥只从环境变量读」。

**改成经管家**：CPA 那一组的地址填管家本机口（8791），密钥那一栏填一个本机环回占位值。
这样 Go 密钥仍然只在管家的环境变量里；同时会话头、浏览器标识、按模型封顶、三层窗口限速
都在管家一处管，账本也只记一处。

**实测下来的三条 CPA 脾气**（本机跑出来的，不是查文档）：
- `keys` 必填，不填整个配置起不来。
- 组级 headers 会原样透传给上游（所以能让 CPA 带上「我是谁」这个头）。
- 同一个模型名在一组里只露一个别名，所以不同别名要分到不同组里。

**现在 CPA 露出来的五个名字**：止观-日常、止观-重活、deepseek-v4.1-flash-free、claude-haiku-5-5、glm-5.3。
它们背后的模型名写在 `plans.py` 的 `CPA_CHAIN` 里，那是唯一真值源；
自测会拿它跟真配置逐组比对，也检查真配置里没有明文上游密钥。

**一个还没解决的坑**：`gpt-6-astra` 这个名字全局没有——Go 的清单里没有它，
CPA 的 Codex 账号池也没注册它。DSH 那个「止观」provider 的模型表里还挂着它，那一条是死的。

## 十八、代理常驻与「孤儿实例」的查法

第十三节讲了怎么让代理常驻。补一个常见故障的查法：**任务在跑，客户端却连不上**。

**三步查**：
1. `schtasks /query /tn "AI调用管家代理" /v /fo list` 看「上次运行时间」。
2. `netstat -ano | findstr 8791` 看谁占着端口，记下 PID。
3. 查那个 PID 的启动时刻，跟第 1 步的时刻比。

**两个时刻一致** ⇒ 现在跑着的是计划任务带的那个实例，正常。
**不一致** ⇒ 有个孤儿实例（多半是哪个临时会话里手起的），它占着端口；
而计划任务设的是「不并行开第二个」，任务新起的实例会立刻退出——
这就是「任务明明在跑、代理却像是没起来」的最常见原因。

**2026-11-05 15:28 实测**：任务上次运行 2026-11-05 14:52:41；
占着 8791 的是 PID 13508，启动时刻 14:52:41。两者一致 ⇒ 现役实例是任务带的。

**清孤儿**：确认那个 PID 不是任务带的后，`taskkill /F /PID <PID>`，
再 `schtasks /run /tn "AI调用管家代理"` 让任务重新带一个。

**代理自己退了呢**：第十三节那个「AI调用管家看门狗」每 5 分钟探一次，掉了就拉回来。
上面这三步是给人手工查的，看门狗是自动的那一份。

## 二十一、Qoder 客户端窗口桥：让群里的 AI 能读本机文件（2026-11-06）

**这条是什么**：把 Qoder 客户端的无头工作进程包成一个 OpenAI 兼容接口，端口 8792。
它的**工作区就是本机项目目录**（`D:\Project\zhiguanAI`），**带 Read／Glob／Grep 工具**——
所以群里问一句「某目录下面有什么」，它能用工具查出来，而不是靠模型瞎猜。

**为什么非它不可**：百炼、Token Plan 那些是**云端模型**，看不见本机文件；
本地 Qwen 3.8-27B 是**本机模型但没有工具**，也读不了文件。
只有 Qoder 客户端的无头进程**既是本机、又能调工具**。

**怎么起**（两个双击件，都在 `AI调用管家` 目录）：

1. `设置Qoder访问令牌.cmd`——双击，把令牌粘进去（**输入不显示**）。
   令牌只写进用户级环境变量 `QODERCN_PERSONAL_ACCESS_TOKEN`，**不落盘、不进日志**。
   只需要设一次；**设完要重起一次桥**（已经开着的桥读不到新值）。
2. `启动Qoder窗口桥.cmd`——双击即起桥（8792），窗口别关。

**管家这一侧怎么指过去**：代理的池子里有一条「Qoder 客户端窗口」（127.0.0.1:8792）。
在模型栏写 `qoder-window` 就走它；写 auto 时它是**兜底之一**。
**注意**：代理和桥都得常驻，否则客户端一律 Connection error（见第十三节）。

**飞书群里怎么用**：两个机器人的模型都改成 `qoder-window` 了（改前都备份，
名字带 AI028 和时刻），DSH 重启后生效。群里 @机器人 问一句就能读本机文件。

**用的是哪个模型（2026-11-06 18:2x 起）**：**Qoder 客户端自己的 `MiniMax-M3.1-Flash`**。
桥默认就钉在这个模型上（`ai_router/qoder_bridge.py` 里的 `DEFAULT_MODEL`；
要改就设环境变量 `AI_ROUTER_QODER_MODEL`）。**换模型要重起桥**——
模型是在工作进程起来那一刻定下的，老进程还抱着旧模型。

**回话里带的是真模型名**：桥把工作进程真在用的模型名放进响应的 `model` 字段，
代理把它记进账本的「模型」栏和审计行。所以看账本就知道**是谁答的**，
不是只看到「qoder-window」这个路由键。

**这套要不要 Token Plan 的令牌**：**不要**。桥这一路用的是 **Qoder 客户端自己的访问令牌**
（用户级环境变量 `QODERCN_PERSONAL_ACCESS_TOKEN`），跟 Token Plan 那把（`sk-sp-` 开头）
是两把完全不同的钥匙；管家池表里「Qoder 客户端窗口」这一池**根本不带上游密钥**。
DSH 那边填的 `AI_ROUTER_TOKEN` 是**本机代理自己的门牌钥匙**，不是云端模型的钱包。

**流式**：客户端要 `stream=true` 时，桥回标准那套 SSE 块——**必须带 `finish_reason`
和 `data: [DONE]`**，少一样客户端会判「流没结束」并重试（DSH 之前就是卡在这里，
报 `Stream ended without finish_reason`，重试 5 次）。

**超时**：桥 300 秒、代理转发侧 360 秒。超时后**那个工作进程会被终止掉**，
下一轮换一个新的——不终止的话，那个哑掉的进程会被当成「还活着」而复用，
下一轮接着卡（实测过一轮挂死）。

**局限**：
- 桥只能起在工作区 `D:\Project\zhiguanAI` 里，读的是这个目录下的东西。
- 工具只有 Read／Glob／Grep；要改文件、写代码，得另说（可改 `AI_ROUTER_QODER_TOOLS`）。
- 引擎是本机的，不吃任何订阅额度；一个请求十几秒到一分钟很正常（首问含冷启动）。
- **令牌值不进任何日志**，窗口桥的报错信息也过一道遮罩。

**自查**：桥的健康接口 `http://127.0.0.1:8792/health` 报「就绪＝true、说明＝Qoder 客户端已登录」
就是好的；整条链的证据在审计日志里——`channel=qoder-window` 的行。
