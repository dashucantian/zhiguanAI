# 常驻任务意识层评估方案 v0 —— QwenPaw 与 OpenClaw（2026-09-22 · W3/AI-006）

> 缘起：法师 09-22 指示，调研 CoPaw/OpenClaw 类部署方案，**重点＝任务管理交互界面能否更友好人性化**；并明确核心需求＝"全天候任务意识"——①随时可进入任务的执行、分配和验收 ②随时可退回后台继续盯着。本方案只评估不动手，待法师裁定后实施。

## 一、需求定性：法师要的是"维那"，不是"聊天机器人"

把法师描述拆成工程语义，是三个能力：

| 能力 | 含义 | 现状 |
|---|---|---|
| **常驻意识** | 进程 7×24 后台运行，心里装着全部任务状态 | 部分有——千问工作助理的两个 cron 巡检（周一 08:30＋每日 20:00），但只在**这台电脑会话**里跑 |
| **随时进入** | 法师任意时刻发指令、查进度、验收结果，入口顺手 | 弱——必须坐到电脑前开千问窗口；手机够不着 |
| **随时退出＋不打扰** | 没事不吭声，有事按轻重报，报完退回后台 | 部分有——但"没事也发一轮"、无静默判据、无分级 |

**结论先行**：市面上没有一个现成 App 同时做到"界面友好＋任务意识＋不打扰"，但有两款开源工具把这三块都实现了，差距只在部署形态。**推荐评估 QwenPaw（阿里开源）为主、OpenClaw 为备**。

## 二、两个候选的界面与任务意识实况（均经 2026-09 检索核实）

### 1. QwenPaw（原 CoPaw，通义 AgentScope 团队，开源）

- **本机部署**：**Windows 原生支持**——官网 .exe 安装包（Tauri 桌面壳）或一行 PowerShell 脚本；本机 Web 控制台 `http://127.0.0.1:8088`。法师这台电脑直接可跑，无需虚拟化。
- **手机入口＝飞书**：扫码一键创建飞书应用并自动回填凭证（App ID/Secret 自动填充），之后**法师在手机上用飞书跟它说话即可**——查待办、派任务、收提醒，全在飞书聊天界面里，零新 App。⚠️ 其飞书通道 4 月曾出 WebSocket 假死 bug（#3331），**v1.1.1 起已修复**——部署时版本必须 ≥1.1.1 并列入验收项。
- **任务意识机制**：内置定时任务调度（循环任务＋日程任务，控制台可视化创建）＋心跳自检；官方定位即"AI 从聊天伙伴进化为主动干活的本地数字员工……定时推送与自检结果发至指定频道"。
- **记忆与人格**：ReMe 记忆系统（跨会话沉淀）＋ PROFILE.md 定义助理性格——**与项目已确认的"维那/虚拟禅堂"远期方向直接对接**：可以给它立一个维那人设，报事风格按寺规来。
- **模型接入**：需外接"大脑"——可接**本机 LM Studio 的 OpenAI 兼容接口**（Qwen3.8-27B，D22 已判可用）→ **全程离线、数据零出网**；也可接百炼云 API（能力更强，但内容会出网，须限定只过任务元数据）。

### 2. OpenClaw（MIT 开源，2026 全球最热个人助理项目）

- **界面最强项**：Control UI（本机 18789 端口）v2026.7.1 后已从"聊天页"改版为**工作区**——左栏会话管理（置顶/分组/归档）、右侧可拖拽分屏，**有独立后台任务面板**：跑着的子任务列表、失败带警示徽标、超时带时钟徽标——这正是"任务状态一目了然"的桌面形态，也是法师问的"界面友好"满分答案。
- **任务意识机制最地道**：Heartbeat 心跳——每 30 分钟读一份 `HEARTBEAT.md` 检查清单自主巡检，社区标准用法就是"**正常别烦我，只有异常才通过飞书报警**"；＋Cron 三模式（at/every/表达式）；＋任务完成即时唤醒推送（不必等下一轮心跳）；＋activeHours 可把主动消息限制在指定时段（深夜零打扰）。
- **弱点**：①Windows 须经 **WSL2** 运行——读写 D 盘项目文件要跨系统边界，运维复杂度上一个台阶；②系统级权限面大（文件/Shell/浏览器全开放），安全配置负担重；③热度数据各源严重打架（星标从 6.8 万到 295 万说法都有，⚠️单源待校验，不作选型依据）。

### 3. 对照小结

| 维度 | QwenPaw | OpenClaw |
|---|---|---|
| Windows 本机直跑 | ✅ 原生 | ⚠️ 需 WSL2 |
| 手机入口（飞书） | ✅ 一键扫码 | ⚠️ 可接但手动配置 |
| 桌面任务面板 | ⚠️ 控制台列表级 | ✅ 工作区＋任务徽标（最强） |
| 不打扰机制 | ✅ 定时任务＋静默可控 | ✅ 心跳清单＋activeHours＋异常才报 |
| 记忆/人设 | ✅ ReMe＋PROFILE.md | ✅ 跨会话记忆 |
| 离线大脑 | ✅ 可接本机 LM Studio | ✅ 可接 Ollama 等 |
| 运维负担 | 低 | 中-高 |

## 三、建议架构：不替代、只补层（守"统一架构不造冗余"）

**定位一句话：千问工作助理诸窗口＝做工的"单沙"，新工具＝守时间的"维那"——它只传话、报时、盯状态，不做判断、不改项目文件。**

```
法师（手机飞书/电脑）
   ↕ ①提醒·报事·轻指令            ↕ ②验收·看板（细）
QwenPaw 常驻进程（本机 8088 控制台＋飞书通道）
   ↕ ③信箱协议（它唯一允许碰的目录）
01_项目管理\inbox\   ←派单：飞书说一句→落一条 md
01_项目管理\outbox\  ←回报：千问窗口办完→落一条→QwenPaw 整点汇总推给法师
   ↕ ④干活
千问工作助理 W1~W4 窗口（现有体系原样，含两个 cron 巡检）
```

- **执行/分配/验收闭环**＝法师飞书发"给 W1 加一条：××"→QwenPaw 落 inbox→法师开千问窗口（或次日 cron 巡检发现新单）→办理→结果落 outbox→QwenPaw 下一轮检查点推"验收单"到飞书。全程**任务元数据**（编号/标题/卡点一句话），不碰内容。
- **不打扰三判据**：①无新待裁项＝当日零消息（只有 20:00 静默检查动作本身不推送）；②有＝一条汇总，紧急置顶其余合并；③深夜 22:00–7:00 一律不推（除非法师自设例外）。
- **与现有两 cron 的关系**＝二选一，防双头巡检：或 QwenPaw 接管提醒（千问 cron 停用），或 QwenPaw 只做手机入口、提醒仍归千问 cron。**建议前者**（一个调度中心）。
- **红线继承**：开示转写、学员数据、脑电原始数据的路径**不进 QwenPaw 可读范围**；它若走云端模型，只允许过 inbox/outbox 的任务元数据文字。巡检隐私纪律原样平移。

## 五、请法师裁定的四个问题

1. **路线**：按"QwenPaw 为主、OpenClaw 留作 P3 面板备选"走？还是先试 OpenClaw？或维持现状不上新工具（手机入口需求不强时，现状两处 cron＋看板已够用）？

### A.3 公道话

正面案例省的时间是真的，但**成功场景（定时早报、监控汇总、纪要整理）与我们现有 cron 巡检＋飞书看板高度重合**——已通过千问工作助理＋两个定时任务覆盖其价值大半，且零新增运维面。36氪那句冷水对本项目成立："省下来的时间，不够配置它花的时间。"

### A.4 改判与选项更新

- **OpenClaw 移出备选**（v0 的"P3 面板备选"定位一并降级）。
- **新增第三条路（零新常驻）**：**飞书 CLI（larksuite/cli，官方、MIT、2026-03 开源，200+ 命令、23 个 Agent Skills）**——嵌入式而非接管式、权限跟企业管控走、与项目**已在用**的飞书看板直接咬合；"任务意识层"或可用"现有窗口＋飞书 CLI＋现有 cron"实现，手机开飞书即可看与派。
- **待裁①选项更新**：**甲** QwenPaw 7 天试点／**乙** 飞书 CLI 轻路线（近零成本先评，不引入新常驻）／**丙** 暂不上。**建议乙先行、甲随后可选。**
- QwenPaw 反向核查：本轮未见大规模事故/崩盘报道；但社区规模远小于 OpenClaw，**反面证据也更少**——"先查后装、7 天试用"前置不变。
