## 八、已知坑（省新窗半天）

| 坑 | 事实与处置 |
|---|---|
| `browser-use` 截图 | 本环境恒报 `NATIVE_BROWSER_VIEWPORT_UNAVAILABLE`（viewport 0×0）。`take_snapshot`＋`evaluate_script` 可用；报告须明写"像素未验" |
| Git Bash 控制台 | UTF-8 被按 GBK 显示，中文乱码**不代表文件坏**。核验一律走 Grep／Read 工具或 Python 读回 |
| `evaluate_script` 15 秒超时 | 别在一个脚本里 sleep 超过 ~12 秒，拆成"触发"＋"读回"两次 |
| PS WinRT OCR | ① 必须用限定语法 `[Ns.Type, Ns, ContentType=WindowsRuntime]` 投影，裸 `[Ns.Type]` 报找不到类型；② **`OcrLine` 没有 `BoundingRect`**，坐标只在 `OcrWord`；③ `.ps1` 正文一律 ASCII（PS5.1 读无 BOM UTF-8 会读错非 ASCII） |
| OCR 中文 | 字间插空格（`学 员`），且会把「手机」读成「手几」→ **匹配前压平空白**，并知会漏面 |
| CSS 皮肤 | 别在 `background` 简写末层放 `var()`，别对渐变设 `transition:background`（KZ-1007-W3d） |
| 自测断言 | 字面断言前**必剥注释**，且**必附反证**（规约 §五.8） |
| git 子进程 | 读 git 输出禁 `text=True`（按 GBK 解码会崩），改 `capture_output=True` 后手动 `decode('utf-8','replace')` |
| 进 git 的文本 | 禁 PowerShell 写命令（必带 BOM，坑 010-W）；用 Write 工具或 heredoc |
| **收口检查门 4** | 四窗共用脚本按 GBK 解 git 的 UTF-8 输出，可**随机吞掉换行**致 trailer 明明在却报缺（`KZ-1007-W3e`，候裁未修）。判据：先用 Python 直读 `%B` 原始字节判 `(?m)^Model: `，True 即为闸门误报，走脚本自述的豁免路径写理由，**不得为此改提交信息** |
| **跨实现复现** | 换解码库≠换实现。本窗用 Python `decode('gbk','replace')` 替 .NET 复现门 4，结论与 PS 实测**方向相反**（Python 保留换行重处理，.NET 连对吞掉）→ 取证须在出问题那一侧跑 |
