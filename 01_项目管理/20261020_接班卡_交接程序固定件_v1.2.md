## §二 接班首动作（顺序写死）
1. 核根路径与 sha256 锚（单⓪：同目录 `.sha256`；本单已入库则加 `git rev-parse HEAD:<路径>` 作第二锚）→ 不符＝红停。
2. 读单正本（仓库内那份，不是附件缓存、不是对话粘贴的）。
3. 读本卡。
4. 复述三点（§三.1）→ 四查（§三.2）→ 填单⑩ → 落回执 → 才开工。

## §三 复述与四查

**1. 三分钟复述（接班窗做，结论进回执，不铺进单⑩）**
- 我接的是……／现在第一件事是……／我不能碰的是……

**2. 四查（各留一行结论＝对上／不对上，附一句依据）**

- **查库**：`git log -1 --format='%h %ci %s'`、`git status --short`、`git rev-list --count @{u}..HEAD`、`git diff --cached --stat`，四样裸跑现取。
  - ⚠ **输出捕获不可靠**：`|` 与 `>` 报 `Access denied`；`@()` 赋值**静默返回空且不报错**（假零，坑 047 同族）。计数一律取直跑全文。
  - ⚠ **行数计数禁用 `Get-Content`**：本机按 GBK 解码，实测把 74 行算成 45 行。用 `[System.IO.File]::ReadAllText()` ＋数 `\n`。
- **查盘**：核对象＝单④ 点名的件。④ 未点名任何件＝本查记**不对上**；点名了但字节／mtime 不符＝也不对上。另核一笔：目录件数与单⑨"出具后盘面变化"是否一致。
- **查信**：`01_项目管理\信箱\` 按 mtime 扫**最新三件**，基线＝这三件本身（不预设应有哪几件），判两样：命名合规、铁律合规。
  - 命名：`YYYYMMDD-<窗>-<会话号>-致<X>/复<X>_<主题>_v1.md`；`复` 与 `致` 同权；`巡检日志-<窗>-<会话号>.txt` 非函体，沿用旧名。
  - 铁律（`信箱\README.md`）：只许编号·标题·一句话卡点·状态·链接；录音转写／学员个人信息／脑电原始数据／代码正文不入。
  - **认领判据**：以 `outbox\` 有无同名配对件为准，**不看** `> 认领：`（实测反例：`inbox\20260928-ZG074.md`）。
  - 现势：`inbox\` 最新停在 2026-10-01；派单与协作实际走 `engine\`。
- **搜裁**：`01_项目管理\待裁单.md` 现读（页头＋各节标题够用）；报两把尺（页头候字条数／列项总数）；`00_当前状态.md` 只互挂、不作正源（坑 043 根因③）。

## §四 四个才算 ＋ 两条硬尺
1. 单在盘上（`.sha256` 或第二锚 git blob 对得上）
2. 复述对上
3. 四查输出对上（查盘无核对象＝不对上）
4. 回执落点按单⑩ 执行；单⑩ 未填则落 `01_项目管理\信箱\engine\`，且**不得判绿**
5. **页尺**：成单 ≤70 行、⑩ ≤12 行；超尺记"填不下"，灯号黄、不阻断。
   - **在途件 >5 时**：④ 页内点名 ≤5 件 ＋ 一行"清单件路径"；清单另件（参照 `20261020_W1-f7e223f6_在途25件清单_v1.md`），**不计入页尺**。不许用"填不下"当理由漏点名。
6. **两版 hash 与换行**：原 `<正本>.sha256` 不动（锚发放版）；填⑩ 后另写 `<正本>.filled.sha256`。
   - ⚠ 本仓 `core.autocrlf=true`：库内 LF、检出转 CRLF ⇒ **工作树 sha256 在重新检出后必变**，不是篡改。稳定锚用 `git rev-parse HEAD:<路径>`；两锚不一致时先判是否换行差异，再判篡改。

## §五 五条硬规矩（编号不动）
1. 单在盘上才算交出，口头说了不算
2. 读数带时刻与尺名，不带就是印象
3. 没验的写"未验"，不写成"已验"
4. 代裁不越权，亲裁事项先落待裁单
5. 复述对不上，交出窗先改单再交

## §六 补则三条
6. **程序不随单重发**：单每次重填，卡不动；改判据就改卡、升版本。
7. **读盘即出网**：本单内容进入对话前先读单②的许可；未许可只给脱敏摘要（路径＋编号＋灯号）。
8. **补签**：交出窗还在跑时，签认走回执内一行（交班后补）；未补签＝保持黄、不阻断；不得因"找不到人签"把单判绿。**关窗最后一动作＝在回执写"本窗停用：<时刻>｜未验面随窗终止：…"**，缺此行不得报"已停用"。

## §七 兜底与容器
- 交接容器＝`01_项目管理\交接试跑_20261019\Qoder\<窗号>\`，一窗一盒；**盒外只读**。
- **盒内第二类件＝待提交单**（见 `Qoder\c5d442aa\` 样例）：四样齐才办——①路径 ②字节与 sha256 全值 ③预计算 `git hash-object` ④分档建议；DSH 办完在同目录写回执。
- ⚠ `_*.md` 被 `.gitignore:59` 忽略：给窗、给法师的件**不许下划线开头**。
- 兜底三档：甲＝能读能写（全流程）；乙＝能读不能写（代录，署名写"代录：X"）；丙＝只能对话（脱敏摘要，连编号都不许出＝红停）。
- **读不到单**：红停，不按记忆开工。**无 git**：三态写"未取＋原因"，不得留空。
