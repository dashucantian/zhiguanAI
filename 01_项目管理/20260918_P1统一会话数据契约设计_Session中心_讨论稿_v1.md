# P1 统一会话数据契约（Session 中心）设计 · 讨论稿 v1

## 〇、一句话定位

> **Session 对象不是新数据库，是「指向既有数据资产的会话级清单 ＋ 一条只追加的事件时间线」。**
> 数据本体（npz／报告／标注）全部留在原地；Session 契约只做三件事：**让一个会话的所有文件能被一次找到（清单）、让一个会话从"入座"到"复盘"的每一步都带时间与来源（事件流）、让控制台各页签与将来三个中心（Session／Case／AI 秘书）有同一个主键可挂（索引）**。

这与 GPT 方案"所有东西挂在同一个 Session 下面"的目标一致，但**拒绝**其中两个隐含做法：①不把所有数据复制进 Session 对象（红线5：不建平行路径；GPT 骨架图里 `eeg:{}`／`vr:{}` 的"内嵌"读法会造第二真相源）；②不把 Case／判语改造成纯数据结构推翻既有文档体系（那是 W2 的资产，判语卡与案例卡已有文体；Session 只挂**指针**）。

## 一、对齐表：GPT 方案 × 既有载体 × 本契约补什么

| GPT 方案（Session 中心） | 本项目既有载体（实测） | 差距 | 本契约补什么 |
|---|---|---|---|
| Session 统一对象 | Zen-ID（`ZEN-YYYYMMDD-Pxxx-Snn`，永不复用）＋ npz `meta`（10 字段）＋ `session_registry.csv`（**仅 6 列**） | **无会话级清单**：一个会话的 npz／report.html／device_info.json／session_note.txt／qc.json 只能靠命名约定与目录扫描凑齐 | `session_manifest.json`：一次性写成的清单（含文件清单＋设备＋信号链＋代码/配置版本＋同意书版本） |
| Session ├─ EEG | npz（eeg＋eeg_pre_filter＋timestamps＋meta；**S1 修复后归档完整**） | 无 | manifest 记指针与 `signal_chain`，数据原地不动 |
| Session ├─ VR | VR 状态只存在于渲染期，**会话内不留痕**（A6：四状态无共同载体） | 体验与数据无法对齐 | `state` 事件：把 VR 的 S.a／报告分类器标签／奖励态／五相 zx_phase **四者并排记录**，各带来源与弃权 |
| Session ├─ Annotation | `05_annotation/` **空目录**；标注规范 V1 在案（三年战略：受试者自评→操作员事件→禅师独立判断→第二标注者→脑电质量→仲裁→置信度与争议） | 无标注事件载体、无多标注者合并视图 | `annotation`／`review`／`ruling` 三类事件（对齐证据结构，只存文本与时间区间，不搬数据） |
| Session ├─ AI Summary | 无（控制台零 AI 接口；判语：AI 协助整理、**不代禅师标签**） | 无 | 预留 `ai_summary` 事件类型，**默认不启用**（待裁定） |
| Session ├─ Case／KZ／判语关联 | 案例卡（md）／KZ 台账／判语卡（md）——文档体系完整但**与数据无指针** | 案例卡引不到具体时间区间 | `case_link`／`ruling_link` 事件：挂指针，不改文档 |
| GPT 第一层"实践验证"（体验 1-10 分） | 会话字段仅 `pre_state`／`post_state`（自由文本）、`contact_quality` | 无结构化自评、无不良反应字段（判语011③ 已立而未落地） | `experience` 事件＋`adverse` 字段——**维度与措辞涉义理，待法师勘定** |
| GPT 第三层"知识治理" | 判语／红线／KZ 在文档层 | 判语未进入系统行为（GPT 卡点3） | 契约只提供 `ruling` 事件可被规则引擎消费；**规则引擎本身待"控制台定位"裁定后再说** |

**读法**：GPT 方案缺的不是想象力，是"指针层"——本契约的全部工作就是**在文档与数据之间补一层最小指针与事件流**，不做数据仓库、不做知识图谱。

## 二、设计原则（七条：六条引自既有判决＋P7 为 GPT 复审新增，本文不新立法）

| # | 原则 | 出处 |
|---|---|---|
| P1 | **指针不复制**：Session 对象只含路径与摘要，不含数据本体；任何字段要么来自数据自述（npz meta），要么标注来源，**不转录** | 红线5（不建平行路径）；判语011（自述不可信→须可核） |
| P2 | **追加不改写**：`session_events.jsonl` 只追加、不修改不删除；manifest 一次写成、事后只"补登记"（追加修正事件），历史永不回改 | 三年战略关口B；BCI2000 自描述记录；KZ-019 教训（自述失实的防复发） |
| P3 | **单一主键**：Zen-ID 永不复用；文件命名偏差（`local_*.npz`）只在采集端暂存期存在，入契约即归一 | 三年战略；D26 |
| P4 | **schema 版本化＋显式迁移**：每份 manifest/events 首行 `schema_version`；改结构必须写迁移而非静默兼容 | 关口B；FieldTrip `ft_checkconfig`／HA config-entry 迁移（全球调查 §4.3） |
| P5 | **每个字段标 `kind`**：`measured`（设备测）／`self_report`（受试者自评）／`derived`（算法导出）／`annotated`（人标注）／`ruled`（法师/禅师裁定）——**五类互不冒充** | 红线9（不得把缺失传感器伪装成生理测量）；判语009（镜子非训练器）；KZ-019（自述≠测量） |
| P6 | **弃权是一等值**：凡 `derived`／`annotated` 字段必须支持 `undecidable`（不可判定），且不得被界面当"确定结论"渲染 | 关口D；判语009；20260917 讨论稿 S4 |
| P7 | **Session 最小主义**（GPT 复审全采）：manifest 只允许三类字段——**定位**（我是谁／何时／何种协议）、**追溯**（schema/代码/阈值/同意书版本）、**指针**（文件在哪）；**禁止**分析结果、解释结果、知识结果——那些进事件流或消费方，不进清单 | GPT 复审（09-18）：防 Session 膨胀重演 registry 旧病 |

## 三、契约本体（三件套，附骨架）

### 3.1 `session_manifest.json` —— 会话清单（一次性写成）

落盘：与归档会话同目录（建议 `02_raw/<ZEN-ID>/session_manifest.json`；采集端暂存期可先写同名草稿，入库时校验）。骨架：

```json
{
  "schema_version": "1.0",
  "session_id": "ZEN-20260911-P001-S13",
  "participant_id": "P001",
  "scene": "monitor",
  "consent_version": "<待裁：同意书版本必填>",
  "protocol": "5min基线+45-60min正式段（三年战略口径；当前实际采集时长见 duration）",
  "files": {
    "eeg_npz": "eeg_raw.npz",
    "report_html": "report.html",
    "device_info": "device_info.json",
    "session_note": "session_note.txt"
  },
  "device": {"model": "Muse S", "sfreq": 256.0, "channels": ["TP9","AF7","AF8","TP10"]},
  "signal_chain": {"chain_tag": "v12_bp_1_40", "pre_filter_available": true},
  "software": {"console_commit": "<git rev-parse --short HEAD>", "python": "3.12.10"},
  "config_snapshot": "<experiment_config 快照路径或哈希>",
  "qc": {"version": "0.1", "thresholds": {"min_duration_s": 30.0, "max_packet_loss": 0.20, "min_clean_ratio": 0.60}},
  "labels": ["zx_phase"]
}
```

要点：①**`consent_version` 必填待裁**——三年战略关口A 要求"同意书版本"可追溯，当前采集流程没有这个字段；②`software.console_commit` 落代码版本（关口B 的直接载体）；③`qc.thresholds` 落当时阈值（讨论稿"口径-1"：质检结果必须能回答"哪个阈值版本产生的"）。

### 3.2 `session_events.jsonl` —— 只追加事件流

每行一个事件，统一信封：

```json
{"schema_version":"1.0","ts":"2026-09-11T23:23:00+08:00",
 "type":"baseline_locked","actor":"system","kind":"derived",
 "payload":{"alpha_db":21.4},"note":""}
```

**事件类型枚举（首版）**：

| type | actor | kind | payload 要点 | 消费方（前瞻） |
|---|---|---|---|---|
| `created` | system | ruled | 预登记信息（若走了 SOP V0.2 先登记） | 驾驶舱"样本"卡 |
| `started` | operator | measured | 数据源、模式（监测/闭环）、scene | 全 |
| `baseline_locked` | system | derived | alpha 基线 dB（闭环路径） | 复盘台 |
| `state` | system | derived | **四状态并排**（见 §3.3） | 复盘台（A6 的唯一解） |
| `experience` | practitioner | self_report | 自评维度与分值（维度待裁） | 复盘台 |
| `adverse` | practitioner | self_report | 不良反应自由文本（判语011③） | 复盘台／伦理 |
| `qc_done` | system | derived | qc.json 指针＋阈值版本 | 驾驶舱"质量"卡 |
| `saved` | system | measured | npz/report 路径 | 全 |
| `ingested` | operator | ruled | Zen-ID 分配、归档位置、pre_filter_archived | 驾驶舱 |
| `annotation` | annotator | annotated | 起止时间区间＋标签＋置信度＋**弃权** | 标注台 |
| `review` | reviewer | annotated | 同意/冲突/独立判断 | 标注台（关口C） |
| `ruling` | master/法师 | ruled | 仲裁结论＋争议原因 | 标注台／知识层 |
| `case_link` | system | ruled | 案例卡/判语/KZ 指针 | 案例中心 |
| `ai_summary` | ai | derived | 摘要文本（**默认不启用，待裁**） | AI 秘书中心 |
| `closed` | operator | measured | 结束与后自评 | 驾驶舱 |

### 3.3 `state` 事件：四状态对照（讨论稿 A6 的落点）

```json
{"type":"state","ts":"...","kind":"derived","payload":{
  "report_label":{"value":"冥想 Meditative","src":"report_generator.classify_state","confidence":"<无，待裁>","abstain":false},
  "vr_sa":{"value":0.42,"src":"vr_feedback.html ALGO 因果滚动分位","abstain":false},
  "reward":{"value":"maintain","src":"closedloop_controller.update","abstain":false},
  "zx_phase":{"value":["入","照"],"src":"muse_local_server.derive_zx_phase","abstain":false}
}}
```

要点：①四值**并排记录**，操作者与修习者看到的是同一条时间线——复盘时"法师说当时很安定"第一次能对上"当时的数"；②`confidence`／`abstain` 对 `report_label` 尤其重要（讨论稿 S4：当前「大脑状态：冥想」无置信度、无弃权档，与判语 009 冲突，**显示词待法师勘定**）；③**VR 是参与者不是中心**（GPT 复审全采）：Session 不"拥有"VR，只**记录 VR 产生过什么事件**——各值带 `src` 即止于此，不进 manifest；④`vr_sa` 目前只存在于 VR 页面内存，**契约落地后由前端/中继把周期值写回事件流**（前瞻实现，不属 P1a）。

### 3.4 标注事件与三年战略证据结构逐条对照

| 战略要求（§2.3） | 契约载体 |
|---|---|
| 受试者自评 | `experience`／`adverse`（kind=self_report） |
| 操作员事件记录 | `started`／`ingested`／任意 `note` 字段（kind=measured/ruled） |
| 禅师独立判断 | `annotation`（annotator=禅师，kind=annotated） |
| 第二标注者复核 | `review`（同意/冲突） |
| 脑电质量状态 | `qc_done`（kind=derived，含阈值版本） |
| 最终仲裁标签 | `ruling`（kind=ruled，含争议原因） |
| 置信度与争议说明 | `annotation.confidence`＋`review.conflict`＋`ruling.dispute` |

**边界**：AI 可协助整理标注文本（判语：不代禅师标签），故 `ai_summary` 与 `annotation` 分属两类事件，且后者 `annotator` 字段只接受人。

## 四、与既有结构的映射（逐字段，不重复造）

| 既有字段/文件 | 处置 | 理由 |
|---|---|---|
| npz `meta` 十字段（timestamp/sfreq/channels/device/samples/duration/signal_chain/scene/participant/zx_phase＋pre/post_state/note/contact_quality） | **全部保留不动**；manifest 只"指向＋摘要"，不转录（P1） | 数据自描述原地成立；转录即第二真相源 |
| `session_registry.csv` 6 列 | **两个选项待裁**：甲＝扩列（scene/consent_version/qc/qc_thresholds_version/annotation_state/manifest_path），须同步改 `console_server.py:118` 列白名单（**D26 教训**：CSV 加列会让控制台入库崩溃，需一并修并回归）；乙＝维持 6 列、新增第 7 列仅 `manifest_path` 指针，聚合查询走 manifest | 驾驶舱六卡要"从主索引聚合"，6 列不够（讨论稿 A7） |
| `device_info.json`／`session_note.txt`／`qc.json` | 保留为产物；manifest 收录其指针；`qc_done` 事件补阈值版本 | 不推翻既有工厂结构 |
| `report.html` | 保留；其"干净数据比例"目前被正则抓取（讨论稿口径-1），**P1 落地时顺手改 npz 实算**（另立批次） | 判据不得依赖模板文本 |
| 案例卡／判语卡／KZ 台账 | **文档体系不动**；契约只加 `case_link`／`ruling_link` 指针（GPT"Case 就是数据结构"**不采纳其强形式**） | W2 资产；文体本身有义理（判语/案例是"灯录/公案"形态） |

## 五、控制台消费面（P2 前瞻，只列需求）

- **驾驶舱六卡**（样本/质量/标注/模型/伦理/进度）＝registry（或指针）＋`qc_done`＋`annotation`＋`consent_version` 聚合——每卡**每个数字可点进源文件**（P1 契约是其唯一数据源）。
- **标注台**＝沿 `state`/`experience` 时间线叠加 `annotation`/`review`/`ruling` 轨道（关口C："分歧发生在哪一段"由事件区间直接回答）。
- **复盘台**＝同一时间轴的 `experience`（自评）↔ `state`（四状态）↔ 视频/标注——**判语 009"镜子"的载体**。
- 全部为读接口（GET）；写入只有两类：采集端追加事件、标注端追加标注。

## 六、出口与互操作（P3 前瞻）

- **BIDS-EEG 导出**：manifest＋events → `participants.tsv`／`*_eeg.json`／`events.tsv` 的一对一映射表随 P3 出（本稿不展开）。
- **LSL（D31 标准总线）**：将来采集端若走 LSL，`session_events` 记录 `stream_info`（name/type/source_id/uid）作为 `started` 事件的扩展字段——契约信封已预留，**不现在做**。
