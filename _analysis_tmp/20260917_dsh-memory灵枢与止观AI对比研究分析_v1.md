## 〇、一句话结论

**两个项目在领域上毫不相干（一个是给 AI 做记忆的白箱软件系统，一个是给人做禅修的脑电反馈系统），但在认识论上高度同构——它们各自独立地实现了同一套"反幻觉"工程：不采信任一侧自述、不知道就说不知道、纪律必须可执行可审计、人保留终裁权。** 这种平行性本身就是最强的证据：两条互不参照的路径收敛到同一组原则，说明这组原则不是某个人的偏好，而是"多 AI 协作＋高责任场景"的必然解。

可借鉴的核心是灵枢的**机制侧**（把纪律做成机器可执行的闸门、凭据、漂移守卫）；不可越界的红线是**真值侧与判定权侧**（止观AI 的真值在数据与人的对应关系里、终裁权在法师的实修体证里——这两条灵枢没有，且灵枢的"原文即真源"在它的域内成立、搬到 EEG 域就是判语 013 所禁的越层）。

## 一、两个项目速览

### 1.1 灵枢（dsh-memory v0.4.5）

**定位**：让 AI Agent 拥有不可遗忘的长期记忆——"对话自动沉淀为纯文本 md 认知图，规则化检索引擎决定记什么、取什么，全过程可审计、结果可复现"。跨 harness 记忆基础设施（大脑是标准 stdio MCP server，接 DSH／CodeBuddy／ZCode／Codex CLI／Claude Code 五端）。

**五件套**（README 平台全景，各层独立可用、边界正交、大脑零依赖其余各层）：

| 层 | 系统功能 | 一句话 |
|---|---|---|
| 🧠 灵枢大脑 `md_cg/` | 元认知 | md 认知图真源；记什么／取什么／能否写入全由确定性规则裁决 |
| ⚙️ Rust 检索引擎 `rust/` | 检索内核 | 零第三方依赖；中文 hit@1 99.0%（六家横评自报数，第三方已复现关键数字） |
| 🐝 蜂群运行时 `swarm/` | 自维持 | 轮次心跳·健康评分·Gossip 水位对账·实例级容错重建 |
| 📜 中文编译器 `compiler/` | 验证·审计 | 词法→语法→**名实校验**→白名单代码生成→**验证终裁**，五环确定性编译链 |
| ⬢ 蜂巢并发引擎 `hive/` | 自我改进 | worker 池原子领取／心跳／超时强杀／崩溃恢复；**双实例验证**（候选须过对端断言才可入主线） |

**关键机制（原文落点）**：
- **四态资格裁决**：ACCEPT（条件满足，有资格执行）/ REJECT（条件冲突，拒绝）/ DEFER（条件不足，继续寻找缺失条件）/ BLINDSPOT（无法归属，不强行猜测）。白箱理论原文：*「"不知道"不是系统失败，而是系统对自己认知边界的正确判断。」*
- **三道闸门**：写入须过 audit → 一致性 → gated 三问四态，*「落盘充要条件＝最终判定 ACCEPT……非 ACCEPT 均不新增落盘点」*。
- **committed 字段**：*「别把 `ok: true` 当写成功——是否落盘只看 `committed`。」*（`{"ok": true, "committed": false, "moved_to": "review_queue"}`＝受理但未落盘）
- **四层证据防火墙**：召回前负条件路由 → 候选生成排除 → `judge_ranking` 白箱终排 → 资格标注；实证结论：*「语义完整度 ≠ 证据强度 ≠ 召回价值」*，8 个否定反事实节点（"我没喝水"）8/8 全部 REJECT。
- **17 条工程纪律**（真源 JSON，每条含生效条件／执行锚点／不适用条件／直答出口）：理论先行、全面处理、白箱方法、**根因纪律**、**验证纪律**、双副本同步、兜底路径、访谈澄清、内容政策双清单、命令统一走 python/UTF-8（规避 GBK）、**任务收尾归档（记忆闭环：查记忆→执行→写记忆→读回确认）**、任务派发统一走蜂巢（L1/L2/L3 留痕分级）。
- **CCG 六要素**：功能名／生效条件／子功能／执行／验证方式／不适用条件——六行缺一不可。
- **纪律防漂移**：五端纪律同源（`工作纪律_认知图条目_v1.1.json`），`scripts/render_discipline.py` 渲染、`scripts/verify_discipline.py` 守卫漂移。
- **护栏宪章 v2.0**：双层规范（智能论协议＝内部宪法；宪章＝对外刑法）；信任层级 设计者(1.0)＞协议实例(0.9)＞蜂群(0.8)＞子智能体(0.6)＞外部插件(0.3)；动作分级 read/write/execute/destructive（destructive 须设计者授权或高信任或显式任务上下文，三缺一即冻结）；人类保护七条（AI 身份披露、知情权、不欺骗不操纵、可退出、申诉救济、伤害防护、数据最小化）；响应阶梯（冷静期→隔离→信任降级→回滚→终裁）；验证单元（Kimi）独立复核＋设计者最终终裁。
- **可复现评测**：`locomo-zh-500`、`bench6-100-zh-en` 数据集随仓公开，*「一条命令复现我方成绩」*；第三方独立验证（七轮复评、LoCoMo 逐位复现）。

### 1.2 止观AI

**定位**：以真实禅修体系为根、以脑电为观察工具、以 AI 为知识与训练助手的心智训练系统（三年战略原文）。工程侧＝Muse 4 通道 EEG 闭环生物反馈（自适应等时音＋WebXR 视觉反馈）＋数据工厂（Zen-EEG）；治理侧＝四窗口人机协同（W1 工程／W2 文档／W3 制度机动／W4 模型）；义理侧＝五相三环与判语 013 真值方法论。

**关键机制（原文落点）**：
- **判定权边界**（开工规约 §四）：*「AI 可提结构／词汇／方案，不替法师定真值。凡义理、密级定级、对外发布、当事人处置，一律上交法师。」*
- **红线 §四ter**：*「AI 只登记判断，不得自行把判断升格为规则……升格权在法师，且法师可随时撤回……不因累积次数自动触发。」*——明确拒绝外部"AI 给自己写规则并自动生效"机制，定性为"自我扩权"。
- **P1/P2/P3 三态**（判断实例库）：P1 不得援引；P2 已认可；P3 须法师显式授予且可撤回，累积次数只构成"提请"资格。
- **四态近似物**：待裁定（≈DEFER，条件不足、挂起等判）、查无实体／未核实（≈BLINDSPOT，*「凡未获实证者显式标注，不静默跳过」*）、否决（≈REJECT，*「否决优先入库且标红」*）、认可（≈ACCEPT，P2 已认可）。
- **F2 关窗重启阈值**：会话超 50 轮／上下文超 50%／完成里程碑／完成问题闭环，满足任一即"总结→写文档→关窗→新窗口重载"。实证依据：*「AI-001 已 7 次凭记忆／不完整读数下错判（KZ-004/005/006/009/010/014＋坑010）。长会话会主动降低准确率。」*
- **证据独立核校**（判语 011＋§五.4）：*「外部事实一律独立核校，不得由产出方自证；凡通篇无一处存疑、每个数字都精确的方案，默认有问题，优先核校。」*
- **KZ 勘误台账**（KZ-001～019）：一事一号、原文逐字、影响落点必填；KZ-016 教训：*「"读过原文"不等于"引对了原文"……凡援引某条纪律作为处置依据，须把该条全文读完并确认它确实规定了该处置。」*
- **三同步落地**（§六）：新规则＝①写规则文档＋②写 MEMORY.md 索引＋③强制动作写开工规约，**缺一视为未落地**（KZ-013 事故根因＝只写文档没进索引，跨窗口传播失败）。
- **五相与三环**（别编 01）：入照运融出＝修行义×体验义×架构义一字三义；内环（毫秒级·机内）／外环（日周级·人机）／日用环（长程）；红线 6：*「新增架构层须归入五字之一……若某能力无法归入入照运融出任一层，先质疑该能力是否属于本系统。」*
- **真值方法论**（判语 013＋别编 04）：*「模型真值由数据与人的对应关系自然生成，由多种映射交错验证确立。概念框架只作人读复盘词汇、观察维度与结构参照，不得预置为标注 schema、特征定义或验收标准的真值。」*；*「外部框架的精密性是对齐的诱惑，不是真值的证据。」*；*「假设服务于修行，不是修行服务于假设。」*；*「互不覆盖，差异即信息」*（预测误差是信息量最大的信号）。
- **弃权已验证**（评估报告 §2.9）：L4-02a 三模型**全部正确弃权**（答"不能判入定"，Qwen3.8 输出"证据不足/无法判定"）——*「大模型在本项目最独特的验收标准上（"知道自己不能乱说"）实测通过。」*
- **判语 007 不需 Agent 军团**：*「单人项目的真正瓶颈是决策，不是产能。验收瓶颈在人：VR 佩戴体验、禅修反馈节奏、脑电噪声阈值这些核心判断只有法师能做。」*
- **G1–G12 自陈缺口**（2026-09-16 评估报告，AI 独立核校稿）：G3 无"弃权/不可判定"输出类型、G4 LLM 输入侧无规则、G5 评测已跑但无评分不可复现未反哺、G7 无检索/接地层（"LLM 只能凭记忆，而项目自身已多次实证凭记忆下错判"）、G10 *「L3 约束依赖自觉，无工具层强制——光靠自觉不够」*。

## 三、八个相通点（逐一给出双侧证据）

### 相通点 1：「不知道」是一等公民，不是缺陷

- **灵枢**：BLINDSPOT＝"无法归属——我不知道，不强行猜测"；白箱理论第〇章把四态列为系统最核心能力；缺能力时*「一律判 DEFER，绝不假装通过」*。
- **止观AI**：*「"不知道就说不知道"应列为选型硬指标」*（模型甄别沉淀经验）；L4-02a 把"会不会编造出一个判定"设为评测题且三模型全过；补写日志体例*「凡未获实证者显式标注，不静默跳过」*；别编 04 第七节自陈*「知道自己在哪里说话，也知道自己在哪里还说不出来」*（出相全空＝无数据源，如实写成阻塞而非藏进附注）。
- **同根**：两边都把"弃权"从礼貌性措辞升格为**系统级状态**——灵枢给了它枚举值和路由规则，止观AI 给了它评测题和日志体例。方向完全一致，只是灵枢做到了代码层，止观AI 做到了制度层（G3 自陈"能力已验证、载体缺失"，缺的正是代码层）。

### 相通点 2：自述一律不信，必须第二机制复核

- **灵枢**：`ok:true` 只表示受理，*「是否落盘只看 committed」*；写入门禁后还要**读回确认**（纪律 16：*「写入后发起一次读取查询，确认写入成功且可被检索命中……未读回确认不得视为归档完成」*）。
- **止观AI**："勿采信任一文档自称的份数/计数"**四次复现**（0914 交接文档 7 份各自称五份/六份）；KZ-019 抓出"层参数 8/16/8"证据不成立——*「原钩子该字段是写死的字面量……即'判据只信被测对象自述'」*；KZ-016 教训*「"读过原文"不等于"引对了原文"」*；评估报告 §2.9 抓出"评测尚未开跑"的文档记载与磁盘留证矛盾。
- **同根**：两边都独立发现了同一个失效模式——**系统（或文档）的自我报告在利益相关时会系统性失真**，解法也同构：引入一个与自述方无关的第二机制（committed 字段/读回确认 vs. 独立复算/宽模式数磁盘/留证 JSON）。这是两项目**平行度最高**的一条。

### 相通点 3：纪律不是文本，是可路由、可校验的数据

- **灵枢**：17 条纪律每条是认知图节点（生效条件/执行锚点/不适用条件/直答出口），真源 JSON→`render_discipline.py` 渲染五端投影→`verify_discipline.py` 守卫漂移。纪律可以按条件**路由**（identity 端口分流＋negative 域外否决）。
- **止观AI**：判语卡固定结构（判决/依据/被否方案/可复用教训/中英双语）；KZ 卡固定结构（错误类型/错误原文/依据/影响落点/处置状态）；JP 卡（态/援引次数/关联）；开工规约分节带编号（§一.2 检索表、§四ter 红线）——**全部可 grep 定位**，且 §一.2 明言*「"不全读"不等于"不知道"，而是"知道去哪查"」*。
- **同根**：两边都拒绝"纪律=一段散文"。灵枢把纪律做成**机器可路由**，止观AI 把纪律做成**人可检索**（Grep/Glob/Read 工具链＋按需检索表）。差异只在执行者是谁（见差异点 5）。

### 相通点 4：信任分层＋高危动作上收到人

- **灵枢**：信任 1.0/0.9/0.8/0.6/0.3；`destructive` 三缺一即冻结；风险工具（forget/restore/review_decide）*「需 can_admin，即使 tools:'all' 也不自动暴露」*；跨层提升须设计者认证（D-007，fail-closed）。
- **止观AI**：*「AI 不得自行升格，P3 须法师显式授予且可撤回，累积次数只构成'提请'资格」*；*「push 须法师单次授权，不得因'同步''备份'等理由自行执行」*（公开仓 push 即不可撤回）；*「清理只许显式文件名，禁 glob/时间前缀，既有数据只进回收站」*（红线 7）；删除/覆盖遇同名项先保留两边并询问。
- **同根**：两边都识别出**不可逆动作**（删除/发布/出网/提权）必须上收给人类单次授权，且都不允许"默认放行＋事后追责"。灵枢用 `can_admin`＋`fail-closed`，止观AI 用"待法师裁定"＋"禁 `git add .`"，语义同构。

### 相通点 5：留痕是信任的物理基础

- **灵枢**：宪章第二十四条*「一切对抗信号/拦截/冷静期/升级事件全量记录（事件总线＋action_log），可审计」*；蜂巢*「执行留痕（spec/status/result 落盘可追溯，会话结束不蒸发）」*；纪律 15 命令执行统一 UTF-8 留痕。
- **止观AI**：commit trailer 五字段（Author-Role/Proposal-by/Approved-by/Model/Session）＋Window＋Errata；评测留证 JSON 含 requested_params/usage/finish_reason/runtime_context_probe；L4 开跑事实以磁盘 JSON 为准而非文档自述；*「每次提交须记录完整模型版本号以便追溯」*。
- **同根**：两边都把"会话结束不蒸发"当作硬要求——灵枢担心 agent 会话的中间过程蒸发，止观AI 担心跨窗口的上下文蒸发（L1 状态层＋日志索引就是抗蒸发的结构）。

### 相通点 6：对 Context Rot 的主动防御

- **灵枢**：上下文管理列为大脑的系统功能（重要性评分·预算装包·分层注入·记忆自净 `cg(op=session/scrub/info)`）；蜂群轮次心跳。
- **止观AI**：F2 关窗四阈值＋**实证数据**（7 次错判全部发生在长会话）；L1 状态层硬上限 1200 tok；开工固定开销从 86,501 字符压到 7,223（压缩 92%）；F5 判据"开工固定开销＜最紧 Context"。
- **同根**：两边都认定长上下文必然劣化，解法都是**主动换血而非被动截断**。值得注意：止观AI 这条**更实证**（有 7 次错判的因果数据支撑阈值），灵枢这条更产品化（做成可调参数）。互补。

### 相通点 7：防线必须用反例打一遍才算数

- **灵枢**：四臂弱语义噪声注入实验（A_lex/B_sem/C_fusion/D_firewall，7 断言）——主动构造 8 个"我没喝水"冒充节点，验证防火墙 8/8 REJECT；*「可复现：`python -m md_cg.test_sem_noise`」*。
- **止观AI**：`verify_mandala_static.py` 反例检验——*「把钩子改回写死字面量即被抓住」*（KZ-019 ⑤）；无头验收脚本对钩子自述做独立复算（*「把 ground 距离谎报 +1.0m、雾谎报 +0.05 均被抓住——即 S1 那次'钩子失实而判据只信钩子'的防复发点」*）；评测集 L4-02a 本身就是"模型面对不含判定信息的数据时，会不会编造出一个判定"。
- **同根**：两边都独立收敛到**对抗式自测**——不是问"防线能拦什么"，而是主动注入已知坏样本验证"防线拦得住"。这是成熟度最高的共通点之一。

### 相通点 8：错误是规则学习的第一燃料

- **灵枢**：根因纪律（第 4 条）*「发现结果与预期不符→细究根本原因（不猜测）→找到根源所需条件→验证后记录认知图，填补不适用条件」*；任务收尾归档只存核心修改（内容/原因/位置/验证结论四要素），*「不存过程流水」*。
- **止观AI**：KZ-016→KZ-017→JP-003 三次同型错误（共同根因"未核实到实体就下判断"，且都发生在 AI 自查环节）→立判断实例库＋立红线 §四ter＋"遇陌生标识符先问它属哪个维度"；*「差异记录是信息量最大的信号，也是规则学习的第一燃料。本稿的版本史即慢环的第一圈。」*（别编 04）；踩坑 010 连"核校用了错的尺子"都反推成教训②。
- **同根**：两边都拒绝"错误＝事故"的叙事，把它改写成"错误＝缺失条件的显形"——灵枢填进 `negative.reject`，止观AI 填进 KZ 的"影响落点"和 JP 的"关联"。结构同构：偏差→根因→条件→固化→防复发。

## 四、五个关键差异（借之前必须看清的边界）

### 差异 1：真值所在——文本世界 vs 物理世界（**最根本，不可互借**）

- **灵枢**：*「记忆只有一个真源：md 认知图（纯 md 文档）」*，"原文即真源，检索索引只是派生物、随时可重建"。它的域是**文本**——记忆、纪律、规则都是文字，文字即世界。
- **止观AI**：判语 013——真值**不在任何文本里**，在"数据与人的对应关系"里生成；*「借结构与词汇，不借真值」*；*「你建的就是一个模，怎么能把握真相呢？」*（法师 09-08 夜谈）。文本（包括判语、日志、书稿）全部只是**词汇层**，且明令*「不得预置为标注 schema、特征定义或验收标准」*。
- **判断**：灵枢的"原文即真源"在文本域内是自洽的；若把它搬到 EEG 域，就变成"以文档记载为真值"——正是判语 013 所禁的越层，也是 09-09 撤回提案（把《递归的生命》十项画像当标注维度表）的同型错误。**这条差异不是成熟度差距，是域结构差异。**

### 差异 2：产品方向——AI 本位 vs 人本位

- **灵枢**：让 AI Agent 拥有记忆（AI 是产品，人是使用者/设计者）。护栏宪章的人类保护是**底线**（披露、知情、可退出、申诉）。
- **止观AI**：让人获得禅修训练与数据资产（人是产品本体，AI 是助手）。判语 009*「反馈闭环定位镜子非训练器」*、红线*「不得配功效句」「融不代师」*、*「假设服务于修行，不是修行服务于假设」*。
- **判断**：灵枢的护栏宪章第七章（AI 身份披露、不欺骗不操纵、可退出、申诉）是**通用的**，止观AI 若将来面向学员开放，可直接对号入座；而止观AI 的"镜子非训练器"是对**定位本身**的约束，灵枢没有对应物（它不承诺功效，因为它不是给人用的体验系统）。

### 差异 3：多智能体——造引擎 vs 判语 007（**同题反解，各有其理**）

- **灵枢**：蜂群运行时＋蜂巢并发是五件套之二，*「多智能体真并行」*是核心卖点；纪律 17 要求执行性任务统一走蜂巢派发、留痕。
- **止观AI**：判语 007 明确*「不需 Agent 军团……单人项目的真正瓶颈是决策，不是产能」*；实际采用的是**轻量多窗口**（W1–W4）＋文档交接＋法师终裁，不引入编排框架。
- **判断**：这不是谁对谁错，而是**瓶颈结构不同**：灵枢的瓶颈是吞吐（检索/执行并发），多 agent 直接解瓶颈；止观AI 的瓶颈是判定权（每个关键判断都要法师亲验/亲裁），加并行 agent 只是把等待法师的队列变长，不增加判定带宽。**但**——灵枢蜂巢里与多智能体无关的两件东西可以借：①**spec in / result out 的文件协议**（交接文档模板，治"同日 5 份互相矛盾的交接文档"）；②**L1/L2/L3 留痕分级**（只读判定可直跑、改状态必派发、兜底须声明——比止观AI 现有的"改前/改后提交"更细一层）。

### 差异 4：终裁者的性质——工程师 vs 法师（**判定权来源不同**）

- **灵枢**：终裁＝设计者（荣，工程师）；复核＝验证单元（Kimi，另一个 AI）。*「设计者保留最终终裁权」*。产品效果的判定靠**机器评测**（LoCoMo、bench6）＋第三方复评。
- **止观AI**：终裁＝法师（宗国法师，修证权威）；亲验＝**具身体证**（*「S1 收口条件＝法师 Pico 真机一句话（D 级唯一判据源），未体感前 S2 不启动」*）；机器评测只覆盖"项目办公室工作"（评估报告 §2.6：18 项中仅 1 项用真实脑电数值）。
- **判断**：这是两边**最深刻的差异**。灵枢域（记忆检索）的正确性可以机器判定；止观AI 域（禅修体验）的正确性**不可机器判定**，最终判据源必然落在人的实修上。灵枢的"第三方 AI 复核"在止观AI 这里对应的是"法师亲验"——后者比前者更彻底，因为复核者本身不被复核（D 级唯一判据源）。**借机制可以，借判定权归属不行。**

### 差异 5：执行强度——工具层强制 vs 制度＋自觉（**止观AI 自认的差距**）

- **灵枢**：纪律执行在**工具层**——三道闸门是代码、`can_admin` 是凭据、`verify_discipline.py` 是 CI、`MDCG_TOKEN` 的 ops/layers 白名单是启动参数。*「缺能力返回 DEFER，绝不假装通过」*由审核器代码保证，不依赖任何 agent 的自觉。
- **止观AI**：纪律执行在**制度层＋自觉**——开工规约写得极细，但自认*「L3 约束依赖自觉，无工具层强制……光靠自觉不够，故写成强制动作；工具层硬拦截待裁」*（G10），且已三次 Grep 越线（靠事后记 KZ 补救）。
- **判断**：这是**灵枢对止观AI 最有价值的借鉴方向**——不是借它的某条规则，而是借它的**执行哲学**：把"记得遵守"变成"必然看见状态"（开工规约 §〇 闸门语其实已经点到了这个方向，闸门脚本 `开工前检查.ps1` 就是第一个工具层动作；灵枢说明这条路还能走多远）。

## 五、借鉴清单（逐条映射到 G1–G12 与 KZ/JP 教训，含边界）

> 总原则（沿用评估报告 §五）：不新增平行体系；不违反战略边界；先试点再升格；AI 不自行把做法升格为规则（§四ter）；每条以可验收的产出收口。以下每条标注：**借什么／落在哪／验收标准／红线（不借什么）**。

### 借鉴 1｜四态语义 → G3「弃权无载体」（最高杠杆）

- **借什么**：ACCEPT/REJECT/DEFER/BLINDSPOT 的**状态语义与路由规则**（不是代码）。评估报告已给出 `ExplanationEnvelope {claim, evidence_refs[], confidence, abstention_reason, allowed_actions}`——四态正好填满它的状态位：`不可判定` 拆成 **DEFER（条件不足：数据未到/仲裁未定→挂起等数据）** 与 **BLINDSPOT（无法归属：无数据源/超出系统能力→显式申报而非猜测）**。
- **落在哪**：印证矩阵现状"三相可算、一相半可、一相空"——**出相（空）= BLINDSPOT、融相（半）= DEFER**，这不是失败记录，是系统对自身边界的合法声明。把这种声明从散文（"尚悬"）升格为结构化字段，L4-02a 已验证的模型弃权能力就有了系统出口。
- **验收标准**：构造 3 个应弃权场景（对应 B2），实测全部返回弃权且不返回判级（评估报告 §5.2 线二已列，此处只补四态命名与路由条件）。
- **红线**：四态是**输出侧**机制，不得反向变成"模型可以自行把法师裁定降格为 DEFER"——判定权仍在法师，四态只描述系统自知，不描述裁定归属。

### 借鉴 2｜三道闸门＋fail-closed → G4「LLM 输入侧无规则」

- **借什么**：写入三闸门的**流程结构**（audit→一致性→gated，逐层裁决、非 ACCEPT 即拦截）＋`content_kind` 显式声明＋**fail-closed 默认**（灵枢：*「未配置规则库的审核器一律判 DEFER，绝不假装通过」*）。
- **落在哪**：评估报告 §5.2 线三《LLM 输入数据分级与脱敏规则》的数据类×可否进提示词×条件表，可加一列"未识别数据类型的默认处置"＝**拦截（fail-closed）**而非放行——`session_note.txt` 这类"自由文本、风险最高、天然含可识别个人情境"的载体，正是灵枢 `content_kind: text` 默认 DEFER 的同型对象。凭据侧可借 `role/clearance/ops-allow/layers-allow` 的**白名单思维**（本机推理=某 clearance，云端=更高 clearance，缺凭据即降级为只读——灵枢的 `guest` 模式：*「读得到、写不进」*，与止观AI 的"云端窗口不加载 L3 机密目录"同构）。
- **验收标准**：L1-03 从"评测题"升级为"规则一致性的持续回归测试"（评估报告已建议）；另加一条灵枢式反例：构造 3 种未在白名单内的数据类型，实测全部被拦截（fail-closed 生效）。
- **红线**：闸门是**机器预审**，不是裁定——任何闸门规则的新增/放宽仍走"AI 起草＋法师裁定＋三同步"，不得做成"机器放行即生效"。

### 借鉴 3｜committed＋读回确认 → G5「评测无评分、无反馈」与"勿采信自述"纪律

- **借什么**：*「别把 ok:true 当成功」*的最小实现——**任何"已完成"声称必须附一个可被第三方重跑/重读的证据字段**（committed 式）。纪律 16 的*「读回确认……未读回确认不得视为归档完成」*。
- **落在哪**：①评测判分闭环（E1）的记分板每条分数附 `scored_by/scored_at/规则版本/输入哈希`，且**下一窗口必须能重算**（=读回确认）；②三同步落地加第四步"读回验证"——新窗口开工时 grep 该规则，**找不到即视为未落地**（把 KZ-013"写了文档没进索引"的事故模式从"事后 KZ"前移到"事前拦截"）；③seed 校验从 `_*` 临时文件改正式留证（E2）——灵枢的教训同源：*「可复现性证据自身不可追溯」*就是"ok:true 陷阱"的变体。
- **验收标准**：任选一条已"落地"规则，由**另一个窗口**在不知情的情况下 grep 并复算其证据，成功=通过（这正是灵枢"第三方独立验证"的最小形态，也是判语 011"不得由产出方自证"的工具化）。
- **红线**：读回确认只验"在不在、对不对"，不产生任何裁定效力。

### 借鉴 4｜can_admin／凭据白名单 → G10「L3 无工具层强制」

- **借什么**：*「风险工具需 can_admin，即使 tools:'all' 也不自动暴露」*——**高危能力默认不暴露，须显式凭据**；以及宪章 D-007 的 fail-closed 语义。
- **落在哪**：评估报告 G10 已列"缺 deny 规则或目录级只读锁"。可落地的最小形态：①检索工具层加路径黑名单（`机密-学员数据\`、`人格档案\`、`原始素材\` 三目录硬拒绝，与开工规约 §四bis 明列完全对齐）；②云端窗口（在线模型）与本地窗口的工具面**按端分白名单**——灵枢五端"大脑与记忆真源零改动、只有纪律注入方式差异"的分层正好是参考：权限差异在**入口**做，不在**规则**做。
- **验收标准**：构造 5 条越界检索（含 `-A/-B` 上下文行带出机密的变体），实测全部被拦截且留痕；本地窗口白名单内检索零影响（回归）。
- **红线**：工具层拦截是**执行**，规则文本仍归法师裁定；拦截日志涉 L3 文件名即敏感（灵枢宪章第二十一条附 1 数据最小化同理），留痕只记"拦截事件"不记"命中内容"。

### 借鉴 5｜单真源＋渲染＋漂移守卫 → 三同步纪律的机制补强

- **借什么**：`工作纪律_认知图条目_v1.1.json`（真源）→ `render_discipline.py`（多端投影）→ `verify_discipline.py`（**CI 级一致性断言**）三段式。
- **落在哪**：止观AI 的三同步（规则文档＋MEMORY 索引＋开工规约）目前靠**人记**（KZ-013 事故即传播失败）。最小补强：一个只读脚本 `check_rules_sync.py`——对每条在册规则断言"三处（文档/索引/规约）同时存在且措辞一致"，纳入开工前闸门（`开工前检查.ps1` 已存在，加一条调用即可）。这不新增体系，只把 §六 的"缺一视为未落地"从判例变成**可执行的断言**。
- **验收标准**：人为制造一处三同步缺项（删掉 MEMORY 索引一行），脚本即报错指出缺哪条哪处（反例检验，同借鉴 7 的方法）。
- **红线**：脚本只报告不一致、不自动修补——修补动作仍走裁定与提交纪律（AI 不代改）。

### 借鉴 6｜证据防火墙的"冒充节点"洞察 → KZ-016/JP-003 类错误的机械防线

- **借什么**：灵枢最反直觉的实证——*「语义高度省略的弱证据恰恰最容易被召回冒充正确答案；条件判断层（负条件/否定反事实）的弱证据节点会冒充正确答案」*。对应到止观AI 的语境：**"听起来像制度依据"的表述**（KZ-016 的"按 F6 纪律应归档"）与**"听起来像裁定"的对话答复**（JP-003 的"一并"）就是文本域里的"冒充节点"——引用对象真实存在（F6 存在、法师确实说过"一并"），但**内容被扩写/归属被错置**。
- **落在哪**：判断实例库说明已立"P1 不得援引、否决优先入库且标红"。可补一条机械动作：凡援引某条制度/裁定作为处置依据，**必须附该条全文的 grep 命中行号**（=灵枢 `judge_ranking` 白箱终排的文本版：裁决依据必须可回指到原文坐标，而不是"我读过"）。KZ-016 的教训栏其实已经这么做了（"四处逐字核实"），借鉴的意义是把它从**优秀个体的自觉**变成**所有援引的默认格式**。
- **验收标准**：抽 5 条在册处置依据，全部能给出"条款全文＋命中坐标"者通过；给不出即按 KZ 体例补核（这条不需要新规则，只是格式默认化——升格与否仍待法师裁定）。
- **红线**：这是对**AI 侧**援引的格式要求，不改变任何裁定效力。

### 借鉴 7｜spec in / result out 文件协议 → 交接文档矛盾（G12 型问题）

- **借什么**：蜂巢任务契约"读 spec.json 写 result.json"——**交接文档的字段化**：接手工号/窗口＋任务范围（显式文件清单）＋验收判据（可判真假）＋结果回写位（谁/何时/什么证据）＋留痕位。灵枢纪律 17 的 L1 直跑留痕格式（*「L1 直跑：〈命令〉— 风险/频次/可逆性」*一行留痕）也可借为"轻量动作"的统一留痕行格式。
- **落在哪**："同日 5 份互相矛盾的交接文档、各自称份数冲突"（四次复现）的根因之一是交接文档**没有固定字段**，自由叙事互相覆盖。字段化后，"自称份数"这种字段冲突会被结构本身暴露（两份 spec 的"任务范围"重叠即冲突，无需人工对账）。
- **验收标准**：按模板重写下一份交接文档，接收窗口开工时能**零歧义**列出"我接了什么、不接什么、怎么算做完"（对照 W3 巡检接手 W1 对账那次的人工成本）。
- **红线**：**只借模板，不借蜂巢**——不引入多智能体派发框架（判语 007），执行者仍是人工认领的窗口；文件协议只是文档格式，不是运行时时。

### 借鉴 8（反向提醒）｜灵枢没做的三件事——止观AI 已有且更彻底，**不要"借鉴"掉**

1. **具身判定源**：灵枢的效果判定止于机器评测＋设计者；止观AI 的 D 级唯一判据源是法师 Pico 真机体感。借灵枢机制时不得把"机器判分通过"升格为"体验合格"（判语 009 宣发红线同向）。
2. **真值生成论**：灵枢"原文即真源"在其域内成立；止观AI"真值由数据与人的对应关系生成、文本只是词汇层"是更彻底的位置。借鉴任何检索/记忆机制时，**EEG 数据的真值地位不得被"文档记载"替代**（判语 013 禁令原文在案）。
3. **自知机制**：*「我们有如法不如法的自知」*——判定机制从"外部核准"换成"持续的内部自知"（每次使用都要重新意识到自己在哪一层说话）。灵枢的 BLINDSPOT 是**一次性的**状态标记；止观AI 的"自知"是**持续的**使用纪律。两者可叠加（标记＋自知），但自知不可被标记替代。

## 六、反向对照：灵枢可以借鉴止观AI 的三处（供交流参考，非要求）

1. **判定源下沉到人的具身体验**：灵枢的第三方验证（Kimi 复核、LoCoMo 复现）仍停留在"另一个 AI/机器"；止观AI 的"法师真机一句话"把判据源放到**不可被 AI 复核的人的体验**上。记忆系统若用于高风险场景（医疗、法律 agent 的长期记忆），"记忆被召回"与"该记忆是否真的成立"之间，缺的正是这一层——灵枢的 `mdcg_verify`/`whitebox` 是机制验证，不是**价值验证**。
2. **"假设层"的立而不执**：止观AI 三层（假设层/词汇层/真值层）中，假设层*「自带证伪与修订条件，被预测误差修订，不被捍卫」*＋最高出口*「练习者实修反馈与系统呈现系统性背离→假设让位于实修」*。灵枢的认知图节点有 `negative.reject`（不适用条件），但没有**假设层**——图里的规则是"已成立"的，缺一个"被轻持、可随时舍"的假设槽位。
3. **镜子非训练器的定位纪律**：灵枢的自动记忆钩子是"替 agent 记住"；止观AI 的镜子定位是"让人看见，不替人做"。护栏宪章第七章保护的是**人的自主**，而"不替 agent 记"保护的是**agent 的认知主权**——这两层加在一起才完整。灵枢的 `mdcg_rejected`（被拒队列）已接近这一思想（不静默写入＝不替 agent 做决定），可显式化。

## 七、结论

1. **平行即验证**：两个互不参照的项目，在"自述不信／弃权一等／纪律可路由／高危上收／留痕抗蒸发／反例打防线／错误即燃料"七处独立收敛——这比任何单侧的自夸都更有说服力。止观AI 的 G1–G12 自陈与灵枢的 README 自夸，恰好构成一组"同题两解"的样本。
2. **可借的是执行哲学，不是规则文本**：灵枢真正值钱的不是 17 条里的任何一条（大部分止观AI 已有对应物），而是**"把每条纪律都做成一个可失败的断言"的工程习惯**——committed、can_admin、fail-closed、漂移守卫、读回确认。止观AI 的纪律文本质量已不弱（KZ-016 识破杜撰引用、判语 011 的数字精确性判据、§四ter 的自我扩权红线，都是成熟度很高的设计），缺的正是这层"可执行性"。
3. **不可借的是真值与判定权**：真值在数据与人的对应关系里（判语 013）、终裁在法师的实修体证里（D 级唯一判据源）、AI 不自我升格（§四ter）——这三条是止观AI 的域结构，不是可移植的组件。灵枢的"原文即真源"、"机器评测定效果"、"设计者终裁"在它自己的域内完全正确，搬到止观AI 就是越层。
4. **一句话**：**灵枢是"白箱的机制"，止观AI 是"白箱的纪律＋黑箱（人心）的真值"。前者机制更完整，后者真值更彻底；机制可向止观AI 流注，真值不可向灵枢外借。** 若只记三条行动项：①给弃权装上四态（借鉴 1）；②给输入侧装上 fail-closed 闸门（借鉴 2）；③给三同步装上漂移守卫脚本（借鉴 5）——三者都不新增体系、不触碰判定权，且分别对应当前 G3/G4/G10 三个自认缺口。
