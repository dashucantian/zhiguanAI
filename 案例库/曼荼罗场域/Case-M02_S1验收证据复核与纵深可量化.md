## 一、目标（验证什么）

**不是**验证场域好不好，而是**验证 S1 的验收证据本身是否成立**——即"判据也要被验收"的第二次实践。

触发：接手复核时读到 `verify_mandala_s1.py:133` 断言"三层瓣数 8/16/8"，而 `__mandalaDiag.layers` 的实现已改为报 `k`（4/8/8）。两者口径不一致 ⇒ 该脚本在当前代码上**必然误报失败**，而 SOP §七 却记着 s1 改造后"✅ 11 项"。**先怀疑证据，再谈结论。**

## 二、方法

| 手段 | 作用 |
|---|---|
| `git show ef97132:vr_mandala.html` | 取变体化重构**之前**的源码，还原字段原义与几何真值 |
| 静态复算（`_analysis_tmp\mandala_metrics_check.mjs`） | **跑页面自己那份 `depthMetrics` 源码**，不经浏览器即得纵深数字 |
| 钩子自述的**独立复算** | 用钩子给出的 `pos`／`cam` 重算距离、角半径、雾透过率，比对自述 |
| 反例检验（变异副本） | 把钩子改回写死字面量，检验新判据能否抓住 |
| `git check-ignore -v` | 确认验收脚本是否真在版本控制内 |

> 为什么要静态复算：受限沙箱下**无头 Edge 不可用**（六种启动参数组合实测全失败——多进程组在首条 CDP 命令被重置 `WinError 64`，`--single-process` 起不来 DevTools；与"受限模式不得开命名管道"边界吻合）。而纵深的关键量本就是纯几何量，可由注册表直接算出。

## 三、结果

### 3.1 查实一：字段含义被静默改掉，判据未动

| | `layers` 语义 | s1 实际取值 |
|---|---|---|
| 重构前 `ef97132` | **花瓣数**（字面量写死） | `{inner:8, middle:16, ground:8}` |
| 重构后 `1d09139` | **k**（`spec.*.k`） | `{inner:4, middle:8, ground:8}` |
| 判据 `verify_mandala_s1.py:133` | 仍按**花瓣数**断言 | 期望 `8/16/8` |

⇒ 该脚本在重构后必然失败；SOP §七 所记 s1"✅ 11 项"**不可复现**（该轮很可能只跑了无层断言的 `verify_mandala_variants.py`）。

### 3.2 查实二：大地层三方不一致，且原始那一条是错的

| | 内环 | 中环 | 大地 |
|---|---|---|---|
| **实际几何**（`rosePoints(4,0.55)`／`(8,2.6)`／`(8,9.0)`，前后一致） | 8 瓣 | 16 瓣 | **16 瓣** |
| `Case-M01` §二 | 八叶 ✓ | 十六叶 ✓ | **"八叶暗金"** ✗ |
| 原钩子 `ef97132` | `8` ✓ | `16` ✓ | **`8`** ✗（写死字面量） |
| 判据脚本 | 8 ✓ | 16 ✓ | 8 ✗ |

**要害**：原钩子该字段是**字面量**，而几何当时就是十六瓣。所以 S1 那次"层参数 8/16/8 与参数表一致"这一项，是**在被测对象自述与几何不符的情况下通过的**——**该项证据不成立**（另 10 项不受此影响）。

> 这与 KZ 家族同源（未核实到实体就下判断），但载体特殊：**失实的是代码里的自述，而不是文档**。

### 3.3 "三层纵深"实算（跑页面自身 `depthMetrics`）

```
s1  相机 [0,1.6,3.2] · 雾 0.022
  层      花瓣数  距离m  最外半径m  角半径°  仰角°   雾透过率
  inner       8   4.522      0.62      7.8    -5.7      0.990
  middle     16   9.214      3.35     20.0     3.1      0.960
  ground     16   3.569      9.60     69.6   -26.3      0.994
  ↳ 内/中角半径比 0.39 · 圆心角距 8.8° · 层间雾透过率差 3.0 个百分点
```

对照 v2abyss（雾 0.030）：中环 0.859 vs 大地 0.994，**差 13.5 个百分点**才形成真退远。

**读数**：s1 的"三层纵深"目前主要靠**屏幕位置差**——内环只占中环角半径的 39%，雾在场景实际深度（3.6~9.2 m）内几乎不衰减。这是"深"字诀的一个**可测量缺口**，不是错觉。

### 3.4 新判据有牙齿（反例检验）

- **等价性**：三变体共 7 个层，验收脚本的独立复算与页面 `depthMetrics` **全部同解** ⇒ 诚实钩子不会被误判。
- **反例**：把 ground 距离谎报 +1.0 m、雾谎报 +0.05 ⇒ **两项均被抓住**。
- **静态套件反例**：把 `layers` 改回写死 `8/16/8` 的变异副本 ⇒ 判据 7 精确报出 `['8','16','8']`，退出码 1。

### 候选判语（提请，AI 不自立）

> **判语候选·钩子自述亦是证据，须被独立复算**
> 验收判据凡以"被测对象自述"为输入者（诊断钩子、自检字段、自报参数），必须另有一条**由判据侧独立复算**的校验；否则自述失实会**伪装成通过**。本例中该失实持续存在且已被写入案例卡（Case-M01）与 SOP 台账。

> **教训（与 Case-M01 §3.2 同族）**：Case-M01 是"判据集有盲区"，本卡是"**判据只信被测对象的自述**"——前者是没测到，后者是**测错了对象**。后者更隐蔽：它给出的不是空白，而是**看起来合格的数字**。
