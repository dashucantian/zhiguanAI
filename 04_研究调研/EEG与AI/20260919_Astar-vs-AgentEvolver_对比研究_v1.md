## 0. 一句话结论

- **Astar**：一个"教 AI 给别的 AI 指进化方向"的小模型——**拿不到**（仅 arXiv 论文，CC BY-NC-SA，内部部署 Lazada）。
- **AgentEvolver**：一个"让智能体自我训练变强"的端到端框架——**开源可用**（GitHub modelscope/AgentEvolver，Apache-2.0，可商用）。
- 两者解决**不同层次**问题，可互补；对止观AI都**别照搬工程**，最该偷走的是它们的**方法论**。

## 1. Astar：用"进化血泪史"训练出的方向军师

### 1.1 是什么
《Astar: Learning to Propose Evolution Directions for Self-Evolving Industrial AI Systems》（阿里 + 浙大，2026-08）。针对 AI 迭代循环里"**该往哪个方向进化**"这一步仍依赖资深专家的问题，训练一个专门的引导模型。

### 1.2 关键数据
| 版本 | S@1（单次生成有效方向成功率） | vs GPT-5.5 | vs 人类专家 |
|------|------|------|------|
| **0.6B** | **54.35%** | 30.71% | 32.29% |
| **8B** | **67.86%** | — | — |

- 部署于 Lazada 广告召回系统：两周自动指导 20 轮迭代，离线 Hitrate@200 **+23.6%**；线上 A/B：GMV +4.86%、广告收入 +1.82%。
- 典型案例：发现检索模型共享 FFN 造成语义层干扰 → 提出"正交化前先做频谱降噪（Spectral Denoising）"。

### 1.3 为什么有效（四大挑战 → 四套打法）
| 挑战 | 解法 |
|------|------|
| C1 数据太少 | **两配扩增**：任意两次实验配对比 loss，稀疏变密集 |
| C2 数据掺水 | **两级过滤**：可达性分析+AST 拧干死代码；LLM 判断真改进意图 |
| C3 搜索空间太大 | **三级分层提示**：一级方向→二级模块→三级动作，压搜索空间 |
| C4 验证太贵 | **代理奖励模型 (surrogate RM)**：秒级预测能否降 loss，替代几天一次真实训练 |

训练流水线：**mid-training(112B token) → SFT → RL(GRPO)**。

### 1.4 开源状态 ❌
- 仅 arXiv 论文（CC BY-NC-SA 4.0，非商用），**无 GitHub 仓库、权重未在 HF/ModelScope 发布**。
- 真正值钱的是"从自身迭代历史中学习"的方法论，而非那 0.6B/8B 权重。

## 2. AgentEvolver：让智能体自我进化的训练框架

### 2.1 是什么
《AgentEvolver: Towards Efficient Self-Evolving Agent System》（阿里，2025-11）。端到端、统一三大自进化机制的训练框架，直接**训**智能体本身。

- **GitHub**: modelscope/AgentEvolver · ⭐1558 · **Apache-2.0（可商用）** · 858 commits
- 依赖栈：ReMe（经验管理）+ veRL（分布式 RL）+ gym/Ray 并发

### 2.2 三大机制
| 机制 | 作用 | 解决的老问题 |
|------|------|--------------|
| **Self-Questioning 自提问** | 好奇驱动，在陌生环境自主生成探索任务 | 摆脱人工数据集依赖 |
| **Self-Navigating 自导航** | 成败轨迹向量化存进经验池(ReMe)，混合策略复用 | 探索孤立、重复犯同样错 |
| **Self-Attributing 自归因** | ADCA-GRPO：给长任务每步精细分配信用，找出关键动作 | GRPO 只给最终奖励、不区分关键/多余动作 |

### 2.3 硬成绩（AppWorld + BFCL-v3，工具型长程任务）
| 模型 | 参数 | AppWorld avg@8 | BFCL v3 avg@8 | Avg |
|------|------|------|------|------|
| Qwen2.5-7B 基线 | 7B | 1.8 | 29.8 | 15.8 |
| **+Questioning** | 7B | 23.2 | 49.0 | 36.1 |
| **AgentEvolver(整体)** | 7B | **32.4** | **57.9** | **45.2** |
| Qwen2.5-14B 基线 | 14B | 18.0 | 41.6 | 29.8 |
| **AgentEvolver(整体)** | 14B | **48.7** | **66.5** | **57.6** |

- **样本效率**：达基线 90% 性能，AppWorld 只需 40 步（基线 90）、BFCL 只需 20 步（基线 60），**省 55~67%**。
- 新分支 SeeUPO（2026-03，带收敛保证的序列级 RL）值得关注。

### 2.4 开源状态 ✅
- Apache-2.0，代码/文档全开源；训练需 **GPU + CUDA + veRL**，较重。

## 3. Astar vs AgentEvolver：本质区别

| 维度 | **Astar** | **AgentEvolver** |
|------|------|------|
| 本质 | 一个**模型**：学"怎么给 AI 指方向" | 一个**训练框架**：让 agent 自我变强 |
| 层级 | 元层 Meta：告诉工程师/Agent **改什么** | 执行层：直接 **训** 策略模型 |
| 产出 | 一句演化方向建议 | 被 RL 强化后的更强 agent |
| 数据源 | 工业系统多年迭代史 | 智能体在环境里的交互轨迹 |
| 开源 | ❌ 仅论文（非商用） | ✅ Apache-2.0 可商用 |
| 算力 | 用它推理很轻；训它需 GPU | 全程需 GPU/CUDA/veRL，很重 |
| 场景 | 调推荐系统架构/超参 | 工具操作型 agent（AppWorld/BFCL） |

**通俗说**：Astar = "AI 当军师告诉你往哪打"；AgentEvolver = "AI 自己练级越打越强"。可互补——Astar 定方向，AgentEvolver 执行进化训练。

## 4. 对止观AI 的借鉴价值

### 4.0 现实约束
AgentEvolver **全程需 GPU + CUDA + veRL**；而本项目是"本地小模型为主、D28 不买显卡"路线。**完整跑框架不现实、也不需要**。但三大机制都精准踩中现有痛点。

### 4.1 🎯 Self-Attributing（自归因）→ 直击"D级判据"难题【最该借鉴】
AgentEvolver 核心创新：长任务里**到底哪个动作导致了成功**，把它映射到每一步。
**对应本项目**：一次禅修会话=一条长轨迹（呼吸引导→脑电变化→音频反馈调整→进入状态），最终"入定/深放松"结果由哪一步干预决定？当前 D 级判据（法师体感）是唯一源却**无法自动归因到具体参数**。可设计"**关键干预步骤归因器**"：从历史会话自动判断"本次深放松主要归功于 τ≥10s 雾场渐变 / 还是 Alpha 阈值触发的那段音频"。

### 4.2 🎯 Self-Navigating（经验池 ReMe）→ 已在做，可升级
已有案例库 Case-M、判断实例库、task_records.json = 同一件事。补两点：
- **混合策略**：部分探索用经验引导、部分纯随机，平衡"利用已知/探索未知"。
- **经验内化**：剥离指导性文本逼模型学推理逻辑而非死记——对应"判据库要沉淀推理而非模板"。

### 4.3 🎯 Self-Questioning（自提问）→ 减少人工造用例
智能体自主生成探索任务。对应本项目：AI 自动生成多样化禅修场景变体与边界 case（不同脑电基线、不同分心干扰），减轻文档线重复劳动。

## 5. 落地建议（三档）

| 档位 | 内容 | 成本 |
|------|------|------|
| **A · 方法论层（推荐先做）** | 借 Self-Attributing 归因思想，用现有本地小模型+历史会话数据做"关键干预步骤归因器"原型；按 ReMe 思路把案例库做成可检索经验池 | 纯 CPU/本地模型，不碰 GPU |
| **B · 观察层** | 关注 SeeUPO（2026-03，收敛保证的序列级 RL）——将来上 GPU 时这是比主框架更新的训练器 | 需 GPU |
| **C · 不推荐** | 完整部署 AgentEvolver 训 EEG agent：太重、且专为 AppWorld/BFCL 工具操作型 agent 设计，与禅修场景不匹配 | GPU+veRL，投入产出比低 |
