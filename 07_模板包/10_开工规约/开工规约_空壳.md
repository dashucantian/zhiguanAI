# 【项目名】AI 开工入口（规约 v【x.y】·由决策人【你的名字】持有裁定权）

> 用法：任何 AI 窗口开工**先通读本件**；本件条文只有决策人能增删，AI 欲立规＝写"立规提请"候裁。
> 空壳标记：【】必填；〔注〕为母本实证旁注，可删。

## 一、窗口分工（先填这张表，多窗才不互踩）

| 窗号 | 职责线 | 负责人（AI 编号） | 领地（只此窗可写的路径） |
|---|---|---|---|
| P1 | 【如：工程】 | 【AI-001】 | 【src/…】 |
| P2 | 【如：文档】 | 【AI-002】 | 【docs/…】 |
| P3 | 【如：制度机动】 | 【AI-003】 | 【未划领地事项】 |

规则：①一任务一负责人；②跨领地动手＝先派单认领；③**窗口身份随每笔提交写进 commit trailer**（Window/Session）。〔注：Session 命名 `窗-工具-日期-序号`，天然免撞〕

## 二、开工强制动作（每窗每会话第一轮照做，八步）

1. 读本规约；2. 读**当前状态页**（见 20_状态页包）；3. `git status` 盘点——**见非己产生的未提交变更，停下报告，不覆盖不叠加**；
4. 扫待办/信箱未认领派单（认领＝末行追加署名行）；5. 确认本单目标＋验收标准已明（不明先复述请示）；
6. 取用任何流水编号**先查末行再取号**，提交信息注明所取号；
7. 判定权边界自查（§四）；8. 估不出就说的活不开工。

**关窗阈值**：会话超约 50 轮或上下文过半或完成一个闭环＝总结→落文档→新窗重载。〔注：长会话必然腐化，与模型无关〕

## 三、并发纪律（五条，每条背后有事故）

1. **改前先提交**（己窗在途先固化）；
2. **改后即提交**（一窗一事一提交，不攒批）；
3. **认领制**：同一时段一个文件只一窗负责；
4. **冲突停下报告**：非己产生的变更，不覆盖、不搭车、不"顺手帮忙"；
5. **提交必带路径限定**：一律 `git commit -- <本窗显式路径…>`，**禁裸提交、禁 `git add .`**；提交前查过 index 亦不豁免——index 是他窗随时可变的公共面，提交瞬间唯一握得住的边界是 pathspec。〔注：母本 09-27 事故——查 index 与 commit 之间 15 文件被并发卷入，soft-reset 拆分方止〕

## 三bis、文档冲突裁决（按序适用）

1. **状态页优先**：任何文档与当前状态页冲突，以状态页为准；
2. **较新胜出**：同级矛盾以较新者为准，较旧原文保留＋加订正注记指向新文，**不删**；
3. **专门优先于顺带**：详述该事项的文档优先于顺带提及者；
4. **报告不静默择一**：拿不准归谁裁，写进状态页"候裁"节，等人。

## 四、判定权边界（AI 三原则）

1. **AI 组织证据，不替人裁定**：义理/真值/对外发布/涉人处置永留人侧；
2. **AI 是协作者不是控制者**：不得自动采集、不得整盘权限、不得绕过验收；
3. **观察优于引导**：如实报（含存疑申报），通篇无一处存疑的产出默认有问题。

**红线条**：AI 不得把"自己总结的做法"直接写进本规约任何条款；升格权在人，且可随时撤回。

## 五、禁入目录（隐私与真值隔离，按你项目填）

- 【如：录音/健康数据/个人档案目录】——任何窗不读不写不检索，Grep/Glob 必须显式限定 path；
- 【如：未定型合作条款】。

## 六、收口三同步

每单收口：①结果回写**状态页**；②决策/订正落**登记分片**（一事一文件）；③有教训开**案例卡**（60_案例库）。固定跑一条收口检查（只读脚本：状态页新鲜度/编号连续/无搭车提交）。

## 七、提交确认流（对外可见动作皆候批）

列文件清单＋逐件归因 → 决策人口头放行 → **pathspec 提交** → 提交后 `git log --stat` 复核并如实报。**push 永远单独特批。**
