# 40_任务看板 — 让表自己催活：状态机＋零常驻自动化

**治的病**：任务提醒靠人肉问、裁决下了没人接（"说了当做了"）；多 AI 窗抢单或集体装没看见。

## 最小字段集（一列都别多加，先跑起来）

| 字段 | 类型 | 作用 |
|---|---|---|
| 任务编号 | 自动编号 `T-001` | 全局唯一，提交/文档都引它 |
| 任务名 | 文本 | 一句话说清做什么 |
| **验收标准** | 文本·**必填** | 没标准的任务不许进表（将来就是社区合并标准） |
| 状态 | 单选 | 待启动/进行中/待决策/待审定/已完成/已搁置 |
| 承接状态 | 单选 | 待承接/承接中/执行中/已完成 |
| 裁决 | 文本 | 决策人写"**【裁决】**…"前缀（自动化按前缀识别） |
| 受理戳 | 文本 | 承接窗写"窗号+时间"＝认领锁，**防两人抢一单** |
| AI执行窗口/承担者 | 单选 | 归因 |
| 计划开始/截止 | 日期 | 驱动到期提醒 |
| 关联文件/AI执行记录 | 文本 | 指针与履历（只放路径不放正文） |

## 状态机（一条任务的一生）

```
待启动 ──(裁决落表)──> 【裁决】+受理戳空 ──(任一窗扫码并盖戳)──> 承接中/执行中
   ──(干完改状态)──> 待审定/待决策 ──(人验收)──> 已完成
   旁路：已搁置（写明原因，不算死）
```

## 三条自动化流程（飞书多维表格 → 自动化，导入 `wf_*.json` 后启用）

1. **wf①每日待办**（Timer 每日 09:00）：扫"待审定/待决策"→ 逐条推你；扫"【裁决】开头且受理戳为空"→ 标待承接＋催办。**误捞防线**＝前缀＋空戳双条件，正文写"裁定"两字不会被捞。
2. **wf②状态变更**（Record 变更触发）：状态进"待审定"即推验收提醒——一次事件一个发信方，别处不许再推。
3. **wf③到期前**（Timer 每日）：截止前 2 天推倒计时。

> 导入后必改两处：`receiver` 的 open_id 换成你自己的（通讯录→个人→开发者ID）；`$.l2.item.fldXXXX` 字段 ID 引用按你新建表的实际 ID 替换（点开字段可查）。额度：免费版 200 次/月够用（母本月耗约 130）。

**配套人肉纪律**（AI 侧）：开工必扫"待承接"（规约 §二.4）；盖了受理戳的单只有戳主可动；收口回填"AI执行记录"一行。
