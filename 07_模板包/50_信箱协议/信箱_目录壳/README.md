# 信箱协议 README（唯一交接通道 · 复制到你的项目即用）

> 本目录是本机各 AI 窗口与云端/常驻 agent 之间**唯一**的交接通道。
> 换实现（任何新工具/新助手）**不改本协议、不加平行目录**。协议改动须走决策编号裁定。

## 目录结构

```
信箱\
  README.md          本协议（唯一真相）
  inbox\             派单区：决策人（或经手机转投）写入，窗口读取认领
  outbox\            回报区：窗口办理后写入，决策人/巡检读取汇总
  engine\            （可选）引擎侧产物：巡检日志（按窗分档 巡检日志-<窗>.txt）、告警草稿
```

## 消息格式（文件即消息，只追加不覆盖）

文件名＝`YYYYMMDD-Txxx.md`（inbox 与 outbox 同名配对）。模板：

```markdown
# T-xxx <任务标题>
- 状态：派单 | 进行中 | 待验收 | 已验收 | 挂起(原因)
- 优先级：紧急 | 本周 | 随缘
- 卡点：一句话（元数据级，不贴正文）
- 期望：要看到什么算完成
- 链接：看板记录 URL ／ 交付物路径（本机路径写绝对）
- 时区时间：YYYY-MM-DD HH:mm
- 署名：决策人口述转投 | 窗口号-AI编号
```

## 三条铁律

1. **元数据级**：任何隐私正文（录音/健康/档案/代码）不得写入本目录。
2. **一次事件一个发信方**：任务提醒只从看板自动化发；巡检只管制度健康，不重复推。
3. **命名唯一**：同一任务重开用 `-r2` 后缀新文件，不改旧文件；全部文件仅追加。

## 消费约定

- 窗口开工：扫 `inbox\` 未认领 → 认领＝末行追加 `> 认领：<Session> <时间>` → 办理 → 写同编号 outbox。
- 常驻巡检（若启用）：只读本目录＋看板元数据；无新项则**静默**（静默是功能）。
- 日志按窗分文件、写前必读本窗档再追加；派生视图（自动生成的索引）豁免滞留判据。
- 制度侧候裁清单以《当前状态页》为准，与信箱互挂编号、不双录内容。
